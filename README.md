# AutoPyro

Настольное приложение на Python / PySide6 для работы с геохимическими данными.
Реализованы модули таблицы, описательной статистики, настраиваемых графиков,
расчётных показателей пиролиза и геометрической интерпретации на Shapely.

## Структура кода

- `autopyro.model` — модель проекта, измерения, таблицы, снимки и протоколы.
- `autopyro.data_io` — импорт, экспорт и шаблоны чтения данных.
- `autopyro.analysis` — расчёты, статистика, контроль качества и интерполяция по глубине.
- `autopyro.curves` — подбор, проверка и сравнение кривых.
- `autopyro.schemes` — схемы интерпретации, геометрия и неопределённость измерений.
- `autopyro.visualization` — подготовка данных, отрисовка и экспорт графиков.
- `autopyro.spatial` — карты, пространственная интерполяция и региональный анализ.
- `autopyro.geology` — стратиграфия и сопоставление литологии.
- `autopyro.reports` — отчёты по проекту и региональным выборкам.
- `autopyro.ui` — настольный интерфейс на PySide6.
- [autopyro.database](autopyro/database/README.md) — PostgreSQL, SQLite, хранение проектов, диалоги БД и административные утилиты.

Новый код использует пути тематических пакетов, например `autopyro.model.core`.
Прежние пути импорта, такие как `autopyro.core`, продолжают работать.

## Запуск в Windows / PowerShell

Для установки из готового ZIP см. [инструкцию Windows](docs/WINDOWS_INSTALL.md).
Офлайн-комплект для Windows x64 и CPython 3.12 собирается из корня проекта
в окружении с `setuptools` и `wheel`.

```powershell
.\.venv\Scripts\python.exe -m tools.build_windows_release
```

Сборка проверяет хеши из `requirements-win-py312.lock`. Для сборки без сети
передайте путь к папке с уже загруженными зависимостями через `--wheelhouse`.

Из каталога проекта:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m autopyro
```

Для нового окружения сначала создайте `.venv` через установленный Python 3.12+.
После установки доступна также команда `autopyro` в виртуальном окружении.

## Что работает

- Предпросмотр CSV/TSV и XLSX, выбор листа, кодировки, разделителя и одного/двух уровней заголовков.
- Выбор импортируемых колонок, названий, текстового/числового типа и единиц.
- Диапазоны строк/колонок, произвольная строка заголовка, десятичный знак CSV/TSV.
- Шаблоны чтения и добавления данных: явные синонимы, редакции, библиотека проекта
  и перенос настроек через JSON. Неоднозначные заголовки требуют ручного сопоставления.
- Ведущие нули, `<LOD`, `ND` и формулы Excel сохраняются текстом; формулы не исполняются.
- Чтение Excel, обработка заголовков и диапазонов, сборка снимков БД, подготовка
  графиков, агрегация карт, массовые QC-проверки, расчёты и сопоставление импорта
  используют pandas. DataFrame создаются для пакетной обработки; история измерений,
  undo/redo и точечные изменения остаются в модели проекта. openpyxl остаётся
  движком XLSX и предоставляет метаданные ячеек; разбор CSV/TSV сохраняет физические
  номера строк многострочных записей. SQLite читается без автоматического
  преобразования смешанных числовых колонок, чтобы сохранить большие целые точно.
- Интерактивная таблица, выбор колонок, перестановка заголовков, сортировка,
  несколько ключей сортировки, AND/OR/NOT-фильтры и именованные представления.
- Изменение ячеек, пакетное заполнение, копирование и транзакционная вставка TSV,
  undo/redo. Все строки имеют собственные UUID; одинаковые имена проб не объединяются.
- Создание текстовых/числовых колонок.
- Линейная, ближайшая, PCHIP-интерполяция и кубический сплайн, предпросмотр таблицей и графиком.
  Выберите ствол и при необходимости дополнительные поля группировки. Для данных без стволов
  подтвердите расчёт без разделения по стволам и выберите группировку.
  По умолчанию заполняются внутренние пропуски.
  Для линейного метода можно включить экстраполяцию с пределом расстояния от крайней опоры.
  Максимальный разрыв разделяет опоры PCHIP и кубического сплайна на непрерывные участки.
  Минимум опор для этих методов применяется отдельно к каждому участку.
  При повторяющемся X расчёт по умолчанию останавливается. Можно исключить все строки с этим X внутри группы.
  Для смешанной выборки можно указать колонку подошвы. Строки с заполненной подошвой
  исключаются из опор и кандидатов на заполнение.
- Интерполированные результаты хранятся в отдельной защищённой колонке со ссылками на опорные
  пробы. В заголовке колонки виден признак устаревания. Сохранённый снимок можно проверить,
  а его параметры загрузить для нового предпросмотра на текущих данных.
- При сравнении методов внутренние опоры скрываются по одной. MAE и RMSE рассчитываются по опорам,
  для которых дали прогноз все методы. Число прогнозов каждого метода показывается отдельно.
  Используются стандартные минимумы опор и текущий предел разрыва.
- Локальный проект `.apyro` на SQLite: пробы, анализы, измерения, рабочие результаты,
  исходные значения, UUID, источник, история и конфигурации. Старый JSON-формат v1
  открывается и мигрирует при сохранении с точной резервной копией.
- CSV-экспорт текущего представления в порядке отображения строк и колонок.
  Формулоподобные текстовые значения получают защитный апостроф для открытия в Excel.
- SQLite открывается с `mode=ro` и `query_only`; PostgreSQL — в read-only,
  repeatable-read транзакции. Источник не редактируется; изменения остаются в проекте.

## Первый сценарий

Команда **Файл → Открыть таблицу как новый проект…** загружает Excel, CSV или TSV
в новый проект. При несохранённых изменениях AutoPyro предложит сохранить открытый
проект. Кнопка **Новый из таблицы** на панели вызывает ту же команду.
Чтобы сохранить текущий проект и пополнить его лабораторными анализами,
используйте **Файл → Добавить измерения в текущий проект…**.

1. Выберите **Файл → Открыть таблицу как новый проект…** и откройте [examples/pyrolysis.csv](examples/pyrolysis.csv).
2. Нажмите **Прочитать / обновить предпросмотр**.
3. Проверьте типы. TOC, S1 и Tmax в этом примере содержат квалификаторы и остаются
   текстовыми. MD и S2 определяются числовыми. Единицы вводятся явно, без пересчёта.
4. Импортируйте. Настройте колонки слева; для сортировки нажмите на заголовок.
5. В **Таблица → Условия фильтрации** задайте `Well равно Demo-A`.
6. Откройте **Обработка → Интерполяция**: X = MD, Y = S2;
   отметьте Well, Formation и Method как группировку; максимальный разрыв = 30.
7. Рассчитайте предпросмотр: для MD = 1010 линейный результат S2 = 4.2.
   Создайте колонку. Исходная ячейка S2 остаётся пустой.
8. Измените измерение, проверьте undo/redo и индикатор устаревших интерполяций.
9. Сохраните `.apyro`, откройте повторно и экспортируйте текущее представление.

**Упражнение для встроенного демо.** Откройте **Файл → Демонстрационные данные**.
В этой отдельной таблице пять проб. Выберите линейную интерполяцию по MD для S2,
скважину используйте как группировку и задайте максимальный разрыв 30 м.
Между значениями 2,4 и 6,0 для скважины A на глубине 1010 м ожидается 4,2.
Для упражнения с колонками Formation и Method используйте CSV из шага 1.

### От повторного измерения до отчёта

1. Импортируйте [examples/pyrolysis.csv](examples/pyrolysis.csv) как новый проект.
   Для `MD` задайте единицу `m`, для `S2` — `mg HC/g rock`.
2. Создайте файл `repeat.csv` с двумя строками.

   ```csv
   Well;MD;S2
   Demo-A;1000;3.6
   ```

3. Откройте его через **Файл → Добавить измерения в текущий проект…**.
   Задайте для `MD` и `S2` те же типы и единицы. В сопоставлении отметьте
   `Well` и `MD` как ключ пробы, сравните с проектом и примените импорт.
4. Выберите ячейку `S2` у Demo-A на глубине 1000 м. Откройте **Правка →
   Измерения выбранной ячейки…**, выделите строку со значением 3,6 и нажмите
   **Использовать выбранное измерение**. В таблице теперь 3,6, обе записи
   доступны в карточке.
5. Откройте **Обработка → Контроль качества…**. Найдите замечание для этого
   `S2`, при необходимости откройте исходное измерение, введите комментарий
   к решению и нажмите **Принять**. Решение и исключение из расчёта настраиваются
   отдельно.
6. В **Файл → Отчёт…** оставьте `S2` среди показателей. Соберите отчёт,
   проверьте выборку и замечания, затем экспортируйте PDF или снимок JSON.
   Сохраните `.apyro`. При повторном открытии проверьте выбранный результат
   и решение QC.

## Диапазоны и шаблоны импорта

В мастере импорта задайте строку начала заголовка и один или два его уровня,
первую/последнюю колонку и последнюю строку. Нумерация начинается с 1;
последняя строка/колонка включается, «До конца» снимает ограничение.
В CSV/TSV номера диапазона считают записи, включая заголовки; перенос строки
внутри кавычек остаётся частью записи. Происхождение результата и сообщения
об ошибках указывают физическую строку начала записи. В XLSX используются номера строк на листе.

Для CSV/TSV доступны точка, запятая или оба варианта десятичного знака.
Разделители тысяч не предполагаются. XLSX сохраняет собственное представление
ячеек. ND, пороги и исходный текст сохраняются; типы и единицы следует проверить.
Вкладка **Ошибки импорта** перечисляет все неразобранные числовые ячейки;
до их исправления проект не заменяется и результаты не добавляются частично.

В колонке **Синонимы** перечислите альтернативные заголовки через `;`.
Кнопка **Сохранить…** в строке шаблонов сохраняет диапазон, параметры чтения,
состав колонок, типы и единицы. Шаблон применяется по точным заголовкам и
указанным синонимам, поэтому перестановка колонок допустима. Пропавшее обязательное
поле или неоднозначность останавливают применение; неизвестные новые колонки
не включаются автоматически. Для автоматически названных пустых заголовков
требуется ручное сопоставление. Единицы не угадываются и не пересчитываются.

У добавления данных в существующий проект свой этап шаблона: сопоставление
показателей, составной ключ, поля аналитического контекста и их общие значения
и политика рабочего результата. При переносе в другой проект проверяются
название, тип, единица и основание показателя; несовместимость требует ручной настройки.
Общее значение контекста используется только при неназначенной колонке;
пустые значения назначенной колонки сохраняются пустыми.

**Файл → Шаблоны импорта…** открывает библиотеку: загрузка/экспорт JSON,
удаление из активного списка и отмена изменений через undo/redo. В мастере
шаблон остаётся черновиком до успешного импорта; его можно заранее экспортировать
в JSON. Совпадающее имя на том же этапе создаёт следующую редакцию.
Старые определения остаются в проекте даже после удаления из списка или отмены
импорта: происхождение хранит редакцию и SHA-256 применённого шаблона.
Ручная правка настроек снимает отметку о применении неизменённого шаблона.
JSON содержит декларативные настройки без реквизитов подключения.

Пакетный импорт листов, автоматический подбор кодировки/разделителя и длинный
формат измерений пока остаются в плане.

## Статистика

Откройте **Обработка → Статистика** (`Ctrl+Shift+T`). Окно работает одновременно
с основной таблицей: после изменения значений, фильтра или выделения расчёт обновляется.
Снимок выбранных ячеек подготавливается порциями, между которыми интерфейс
обрабатывает события. Расчёт выполняется в фоне на готовом снимке. При изменении
данных незавершённый снимок или устаревший результат отбрасывается.
Кнопка «Отменить расчёт» останавливает подготовку снимка или запрашивает
отмену фоновой задачи. Предыдущие таблицы остаются доступны для просмотра
при пересчёте. Если изменились исходные данные, экспорт ожидает нового результата.
При изменении только правил расчёта используется актуальный снимок той же выборки.

Области расчёта: все пробы, текущая отфильтрованная таблица, выделенные строки
(достаточно выделения одной ячейки строки) или сохранённое представление. Пустое
выделение даёт пустую выборку, а не весь проект. Выбор сохранённого представления
не меняет фильтр основной таблицы. Настройки статистики сохраняются в `.apyro`.
Под таблицей результатов показаны правила текущей вкладки и фактически
применённые настройки расчёта.

Выберите показатели и при необходимости группировку по скважине, формации, методу
и другим колонкам. Пустая категория группировки остаётся отдельной группой.
Разные методы автоматически не объединяются и единицы не пересчитываются.

Вкладки:

- **Сводка:** N, среднее, медиана, выборочное SD (`ddof=1`), минимум, максимум,
  P10, Q1, Q3, P90, IQR, количество потенциальных выбросов.
  Двойной щелчок по строке открывает boxplot выбранного показателя по группам
  с точками использованных проб и числом значений в каждой группе.
- **Заполненность:** всего строк, использовано чисел, пусто, записи `<`/`>`/`≤`/`≥`,
  ND, прочий текст, исключённые и использованные интерполяции, процент чисел.
  Двойной щелчок по счётчику или проценту открывает список проб соответствующей группы.
- **Корреляции:** Pearson и Spearman, число полных пар и статус каждой пары показателей
  внутри каждой группы. Минимум — 3 пары (можно увеличить). Постоянный показатель
  даёт неопределённый коэффициент. P-value и статистическая значимость не оцениваются.
  Двойной щелчок по ячейке Pearson или Spearman открывает тепловую карту группы.
  В каждой парной ячейке видны коэффициент и число полных пар, в том числе когда
  коэффициент не определён.
  Кнопка **Матрица диаграмм рассеяния** строит графики для группы выбранной строки
  при 2–6 показателях. На диагонали показаны гистограммы отдельных показателей.
  Сначала выделите ячейку в строке нужной группы.
  Каждая диаграмма рассеяния использует только полные пары для своих осей,
  с теми же правилами исключения, что и корреляции. В панели указано её N.
  Кнопка **Сохранить матрицу…** выгружает PNG, SVG, PDF или переносимый JSON
  с выборкой, параметрами расчёта и данными матрицы. JSON открывается кнопкой
  **Открыть матрицу…** или через загрузку оформления в модуле «Графики».
- **Потенциальные выбросы:** значения за границами `Q1−1.5×IQR` / `Q3+1.5×IQR`
  при N≥4 с UUID пробы. Двойной щелчок выделяет пробу в основной таблице.
  Если проба скрыта, «Статистика» запрашивает подтверждение смены фильтра.
  Прежний фильтр можно вернуть кнопкой в строке состояния.
- **Сравнение:** для A и B выберите сохранённое представление или набор проб.
  Можно сочетать оба типа выборок. Для каждого показателя
  отображаются медианы, разница B − A, число использованных и исключённых значений.
  Пробы в пересечении учитываются в обеих выборках. При разных единицах или
  аналитическом контексте разница не рассчитывается. Для сравнения требуется
  указанный метод у каждого вошедшего измерения. Лаборатория, прибор, основание
  и другие поля контекста должны совпадать, если они указаны хотя бы у одного
  измерения. Двойной щелчок по счётчику
  открывает список проб с причинами исключения. Из списка можно перейти к пробе
  в основной таблице. Для скрытой пробы применяется фильтр её представления
  или открывается её сохранённый набор.
- **Повторные анализы:** внутри каждого метода, лаборатории и прибора рассчитывается
  размах по пробе, если доступны хотя бы два анализа. Для двух методов или лабораторий
  сначала вычисляется медиана по каждой стороне для каждой общей пробы, затем разность
  B − A. В таблице показаны число проб, медиана, P10 и P90 размахов или разностей.
  Единица, основание, программа нагрева, подготовка и фракция должны совпадать.
  Используются точные числовые результаты с указанным методом, включая нерабочие
  измерения. Если один анализ содержит несколько подходящих измерений, он представлен
  их медианой. Исключения QC учитываются по версии измерения. Двойной щелчок по строке
  показывает расчёт по пробам и позволяет перейти к ним в основной таблице.
- **Пороги и ND:** по каждому показателю, методу и лаборатории отдельно показаны
  число и доля записей ниже порога, выше порога и ND. Единицы и основания
  измерений разделяются. Знаменатель — непустые рабочие записи, включая
  исключённые QC. Числовые пороги из записей образуют отдельные диапазоны для
  `<`/`≤` и `>`/`≥`. Записи вроде `<LOD` учитываются без числового порога.
  По двойному щелчку доступны исходные записи, явно заданные LOD и LOQ и переход
  к пробам в основной таблице.
- **Сравнение с интерполяцией:** для выбранных показателей показывает исходную
  заполненность и медиану, медиану добавленных оценок и результат после заполнения.
  В расчёт включаются только актуальные оценки для пустых исходных ячеек с
  совпадающими единицами. ND, пороговые записи и исключённые QC значения остаются
  без замены. Причины исключения показаны в сводке и в деталях по пробам.
  Счётчик «Пусто без оценки» открывает список проб с незаполненными ячейками.

Пустые результаты обозначаются `—`; при N=1 выборочное SD не определено. Квантили
рассчитываются методом `linear`. Статистика использует float64; большие целые в
исходной таблице сохраняются точно, но в статистических расчётах возможна потеря
точности. Метрики сводки, выходящие за числовой диапазон, отображаются как `—`
с предупреждением в строке и сохраняются в JSON как `null`.
Методические определения: [pandas Series.quantile](https://pandas.pydata.org/docs/reference/api/pandas.Series.quantile.html),
[SciPy Pearson](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.pearsonr.html),
[SciPy Spearman](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.spearmanr.html).

По умолчанию числовые записи текстовых колонок не участвуют в расчёте. Для TOC,
Tmax или других смешанных колонок отметьте их в списке показателей и включите
**Читать числа в текстовых колонках**. Это преобразование только для расчёта:
`1,2` интерпретируется как 1.2; исходное значение не меняется. `<0.1` и `ND`
никогда не заменяются нулём, половиной LOD, средним или другим числом.
Распознаваемые маркеры необнаружения: `ND`, `N.D.`, `N/D`, `н/о`, `не обнаружено`;
прочие лабораторные обозначения учитываются как прочий текст.

Интерполированные колонки по умолчанию исключены. Их можно включить отдельно
для сравнения с исходными показателями, без заполнения исходных колонок. Устаревшие
интерполяции всегда исключаются с уведомлением. На каждый показатель выводится
число использованных интерполированных значений.

Для корреляций выберите не более 30 показателей. При большем наборе отключите
корреляции: сводка и заполненность останутся доступны. Фильтры и выбор показателей
позволяют ограничить объём работы; профилирование на крупных реальных проектах
ещё не выполнялось. Копирование и экспорт таблиц результата выполняются синхронно.

Выгрузка:

Таблицы результатов сортируются щелчком по заголовку. Копирование и CSV-экспорт
сохраняют порядок строк на экране.
Идентифицирующие колонки остаются видны при горизонтальной прокрутке.
Чтобы освободить место для метрик, снимите флажок «Закрепить идентифицирующие колонки».

- **Копировать вкладку** — таблица TSV в буфер обмена с защитой текста,
  похожего на формулу, при вставке в табличный редактор.
- **Экспорт вкладки CSV** — полная числовая точность, категории групп, область,
  число строк, время расчёта и основные политики включения данных.
- **Полный снимок расчёта JSON** — рассчитанные вкладки, настройки, методы, версии библиотек,
  UUID, использованные ячейки и сведения об источнике. Он позволяет пересчитать
  результат независимо от последующих изменений проекта. «Повторные анализы»,
  «Пороги и ND» и «Сравнение с интерполяцией» включаются в расчёт после первого
  открытия соответствующей вкладки. Если нужные колонки уже в актуальном снимке,
  дополнительная вкладка рассчитывается по нему.

Пример: в демонстрационном проекте выберите TOC, включите чтение чисел в текстовых
колонках и группировку по скважине. Для A среднее TOC = 1.566666…, N=3; для B
используется 0.8, а `<0.1` учитывается отдельно как цензурированный результат.

## Графики

Откройте **Обработка → Графики** (`Ctrl+Shift+G`). График строится на Matplotlib;
интерфейс и экспорт используют одну сериализуемую конфигурацию `PlotSpec`.

Сверка возможностей, известных ограничений, замеры скорости и порядок доработки
зафиксированы в [аудите визуализации от 4 ноября](docs/VISUALIZATION_AUDIT.md).

Новые поддерживаемые виды настраиваются через ту же панель **Свойства**:
X/Y/Z и область — в **Данные**, оси — на общих вкладках, оформление —
в **Маркеры** и **Категории**. Для погрешностей и векторов появляются
дополнительные поля показателей, для матриц — список **Показатели матрицы**.
Матрица исходных значений не вычисляет корреляции.
Параметры вида, например положение ступени, размер засечек, число уровней
или разрешение поверхности, задаются списками и числовыми полями.
Обязательного ввода JSON и отдельной вкладки «Библиотека» больше нет.

Неприменимые настройки отключаются или скрываются. В 2D/3D scatter работают
общие цвет, форма, размер, обводка, подписи и таблицы категорий; для линий,
матриц и поверхностей используется соответствующий набор свойств.
Виды без принятого контракта помечены **Экспериментальный**.
Необязательный экспертный редактор сохраняет специальные старые параметры;
нестандартное сохранённое значение не заменяется молча значением по умолчанию.
Старые привязки X/Y/Z преобразуются в общие поля, дополнительные привязки
переносятся через JSON вместе с осями. Сброс оформления сохраняет выбор данных.

Доступны X–Y, глубинный профиль, многотрековый глубинный планшет (до 10 треков),
гистограмма, горизонтальные box plot и violin plot. Для распределений числовой
показатель задаётся как X, группы — через категориальное свойство цвета.
Вырожденная группа violin отображается точками с пояснением.
Гистограммы групп используют общие границы интервалов в исходных единицах X.

В меню действий **Шаблоны осей** доступны HI–OI (X=OI, Y=HI), HI–Tmax, S2–TOC, S1–TOC, S1–S2,
PI–Tmax, HI–TOC и S1+S2–TOC. Шаблоны используют уже существующие показатели.
Группы методов и единицы не объединяются.

Обычный график по умолчанию следует общей области анализа. В его свойствах
можно выбрать локальную область, которая сохраняется с графиком и не меняет область
других инструментов. Команда **Зафиксировать набор проб графика…** сохраняет UUID
текущей области как набор проб. Значения измерений остаются в проекте.

Восемь шаблонов X–Y сохраняют ID и версию паспорта. При выборе шаблона
проверяются роли показателей и объявленные единицы. Для каждой оси должна
найтись одна совместимая колонка. График остаётся описательным, а слой
классификации подключается отдельно. Пакетный манифест содержит паспорт
с осями и ссылкой на [научные методы](SCIENTIFIC_METHODS.md). Для свободной
смены показателей выберите **Убрать паспорт диаграммы** в меню действий.

В **Шаблоны осей → Профили по MD** доступны профили TOC, S1, S2, S3,
Tmax, HI, OI и PI для точечных проб. По X откладывается показатель в единице
паспорта, по Y — измеренная глубина MD в метрах, по умолчанию возрастающая
вниз. Профиль требует однозначной привязки обеих колонок. Для TVD и других
единиц глубины используйте свободный глубинный график.
Пакетный манифест профиля явно указывает систему глубины MD.

Там же доступен паспорт **Планшет TOC, S1, S2 и Tmax**. Он требует
четыре однозначно сопоставленные колонки в единицах паспорта и общую
глубину MD в метрах. Порядок треков фиксирован паспортом и записывается
в пакетный манифест. Чтобы изменить состав или порядок, уберите паспорт
и продолжите работу со свободным планшетом.

В **Шаблоны осей → Интервальные профили по MD** для тех же восьми
показателей доступны паспорта интервальных проб. Они требуют отдельные
колонки `MD_TOP` и `MD_BOTTOM` в метрах. Имена `MD top` и `MD bottom`
также поддерживаются, как и явные роли этих колонок. На рисунке проба
занимает отрезок от верха до низа отбора. Пробы с низом на уровне верха или
выше исключаются с указанием причины. Манифест фиксирует обе привязки.

Оформление через вкладки:

- **Данные:** вид, область (проект, текущий фильтр, выделение или сохранённое
  представление), X/Y, подписи точек, чтение чисел из текста, включение актуальных
  интерполяций, интервалы гистограммы, плотность и соединение точек внутри группы.
- **Ось X / Ось Y:** подписи, пределы, линейная/логарифмическая шкала, инверсия,
  шрифты, цвет, поворот делений, фиксированный линейный шаг, дополнительные деления,
  обычный/научный формат чисел, основная/дополнительная сетка. Для планшета можно
  выбрать отдельный трек и задать его X независимо; Y общая. При выборе глубинного
  вида вручную глубина направляется вниз; её показатель назначает пользователь.
- **Маркеры:** независимо цвет, форма и размер по свойствам; цвет и размер могут
  использовать категории или числовую шкалу. Диаметр задаётся в pt (внутри scatter
  переводится в площадь). Настраиваются заливка, обводка, прозрачность, диапазоны
  размера и цвета, палитра и подпись цветовой шкалы.
- **Категории:** редактируемые цвета, формы, размеры и подписи легенды. Двойной
  щелчок по цвету открывает выбор цвета; форму задайте как `o`, `s`, `^`, `v`, `D`,
  `P`, `X`, `*` или `h`; размер — положительный диаметр в pt.
- **Оформление:** заголовок, подзаголовок, шрифт, аннотация, подписи точек,
  легенда, сетка, фон, физический размер, DPI, прозрачный экспорт, поля и промежутки
  между треками. В аннотации `\n` переводится в новую строку.

Цвет, форма и размер категорий назначаются по всему проекту, поэтому фильтрация
не переназначает стили. Числовые диапазоны по умолчанию также берутся из проекта;
их можно зафиксировать вручную. Палитры сохраняются в проекте и используются как
начальные при создании нового оформления. Именованные графики сохраняют свои копии.
Категориальное оформление ограничено 100 категориями на канал; при большем числе
выберите числовую шкалу или другое свойство. Легенда категорий сохраняет полный
набор категорий проекта, в том числе скрытых фильтром.

Через меню действий **Аннотации на графике…** можно добавлять, править и
удалять позиционные подписи, стрелки, прямоугольники и эллипсы. Правый щелчок
по области 2D-графика задаёт начальную точку аннотации. Координаты можно задать
в единицах осей или в долях области осей от 0 до 1, с началом внизу слева.
У стрелки X₂/Y₂ задают наконечник, у фигуры — противоположный угол рамки.
На планшете аннотация может быть закреплена за треком. В 3D доступны текстовые
подписи в координатах области осей. Аннотации сохраняются с графиком,
переносятся через JSON оформления и входят в экспорт. Фигуры не меняют
автоматические пределы осей.

На вкладке **Оформление** можно включить **Интервалы неопределённости
измерений** для X–Y, глубинного профиля и планшета точечных проб. Предпросмотр
и экспорт берут неопределённость из текущего измерения каждого показателя и
рисуют отдельные отрезки по X и Y. Если граница интервала на логарифмической оси
неположительна или единицы не совпадают, исключается соответствующий отрезок
и выводится причина. Точка и допустимый отрезок на другой оси остаются видимыми.

Команда **Добавить сохранённую кривую…** в меню действий накладывает результат
из архива подгонки на обычный X–Y-график. Кривая строится по сохранённой сетке,
а точки берутся из выбранной области графика. Легенда показывает имя архива,
метод и отметку устаревания. Манифест пакетного экспорта фиксирует архив,
настройки расчёта и контрольную сумму входов. Именованный график и JSON
оформления хранят ссылку на архив, поэтому для повторного открытия нужен проект
с этим архивом.

Для цвета по числовой колонке на вкладке **Маркеры** можно выбрать
нормировку **Числовые классы**. Введите минимум три возрастающие границы
через точку с запятой, например `0; 0,5; 2; 10`. Промежуточная граница
относится к следующему классу. Значения за крайними границами получают
цвет ближайшего класса, а пропуски сохраняют отдельный цвет. Границы
классов заменяют обычные минимум и максимум цветовой шкалы и сохраняются
с настройками графика.

Квалификаторы и ND исключаются с подсчётом причин. При логарифмических осях
неположительные значения исключаются явно. Интерполяции по умолчанию исключены,
а устаревшие исключаются всегда. Пропуск свойства цвета при числовой шкале
отображается отдельным цветом, пропуск свойства размера — базовым размером.
Исходные ячейки не меняются. Группу линий можно задать отдельно от цвета. Если отдельная группа не задана,
используется категориальная группа цвета. Можно разрывать линии на исключённых
пробах с известной позицией по X или глубине внутри текущей области. Линии
показывают порядок проб и не вычисляют значения между ними.

Щелчок по точке выделяет пробу в основной таблице по UUID. Режим **Выделять рамкой**
выбирает несколько проб. Выделение в таблице показывается красными кольцами;
это временное выделение не включается в экспорт. Пробы, скрытые фильтром таблицы,
выделить в таблице нельзя — измените её фильтр. Для распределений связь отдельных
баров/квартилей с выборками пока не реализована.

Подсветка точек и интервалов хранится отдельным слоем по UUID. В 2D изменение
выделения использует готовое изображение основы без повторного разбора данных;
карта также не пересчитывает агрегацию. Для 3D повторно рисуется canvas,
но подготовка данных не запускается. Если область графика/карты — **Выделенные
строки**, изменение выделения перестраивает данные и временно блокирует экспорт.
Сортировка и фильтры сохраняют связь с UUID; выбор рамкой применяется одним
событием таблицы. Подсветка не делает проект изменённым и не попадает в экспорт.

Масштабирование и перемещение доступны на панели Matplotlib. Чтобы перенести
полученный масштаб в `PlotSpec` и экспорт, нажмите **Сохранить текущий масштаб осей**.
В 3D эта команда сохраняет также пределы Z и положение камеры.
Команда **Автопределы** сбрасывает фиксированные пределы и возвращает исходное
положение камеры. Отмена/повтор оформления
на панели работают для успешно построенных состояний; исходные значения таблицы
этими действиями не меняются.

**Сохранить график** записывает именованную конфигурацию в `.apyro`; последняя
конфигурация также сохраняется вместе с проектом. JSON оформления переносится
между проектами с однозначным сопоставлением имени и единицы колонки; неоднозначное
сопоставление отклоняется. JSON оформления не содержит сами измерения.
Новые шаблоны дополнительно фиксируют тип и основание показателей; изменённые
единицы проверяются даже при сохранённом UUID. Старые JSON без этих полей
продолжают читаться. Изменение неиспользуемой колонки не блокирует перенос.

Экспорт: PNG, TIFF, SVG, PDF; размеры в мм, DPI, прозрачность. Предпросмотр имеет
то же соотношение сторон и физическую компоновку; при необходимости прокручивается.
Обычный экспорт использует настройки вкладок. Команда **Экспортировать видимые границы осей…**
сохраняет рисунок с текущим приближением. Если подписи выходят за холст,
предпросмотр и экспорт показывают предупреждение. Растровый экспорт ограничен 64 млн
пикселей. **Пакетный экспорт** в меню действий сохраняет все или выбранные именованные
графики и JSON-манифест с названиями, фактическими именами файлов и настройками.
`row_ids` содержит UUID входной области, `plotted_row_ids` содержит UUID после отбора по трекам,
а `panel_row_ids` фиксирует состав панелей сравнения. Для агрегированных видов это пробы,
переданные в построение после проверки данных. Динамические области вычисляются на текущих данных проекта.
Для глубинного планшета команда **Экспортировать отдельный трек…** сохраняет выбранный
трек с общей осью глубины, его настройками оси X и относящимися к нему аннотациями.
Рисунок, JSON оформления и манифест сначала записываются во временный файл
в той же папке. При совпадении имён пакетный экспорт публикует готовый файл под свободным именем.
Манифест перечисляет завершённые рисунки, предупреждения и ошибки.

Для повторения экспорта без исходного проекта выберите **Сохранить снимок
графика…** в меню действий. Файл `.aplot.json` содержит настройки графика,
значения используемых колонок для выбранных проб, нужные метаданные слоёв
и значения колонок оформления по всему проекту для восстановления палитр и
диапазонов. В отличие от JSON оформления, этот файл содержит исходные значения.
Команда **Экспортировать из снимка графика…** строит PNG, TIFF, SVG или PDF
по сохранённому снимку, даже если в приложении открыт пустой проект. Запись
снимка и построение изображения выполняются в фоне. Доступность шрифтов
и версий библиотек отрисовки зависит от среды воспроизведения.

Команда **Собрать многопанельный рисунок…** объединяет два или больше
именованных графиков в один PNG или SVG. В диалоге компоновки отметьте графики,
задайте порядок перетаскиванием или кнопками **Вверх** и **Вниз** и выберите число столбцов.
**Схема панелей** показывает расположение, размеры рисунка и DPI для PNG до сохранения.
Размер отдельной панели виден в подсказке ячейки.
Панели заполняются слева направо и сверху вниз. Каждая сохраняет оформление, размеры и область данных,
а общий DPI берётся из первого графика. Между панелями остаётся прозрачный
промежуток 3 мм. Лимит 64 млн пикселей действует на весь PNG. В SVG векторные
элементы каждой панели доступны для редактирования. Файл
публикуется после завершения всех панелей.

В диалоге выбора графиков для пакетного экспорта или многопанельного
рисунка можно включить **Единое оформление по текущему графику**. Фон, сетка
и типографика текущего построенного графика применяются к копиям выбранных
настроек на время экспорта. Данные, области, подписи и диапазоны осей, цветовые
классы и размеры остаются собственными у каждого графика. Манифест пакетного
экспорта содержит фактически применённые настройки.

Подготовка числовых столбцов выполняется в фоне; повторные запросы используют
кеш с обновлением при изменениях данных, QC, области и политики разбора чисел.
Копирование входных значений разбито на порции. Устаревший результат не заменяет
новый; на панели есть «Отменить подготовку». Лимит кеша разобранных столбцов —
128 МиБ; входной снимок и рисунок в этот лимит не входят.
Создание графика и растеризация предпросмотра, в том числе после масштабирования
и поворота 3D, выполняются в отдельном переиспользуемом процессе. GUI получает
готовый кадр; сохраняются выбор проб, подсветка, навигация и высокое DPI.
Изображение строится по всем данным, без прореживания. Процесс запускается
параллельно с созданием панели и подготовкой данных; старый кадр остаётся видимым
до готовности нового. Закрытие окна освобождает данные кадра и останавливает
процесс; при повторном открытии подготовка запускается заново.
Предыдущая сцена освобождает массивы при замене кадра. Индекс выбора проб
передаётся компактными массивами; числовые буферы принимаются без промежуточной
копии всего кадра. История и происхождение данных остаются в исходном проекте.
Крупные буферы входных данных также передаются отдельно; одинаковые индексы
проб во входном пакете используют общее представление.
Большие массивы значений упаковываются порциями, освобождая процессорное время
для интерфейса и сохраняя исходную точность чисел.
Новый снимок после правки хранит значения по колонкам, без отдельного объекта
на каждую строку. Квалификаторы и точность исходных чисел сохраняются.
Правка ячейки и её undo/redo обращаются к строкам по проверенным UUID/позициям;
словарь всех строк для каждой правки больше не создаётся.
Поля строк проекта хранятся компактно, сокращая стоимость полного обхода GC.
Дополнительные атрибуты строк, копирование и формат проекта сохраняются.
Одиночный и пакетный экспорт изображений работают в отдельном процессе
по снимку данных и настроек. Доступны прогресс и «Отменить экспорт»; отмена
сохраняет уже завершённые файлы пакета. Изменения проекта после захвата снимка
не меняют текущую выгрузку. Если данные изменились во время самого копирования,
экспорт нужно повторить. JSON оформления записывается синхронно.

Пример: загрузите демонстрационные данные, откройте графики, выберите X=TOC, Y=S2,
включите чтение чисел из текста, назначьте цвет по скважине и размер по MD.
Для S2–TOC отобразятся три пробы: пропуск S2 и цензурированное TOC исключатся.

Ограничения: передача объектов, сборка мусора Python и сложные фильтры на больших
проектах ещё могут задерживать GUI; полный SLA и общая память не приняты.
Явный вызов `redraw()` из Python остаётся синхронным. Динамический каталог добавляет библиотечные
команды Matplotlib/3D; при установке необязательных Seaborn/UltraPlot доступны
и их адаптеры. Явный errorbar из колонок частично доступен, но привязка к
неопределённости Measurement и собственный воспроизводимый результат регрессии
пока не реализованы. Корреляционная тепловая карта и матрица диаграмм рассеяния
с N пар доступны в «Статистике». В «Графиках» пока нет исходных пирограмм.
Интерпретационные/стратиграфические слои библиотечных типов пока не подключены;
связанное выделение доступно для библиотечного scatter, но не для всех остальных
видов. Seaborn/UltraPlot для основных графиков не нужны.

## Расчёты пиролиза

Откройте **Обработка → Расчёты пиролиза**. Выберите TOC/S1/S2/S3, объявите единицы,
укажите аналитический контекст и подтвердите совместимость измерений. Выберите
нужные HI/OI/PI/GP/OSI и названия новых колонок. OSI — это S1, нормированный
на TOC: `100 × S1 / TOC` в мг УВ/г TOC. При необходимости включите чтение
чисел из текстовых колонок; ND и `<LOD` числами не становятся.

Предпросмотр показывает по 200 проб на странице и сводку по всей области.
В узком окне он открывается на отдельной вкладке «Результаты». Кнопки предпросмотра
и создания колонок доступны под вкладками.
Ошибка отдельного показателя отображается рядом с его формулой и в сводке.
Если нужно исправить колонку или единицу входа, пояснение появляется и под
соответствующим полем.
Создаются колонки, для которых есть допустимое значение или диапазон.
Область по умолчанию — текущая таблица: её UUID фиксируются в определении расчёта,
последующая смена фильтра их не меняет. Также можно выбрать весь проект.

Полученные колонки доступны только для чтения и автоматически пересчитываются
при правке исходных значений, undo/redo и открытии проекта. Измеренные HI/OI/PI
не перезаписываются: задайте отдельные уникальные имена. Все новые колонки создаются
одной отменяемой операцией. Причина отсутствия результата доступна в подсказке ячейки.

На вкладке «Сверка с лабораторией» выберите колонки HI и PI и задайте абсолютные допуски.
Лабораторный PI можно указать в долях или процентах. Разница и допуск для PI
выражаются в долях (0,01 соответствует одному процентному пункту). Сводка охватывает
всю область расчёта. Переключатели позволяют просмотреть расхождения и пробы без
доступного сравнения. Кнопка «Выгрузить сверку…» сохраняет все результаты в CSV.
Кнопка «Сохранить сверку в проекте» записывает настройки, диагностику и результаты по всем
пробам области. В окне «Сохранённые сверки…» снимок можно открыть и выгрузить
после изменения входных данных или повторного открытия проекта. Сохранение
снимка поддерживает отмену.
Поиск по пробе, скважине, глубине или UUID действует на все страницы
предпросмотра. Enter в поле поиска переводит фокус к найденной строке.
Enter в таблице, двойной щелчок или кнопка «Показать пробу в таблице»
открывают выбранную строку.
Если проба скрыта, приложение предложит сбросить фильтр основной таблицы.
Для сверки без создания колонок снимите отметки в списке «Создать».

Новые расчёты проверяют рабочие измерения каждой пробы. Известные различия в
методе, лаборатории, подготовке, фракции или программе нагрева дают отдельную
диагностику. Аналогичная проверка действует при сверке с лабораторной колонкой.
Уже сохранённые определения расчёта сохраняют прежнюю политику. Контроль качества
показывает конфликты контекста у старых результатов и у проб, пропущенных новой
проверкой. Для старых колонок предупреждение также видно в подсказке ячейки.
Чтобы исключить конфликтующие пробы из самого расчёта, создайте колонку заново.

В расчётах используются только измеренные/вычисляемые входы с совместимыми единицами;
интерполированные входы запрещены. Формулы, коэффициенты единиц, ограничения,
источники и API описаны в [SCIENTIFIC_METHODS.md](SCIENTIFIC_METHODS.md).
Включите «Рассчитать стандартную неопределённость», если входы можно считать
некоррелированными и у каждого рабочего измерения указана неопределённость типа
`standard` в единицах входа. Предпросмотр покажет значение с `± u`, а подсказки
покажут вклады входов или причину отсутствия оценки. Предупреждение появляется,
когда стандартная неопределённость знаменателя достигает его значения.

Включите «Показывать диапазоны для входов ниже предела», чтобы рассчитать допустимые
диапазоны HI, OI, PI, GP и OSI. Например, при `S1 < 0,10` и `S2 = 0,90` PI лежит
в диапазоне `[0, 0.1)`. Для записи `<LOD` нужен числовой LOD рабочего измерения.
Диапазон виден в предпросмотре и в созданной колонке. В числовых операциях такая
ячейка считается пустой.

## Геометрическая интерпретация

Откройте **Обработка → Интерпретация**, загрузите схему JSON и выберите X/Y.
Оси проверяются по показателю и единице. Для колонок с произвольными названиями
роль можно задать в метаданных `property_role`. Числа текстовых колонок включаются отдельно.
Поддерживаются текущий фильтр, весь проект и выделенные строки.

В списке **Группа диаграмм** доступны оцифрованные SVG по HI–OI, HI–Tmax,
HI–TOC, PI–Tmax, S1+S2–TOC, S2–TOC и TOCo. Внутри группы выберите схему
по имени источника. Проверьте в предпросмотре её назначение, оси, единицы и
доступные колонки, затем нажмите **Применить схему из каталога**. Согласие типов
рассчитывается для стандартных HI–Tmax и HI–OI.
Границы и линейные или логарифмические шкалы перенесены
из приложенных рисунков. Для открытых траекторий HI–OI и HI–Tmax оценка
типа основана на ближайшей кривой в нормированных координатах. В новых редакциях
встроенных схем геометрический предел расстояния равен 0,15. Чтобы применить его
к ранее сохранённой схеме, выберите её в каталоге и подтвердите редакцию.
Номограмма
Jarvie в группе TOCo использует ось Kerogen Yield и доступна для справочного
просмотра. Для схемы Spasennykh требуется показатель S0+S1+S2.

### Исходные пирограммы

Выберите одну пробу в результатах и нажмите **Пирограммы пробы…**. Файл
Rock-Eval `.S00` с секциями `[Curves pyro]` и `[Curves oxi]` загружается
целиком. Доступны FID, CO и CO₂ для пиролиза и CO и CO₂ для окисления.
Сигнал отображается в исходных единицах файла, время отсчитывается отдельно
для каждой стадии.

Можно также прикрепить JSON запуска или выбрать колонки в таблице CSV/TSV
с заголовком. Для таблицы укажите время, сигнал, его единицу, канал
и стадию. Колонка температуры необязательна и должна быть в °C. Поддерживаются
UTF-8 и Windows-1251, а также десятичные точка и запятая. Один импорт таблицы
создаёт один ряд сигнала. Для дополнительного канала можно прикрепить тот же
файл с другой колонкой сигнала.

Если экспорт прибора начинается со строк метаданных, укажите номер строки
с заголовками. Разделитель можно выбрать вручную (табуляция, точка с запятой
или запятая). Ошибки чтения указывают номер строки исходного файла.
Если один файл содержит несколько запусков, укажите первую и последнюю строки
выбранного запуска. Для времени `ЧЧ:ММ:СС` отсчёт начинается с первой точки
выбранного ряда. Повторяющиеся отметки сохраняются, а обратный ход часов вне
перехода через полночь вызывает ошибку.

Отметьте запуски для наложения и выберите
канал, стадию и ось времени или температуры. Исходные сигналы с разными
единицами показаны на отдельных панелях. Для сравнения формы можно разделить
каждый сигнал на его максимальный модуль. Ряды сигналов и сохранённое наблюдение
хранятся в проекте вместе с пробой. Наблюдение видно в карточке интерпретации.
При закрытии с несохранённым текстом можно сохранить изменения, отбросить их
или вернуться к редактированию. Для удаления вложения из пробы выделите строку
запуска и нажмите **Открепить выбранный запуск…**. Исходный файл остаётся на диске.

Ограничение файла — 16 МиБ. Для JSON используется UTF-8. Пример с условными данными:

```json
{
  "format": "autopyro.pyrogram",
  "version": 1,
  "label": "Повторный анализ",
  "time_unit": "s",
  "temperature_unit": "°C",
  "heating_program": "Описание программы нагрева из лаборатории",
  "traces": [
    {
      "channel": "FID",
      "stage": "Пиролиз",
      "unit": "mV",
      "time": [0, 1, 2, 3],
      "temperature": [300, 305, 310, 315],
      "signal": [0.2, 1.4, 0.7, 0.3],
      "peaks": [{"label": "Пик", "index": 1}],
      "intervals": [{"label": "Отмеченный участок", "start": 0, "end": 2}]
    }
  ]
}
```

В каждом запуске пара `channel` и `stage` уникальна. Массивы `time` и
`signal` содержат одинаковое число конечных значений, минимум два.
Время строго возрастает. Массив `temperature` той же длины и
`temperature_unit` нужны для просмотра по температуре. `peaks`, `intervals`
и `heating_program` необязательны. Индексы начинаются с нуля, оба края
интервала включены. Если указан `analysis_id`, он должен принадлежать
выбранной пробе. Просмотр использует предоставленные отметки и исходные
сигналы. S1, S2 и Tmax остаются значениями из рабочих измерений проекта.

### Схемы и результаты

Схема определяет области и линии, систему координат, единицы, преобразования,
политику границ и допуск. Приложение проверяет её геометрию; научная обоснованность
полей и совместимость данных должны быть подтверждены автором схемы.

Результат для каждой пробы: внутри области, на границе, неоднозначно, вне областей,
недостаточно данных или вне области применимости. Перекрытия не разрешаются
произвольным приоритетом. Недопустимые полигоны отклоняются без исправления.
Цвет, масштаб изображения и пределы осей не участвуют в классификации.

В JSON-редакторе можно изменить координаты, подписи, цвета, преобразования и правила.
Изменение сохранённой схемы требует новой `revision`; нажмите **Применить редакцию**.
Для рисования и переноса вершин доступен **Графический редактор** (см. ниже).

Кнопка **Показать на графике** добавляет области к X–Y: они сохраняются в `PlotSpec`
и попадают в экспорт. На вкладке оформления настраиваются прозрачность слоя,
подписи областей и отметка редакции. Цвета областей задаются в JSON схемы.
На панели графика можно убрать слой. Для слоя фиксируется привязка X/Y и единиц;
подмена осей требует удаления слоя или восстановления привязки.
Именованный график хранит свою редакцию схемы; отличие от текущей отмечается.

Результаты и последняя схема сохраняются в проекте. При открытии проверяются входы,
определения расчётных колонок и редакция схемы. Правка данных помечает результат
как устаревший, и открытое окно пересчитывает его. Во время пересчёта таблица
очищается, а после успешного расчёта выделение восстанавливается по UUID проб.
Повторный расчёт с теми же данными и настройками не помечает проект изменённым.
Кнопка **Закрепить текущий расчёт
как базу** сохраняет снимок расчётной выборки в проекте для сравнения. После
открепления используется последний автоматически сохранённый предыдущий расчёт.
В окне **Сравнить расчёты…** выберите пробу, чтобы увидеть изменения исходных
значений, привязок, рабочих измерений и неопределённости по каждой диаграмме.

В карточке **Проверить выбранную пробу…** укажите автора решения. Там же доступна
история решений по пробе и схеме. Экспорт JSON и CSV учитывает текущий фильтр
результатов. CSV включает последнее решение и его актуальность, JSON дополнительно
содержит историю решений. Оба формата включают наблюдение по пирограммам.
Функция `replay_report` воспроизводит геометрический результат из JSON-снимка
по сохранённым исходным значениям, правилам, версиям и контрольным суммам.

В **Сводке по стволам и интервалам** можно настроить колонки ствола, глубины
или кровли и подошвы пробы. Для этого нужна сохранённая схема интервалов.
Привязка сводки сохраняется в проекте отдельно. Выберите **Второй ствол**,
чтобы сопоставить распределения на одном стратиграфическом уровне. Строки
таблицы сгруппированы по стволам, а профиль показывает ствол выбранной строки.
**Экспорт CSV…** выгружает видимую сводку с числом проб, распределением оценок
и долями неоднозначных и исключённых проб.

Пример полного процесса:

1. Импортируйте `examples/pyrolysis.csv`, выбрав нужные типы колонок.
2. В расчётах задайте единицы, контекст и включите чтение чисел из текста; создайте HI.
3. Откройте интерпретацию и загрузите `examples/interpretation-demo.json`.
4. Выберите исходный TOC и рассчитанный HI; объявите TOC как `%wt` и включите чтение
   его числовых записей. Единица HI — `mg HC/g TOC`.
5. Проверьте результаты и отобразите области на графике. Измените S2 и проверьте
   пересчёт HI и интерпретации. `<0.1` и ND останутся исключёнными.

**Демонстрационная схема содержит произвольные области A/B и не является научной
геохимической классификацией.** Рабочие научные поля загружаются из проверенных
схем пользователя. Для предоставленного позднее Python-кода предусмотрен контракт
`InterpretationEngine`; описание и пример адаптера — в `SCIENTIFIC_METHODS.md`.

Расстояния включаются только с обоснованной метрикой и не трактуются как уверенность.
Интервалы неопределённости поддерживаются API, их ввод через GUI пока отсутствует.
Расчёты и интерпретация на этом этапе синхронные; на крупных проектах возможна
задержка интерфейса. Полноценное геологическое заключение по набору независимых
методов этим геометрическим модулем автоматически не формируется.

## Графический редактор интерпретационных схем

В **Обработка → Интерпретация** выберите **Графический редактор** для текущей схемы
или **Новая схема** для создания с нуля. Новая схема требует названия, источника,
показателей и единиц X/Y. Можно выбрать отсутствие преобразования или log10;
другие параметры преобразований редактируются в JSON.

Редактор работает с частной копией. Исходная схема в проекте меняется только после
**Применить редакцию**. Отмена или закрытие окна отбрасывают изменения этой копии.
Для существующей схемы предлагается следующая редакция; поле можно изменить вручную.
Ранее использованную редакцию нельзя назначить другому содержимому.
Предыдущие версии сохраняются в `interpretation_scheme_revisions` внутри проекта.
Созданная схема сохраняется как текущая и до привязки к данным; её можно открыть
повторно вместе с проектом и назначить колонки позже.

Работа с геометрией:

- Выберите объект в списке; в выпадающем списке доступны внешний контур, отверстия
  и части MultiPolygon/MultiLineString.
- В режиме **Выбор / перенос вершины** потяните вершину мышью. Один перенос — одна
  операция undo/redo. Координаты также редактируются в таблице, без округления данных.
- **Вставить вершину** добавляет середину выбранного ребра; новую точку можно
  передвинуть или задать численно. **Удалить вершину** сохраняет минимум три точки
  контура или две точки линии. Замыкающая вершина полигона поддерживается автоматически.
- **Новая область / Новая линия:** ЛКМ добавляет точки, ПКМ, Enter или кнопка завершения
  заканчивает рисование. Esc сбрасывает незавершённый контур; следующий Esc закрывает окно.
- **Новое отверстие** добавляет контур выбранному полигону/части. **Новая часть объекта**
  расширяет объект до MultiPolygon или MultiLineString с сохранением остальных частей.
- Можно удалить отверстие/часть или целый объект. Название и цвет объекта задаются слева.
- Отмена и повтор доступны на панели и через Ctrl+Z / Ctrl+Shift+Z.

**Координаты редактора — analysis**, включая таблицу и мышь. Точки измерений сначала
преобразуются в это пространство по схеме. Формулы осей показаны над рабочим полем.
Линейная шкала редактора для log10-схемы показывает уже логарифмированные координаты;
научные границы при этом не переносятся в другую систему и не пересчитываются по виду.
Панорамирование, масштабирование, числовые пределы и **Вписать всё** меняют только вид.
Готовый рисунок с исходными единицами и оформлением экспортируется из модуля графиков.

Самопересечения и другая некорректная геометрия блокируют применение. Исправьте контур
или выполните undo; автоматического исправления/упрощения нет. Перекрытие валидных
областей и самопересечение линии показываются как предупреждения; перекрытие разрешено
для явного выявления неоднозначности. Общая граница без площади перекрытия не считается
перекрытием. Показываются первые пять предупреждений и общее число оставшихся.
Проверка покрытия/пробелов без явно заданной области применимости не выполняется.

Если в окне интерпретации уже есть расчёт, редактор показывает первые 2000 входных проб
и результат их классификации: зелёный — внутри, жёлтый — граница, пурпурный — неоднозначно,
серый — вне областей. Недопустимые координаты не отображаются. Подпись указывает,
сколько проб показано; это предварительная выборка. Во время переноса/незавершённого
контура точки серые, а классификация обновляется после завершения операции.
После применения основное окно пересчитывает всю выбранную область данных.

Изменение схемы помечает предыдущий результат как устаревший. Именованные графики
сохраняют собственные версии слоёв; открытое окно графика обновляет предупреждение
об отличии от новой редакции. Для показа нового слоя нажмите **Показать на графике**.

На больших схемах возможны задержки перерисовки и проверки перекрытий. Пока нет
совместного переноса нескольких вершин, привязки к сетке, импорта сканированных
диаграмм и преобразования координат самих границ. Авторский научный статус схемы
нужно пересмотреть при изменении границ; приложение не подтверждает его автоматически.

## Существующая база PostgreSQL

Схема и подготовленные импортёры в [database/README.md](database/README.md) сохранены.
В приложении выберите **Файл → Снимок базы данных → PostgreSQL**.
Используйте отдельную учётную запись с правами SELECT. Пароль в проект не записывается.

Первый адаптер читает `geochem.source_record.raw_cells`, сохраняет исходные группы
в названиях колонок и включает `source_record_id` / `sample_id`. Это снимок исходного
импорта, а не актуальная реконструкция изменённых нормализованных таблиц. Если снимок
отсутствует хотя бы у одной строки, загрузка завершается ошибкой без частичного импорта.
Автоматическая синхронизация и разрешение конфликтов пока не реализованы.

SQLite: укажите путь к файлу и точное имя таблицы/представления.
Оба адаптера ограничены 100 000 строками; при превышении загрузка отклоняется,
а не усекается. Живое подключение к PostgreSQL требует доступного локального сервера.

## Стратиграфия

Откройте **Обработка → Стратиграфия…**. Создайте интервалы вручную либо импортируйте
JSON, Excel или CSV (UTF-8; выбор разделителя и листа). Для Excel/CSV используются
точные заголовки экспортируемого представления `geochem.v_wellbore_lithostratigraphy`:
`wellbore_name`, `unit_name`, `unit_level`, `top_depth_m`, `bottom_depth_m`.
Их границы всегда выражены в метрах. Дополнительное поле `depth_reference`, если
заполнено, должно совпадать с объявленной системой глубин. Исходные ячейки, номера
строк и хеш файла сохраняются. Пример структуры: `examples/stratigraphy-demo.csv`
(синтетические интервалы; они не являются геологическими данными).

При импорте названия пород сопоставляются с каталогом stratapy. Используется
поле `lithology`, а при его отсутствии — единственная колонка с названием
`lithology_name`, `rock`, `rock_name`, «Порода», «Литология» или «Название породы».
Коды, точные названия каталога, распространённые русские названия и ранее выбранные
правила проекта распознаются автоматически; регистр и лишние пробелы не важны.
Составные описания и неоднозначные названия не подбираются по сходству текста.
Для общего названия «песчаник» используется базовый узор Massive sandstone (607).

Для неизвестных пород открывается **«Сопоставление названий пород»**: одно название
занимает одну строку с числом интервалов и предпросмотром узора. Неопознанные названия
показаны первыми. Выберите строку и нажмите **«Выбрать литологию для названия…»**:
назначение применяется сразу ко всем её интервалам. Оставленные без соответствия
значения импортируются без литологии, сохраняя исходные названия и ячейки файла.
Отмена этого окна отменяет импорт. Выбранные вручную соответствия запоминаются
в проекте и используются при следующих импортах; для записи правил на диск
сохраните сам проект.

Кнопка **«Сопоставить породы…»** на шаге «Интервалы» позволяет проверить назначения
повторно или выбрать любую другую исходную колонку. Для ранее сопоставленных данных
доступны исходные названия. Правки кодов вместе с их происхождением отменяются одним
**Ctrl+Z** и повторяются через **Ctrl+Shift+Z**; после правок постройте колонку заново.

Для построения колонки достаточно схемы интервалов; таблица проб не требуется.
Задайте систему глубин интервалов (для CSV/Excel — перед импортом), выберите
**«Ствол колонки»** из импортированных данных и **«Уровень колонки»**, затем нажмите
**«Построить колонку»**. На вкладке «Колонка» отображается весь диапазон интервалов
выбранного ствола и уровня. Панель над рисунком позволяет масштабировать и сохранять
изображение, в том числе PNG/SVG/PDF. При заполненной литологии рядом появляется
литологическая колонка с узорами stratapy. **«Сохранить схему»** сохраняет интервалы
в проект без привязки к пробам, с undo/redo; схема доступна после открытия проекта.
Построение само по себе не изменяет проект. Экспорт JSON также не требует проб.

Окно разделено на три последовательных шага: **«1. Интервалы»**, **«2. Колонка»**
и **«3. Замеры»**. В первом задаются интервалы и система глубин, во втором — вид
и оформление рисунка, в третьем при необходимости привязывается таблица измерений.
В таблице по умолчанию видны основные поля; флажок **«Геологические свойства слоёв»**
открывает зернистость, формы профиля, минералы, признаки и контакты. Уровни схемы,
режимы и геологические элементы имеют русские и английские подписи; внутренние
идентификаторы при импорте и сохранении не меняются.

На шаге **«2. Колонка»** выберите вид рисунка: литологическая колонка, профиль
зернистости с заливкой или колонка с профилем. Здесь же задаются размеры, качество,
подписи, пределы глубин, границы слоёв и легенда. Неактуальные для выбранного режима
поля отключаются. После первого построения изменение оформления автоматически
обновляет предпросмотр через 450 мс после последнего изменения. Быстрые правки
объединяются; скрытая колонка обновляется при возвращении на её вкладку. До обновления
сохраняется прежний рисунок, а экспорт временно отключён. Изменение шрифтов и цветов
сохраняет выбранный масштаб глубины; новые пределы глубин применяются явно.
Изменения самих интервалов требуют повторного построения кнопкой.
Для точного экспорта используйте **«Экспорт колонки с заданными
размерами…»**: размер окна предпросмотра не влияет на выходной файл.

Кнопка **«Настроить легенду, шкалу и свои породы…»** открывает обычные редакторы:
- **Легенда:** цвета, отступы, образцы, точное положение и заголовки разделов.
- **Деления и группы:** готовая шкала либо таблица подписей и числовых положений;
  состав групп выбирается флажками в списке. Группы можно скрыть.
- **Свои породы:** название, цвет и узор из каталога либо локальное изображение.
  Идентификатор создаётся автоматически; порода появляется в каталоге назначения.

Вверху настроек «Колонки» находится блок **«Шаблоны оформления»**. Настройте
размеры, шрифты, легенду, шкалу зернистости и другие параметры stratapy, затем
нажмите **«Сохранить как…»** и задайте имя. Выберите сохранённое имя в списке и
нажмите **«Применить»**; построенный предпросмотр обновится с обычной задержкой.
Повторное сохранение под тем же именем предлагает заменить шаблон. Удаление
шаблона не меняет текущее оформление. Шаблоны хранятся вместе с проектом:
сохраните сам проект, чтобы записать библиотеку на диск.
Применение сохраняет текущие стволы и уровни, пределы глубин, заголовок и
определения своих пород. Интервалы, привязка проб и история черновика не меняются.

Чтобы сопоставить несколько уровней одного ствола, выберите **«Основной уровень»**
и отметьте нужные флажки в блоке **«Дополнительные уровни рядом с колонкой»**.
Группа, подгруппа, формация и пачка располагаются рядом в этом порядке на общей
шкале глубины; масштабирование действует на все дорожки. Литология берётся только
из интервалов основного уровня, который также используется для результатов привязки.
Уровни без интервалов пропускаются с предупреждением. Выбор уровней сохраняется
вместе с оформлением и обновляет построенный предпросмотр с обычной задержкой.

Для сравнения скважин откройте в настройках «Колонки» блок **«Сравнение скважин
и стволов»** и нажмите **«Выбрать стволы для сравнения…»**. Отметьте дополнительные
стволы в списке с поиском. Выбранный в основных параметрах ствол остаётся первым;
каждый дополнительный получает свой блок с названием, уровнями и литологией.
Все блоки используют общие пределы глубины и синхронное масштабирование.
Сравнение ведётся внутри одной схемы с общей единицей и началом отсчёта глубины;
интервалы не сдвигаются и не выравниваются автоматически по названиям подразделений.
Уровни без интервалов пропускаются с указанием ствола в предупреждении.
Флажки сравнения сохраняются с оформлением; снятие дополнительных флажков
возвращает одну колонку. Ширина рисунка задаёт общий размер экспорта: для большого
числа дорожек увеличьте её в разделе «Размер и качество». В узком окне выберите
на панели просмотра **«Реальный размер»** и используйте горизонтальную прокрутку.

На вкладке «Колонка» рядом с рисунком есть компактная таблица интервалов.
Она использует то же выделение и те же данные, что и основная таблица: щелчок по
слою выбирает строку, выбор строк подсвечивает соответствующие глубины на колонке.
При нескольких уровнях таблица показывает их названия, а щелчок выбирает интервалы
только уровня соответствующей дорожки; подсветка также учитывает уровень.
При сравнении нескольких стволов таблица показывает название ствола, а выбор
и подсветка относятся только к его дорожкам. Выделение не перестраивает stratapy.
Ctrl добавляет/снимает выделение, Shift добавляет слои. Если на глубине есть
перекрытия, выбираются все соответствующие интервалы. Кнопка **«Показать выделенные»**
приближает выбранный диапазон. При включённом панорамировании/масштабировании
щелчки продолжают управлять навигацией. Выделение и подсветка не запускают stratapy
повторно и не включаются в экспорт через отдельную кнопку экспорта колонки.

Правки черновика интервалов имеют отдельную историю: **Ctrl+Z** отменяет,
**Ctrl+Shift+Z** повторяет изменение. Поддерживаются правки ячеек, добавление и
удаление строк, свойства схемы и массовое назначение литологии одним действием.
В незавершённом текстовом редакторе остаётся обычная отмена ввода Qt.
История черновика не затрагивает историю проекта; изменения попадают в проект
при сохранении схемы. Импорт новой схемы начинает новую историю черновика.

Вводить JSON для настройки не требуется. Старые настройки проектов читаются в
эти редакторы, в том числе дополнительные параметры легенды; изменение оформления
не меняет геометрию и редакцию схемы. Кнопка **«Сохранить схему и оформление»**
сохраняет результат, а сброс возвращает исходные настройки, включая таблицы.

В импортируемых файлах дополнительные поля остаются совместимыми со stratapy:
`top_grain`, `bottom_grain`, `connection_type`, `erosion`, `lenses`, `minerals`,
`features`, `contact`. В редакторе им соответствуют понятные подписи; минералы
и геологические признаки выбираются двойным щелчком из списков с поиском.
Подробнее о возможностях библиотеки: [stratapy](https://stratapy.readthedocs.io/en/latest/customisation/customisation_options.html).

Привязка проб и замеров — отдельный необязательный шаг в одноимённом блоке.
Задайте тип глубины и начало отсчёта интервалов и проб, выберите колонку **ствола**
и режим проб: **точечная глубина** либо **интервал отбора** с колонками верха и низа.
Обозначения систем глубин должны совпадать явно, например
`MD RKB`; приложение не определяет их по числам или названию файла. Разрешены
единицы `m` и `ft`, с переводом 1 ft = 0.3048 m; MD/TVD и начала отсчёта не
преобразуются. Названия стволов сравниваются точно, включая регистр, пробелы и
суффиксы боковых стволов. Скважина и ствол не объединяются автоматически.

Принадлежность определяется правилом **кровля ≤ глубина < подошва** для каждого
уровня `GROUP`, `SUBGROUP`, `FORMATION`, `MEMBER` отдельно. Разные уровни могут
перекрываться. Перекрытия одного уровня сохраняются и дают статус неоднозначности,
даже если совпадают названия. Подошва последнего интервала не включается. Значения
ND, `<LOD`, пропуски и интерполированные глубины не классифицируются. Интервалы
отбора задаются отдельным режимом, без автоматического перехода к средней глубине.

В режиме **«Интервал отбора [от, до)»** выберите разные колонки верха и низа.
Обе используют объявленную единицу проб. Проба получает название подразделения
только при полном включении в один однозначный интервал. Полное покрытие несколькими
соседними подразделениями даёт статус «Пересекает границу подразделений»; наличие
пробелов или выход за разрез — «Неполное покрытие»; отсутствие пересечений — «Вне
интервалов». Положительная длина перекрытия исходных интервалов внутри пробы даёт
«Перекрытие интервалов», в том числе при неполном покрытии. Нулевые и обратные
интервалы отбора помечаются как некорректные; ND, `<LOD` и интерполяции любой границы
исключаются. Название при любом статусе, кроме «Определено», остаётся пустым.

Диагностика ячейки и отчёт содержат длину и долю пересечения с каждым исходным
интервалом, покрытие их объединением, непокрытую и неоднозначную длину в единице
проб. Доля покрытия лежит в 0–1; сумма долей отдельных пересечений при перекрытиях
может превышать 1. Эти доли описывают геометрию отбора: значения TOC/S1/S2 и других
измерений между пластами не делятся и не усредняются автоматически.

«Проверить привязку» показывает результаты текущей отфильтрованной таблицы.
«Сохранить схему и привязку» сохраняет настройки в проект; «Создать колонки уровня»
добавляет название подразделения и статус **для всех проб**. Название при
неоднозначности остаётся пустым, кандидаты доступны в диагностике ячейки и отчёте.
Эти колонки доступны для фильтрации, группировки статистики и оформления графиков,
защищены от ручной правки и пересчитываются после изменения глубин или схемы.
Повторное создание тех же результатов не добавляет дубликаты колонок. Сохранение
настроек и создание колонок поддерживают undo/redo. Для изменения содержимого
схемы увеличьте редакцию: повторное использование сохранённой редакции с другим
содержимым отклоняется. Черновик окна не изменяет проект до явного применения.

Чтобы добавить к колонке профиль замеров, отфильтруйте таблицу до **одного ствола**,
сохраните привязку и нажмите «Показать график замеров с колонкой». В окне графиков можно выбрать X,
добавить треки планшета, изменить прозрачность, размер и видимость подписей колонок,
пределы осей и остальные настройки. Интервальная проба изображается вертикальным
отрезком от верха до низа, без маркера в средней точке. Низ можно также выбрать
на вкладке «Данные» окна графиков; режим доступен для профиля и планшета. Цвет
и размер по свойству задают цвет и толщину отрезка, а постоянная толщина задаётся
на вкладке «Маркеры». Форму по свойству и соединение точек для этого режима нужно
отключить. Щелчок выбирает пробу; прямоугольник выбирает пересекающие его отрезки.
Колонки не расширяют диапазон глубин; неподходящая
ось Y или смесь стволов блокирует построение. Слой содержит копию схемы, а при
отличии от текущей редакции выдаёт сообщение. Шаблоны и экспорт сохраняют слой;
кнопка панели графиков позволяет его убрать.
Колонка подразделений строится библиотекой [stratapy](https://stratapy.readthedocs.io/en/latest/)
рядом с треками и использует ту же шкалу глубины, включая масштабирование.
Необязательное поле `lithology` в JSON/CSV/Excel или столбец «Литология stratapy»
в редакторе включает соседнюю литологическую колонку. Для выбора породы дважды
щёлкните по ячейке «Литология stratapy» или выберите строку интервала и нажмите
**«Выбрать литологию…»**. Чтобы назначить одну породу нескольким интервалам,
выделите их строки или ячейки с Ctrl/Shift и нажмите эту кнопку: выбранная литология
применится ко всем выделенным строкам за один выбор. Пункт «Без сведений о литологии»
также очищает назначение сразу для всей выборки. Каталог содержит названия пород, чёрно-белые и цветные
варианты, дополнительные узоры stratapy и пользовательские литологии из оформления.
Поиск работает по названию или коду; в списке видны миниатюры, справа — увеличенный
образец. Подтвердите выбор кнопкой OK или двойным щелчком по породе. В таблице
отображаются название и узор, а в схеме сохраняется код. Пункт «Без сведений о
литологии» очищает назначение; отмена не меняет интервал. При импорте также
принимается код (например, `607`) или английское название (`Massive sandstone`).
Миниатюры загружаются по мере отображения и кэшируются с ограничением памяти;
построение графика для предпросмотра узоров не выполняется. Пустое поле
означает отсутствие сведений о литологии; тип породы по названию подразделения
не угадывается. Пропуски и перекрытия интервалов сохраняются; соседние слои
не объединяются. Стратиграфия также включается в
HTML/PDF/JSON отчёты с привязкой, версией схемы и статусом каждого уровня.

Модуль работает с локальной копией интервалов; прямого чтения стратиграфического
представления PostgreSQL из этого окна пока нет. SQL-миграции и данные БД он не меняет.

## Локальные карты

**Анализ по палеогеографическим областям:** после привязки проб нажмите
**«Геохимия по областям…»** в нижней панели окна карты. Выберите полигональный
слой (например, `T3`) и поле области (`Paleogeogr`). Колонки `TOC`, `HI`, `Tmax`,
`Well`, `Age`, `Depth`, `Method TOC` и `Method Pyrolysis` подставляются по именам;
проверьте их соответствие. Предварительно присоединять области к таблице не нужно.
Отметьте нужные значения возраста и методов (пустой список отметок означает «все»),
задайте глубину и нажмите **«Рассчитать сравнение»**. Возраст сравнивается буквально:
`T2–T3` не включается автоматически в `T3`. Для интервальных проб можно указать низ
интервала: используется положительное пересечение с диапазоном глубин.

Вкладки показывают сводную статистику, ECDF и boxplot для выбранного показателя,
а также диагностику фильтрации и пространственной привязки. В сводке доступны
число строк, допустимых чисел и скважин, среднее, медиана, выборочное стандартное
отклонение, минимум, максимум, P10/P90 и квартили. Методы TOC и пиролиза
фильтруются отдельно; по умолчанию распределения разных методов разделены.
Пробы на границах, в перекрытиях и вне областей, ND, квалифицированные пределы,
неконечные значения и явные исключения QC в числовую статистику не входят.
По умолчанию вес каждого замера одинаков. В режиме **«По скважинам»** сводка
и распределения используют одну медиану на скважину внутри каждой группы.
Для расчёта медианы нужна привязка к скважине. Проверка статистической
значимости не проводится. Фильтры окна сужают
текущую выборку карты. Доступен экспорт сводки и значений CSV, отчёта JSON
с параметрами и идентификаторами строк, графика PNG/SVG/PDF.

Окно анализа можно держать открытым рядом с картой. Выделение строки сводки
подсвечивает все полигоны выбранной области и пробы данной группы с учётом
возраста, глубины и метода; включаются и строки без допустимого числового
результата (счётчик «Всего»). Ctrl/Shift позволяют выделить несколько строк.
Щелчок по области анализируемого слоя на карте выделяет все её строки сводки
(TOC, HI, Tmax и методы) и прокручивает таблицу к первой из них. Полигоны с
одинаковым значением поля области соответствуют одной группе строк.
При изменении параметров, обновлении карты или закрытии анализа подсветка снимается.

После выбора строк сводки вкладка **«Пробы»** показывает исходные измерения
и причины исключения. Щелчок подсвечивает пробу на карте, двойной щелчок
переходит к исходной строке. На вкладке **«Профили глубины»** можно переключать
скважины и показатели. Шкала глубины общая для скважин выбранного показателя.
**«Контроль привязки»** показывает проблемные точки на карте и ключи строк
без координат в таблице. Сценарии сохраняют слой, поле, колонки, фильтры и
режим сравнения в файле проекта. Расчёт использует текущую выборку карты.

Для сравнения двух сценариев рассчитайте первый набор параметров, откройте
вкладку **«Сравнение A и B»** и нажмите **«Сохранить снимок расчёта…»**.
Повторите для второго набора параметров. Выберите снимки, показатель и методы
для A и B. Сводка показывает медианы, квартили, числа проб и скважин и
разницу B − A. Выбор области строит обе ECDF на одной шкале и подсвечивает
скважины по сохранённым координатам. Синий цвет соответствует A, оранжевый B,
фиолетовый общим скважинам при одинаковой колонке идентификатора.
Снимки сохраняются в проекте и экспортируются парой в JSON. Для сравнения
нужны одинаковые определения областей, единицы и режим расчёта.

Откройте **Обработка → Карты…**. Сеть и онлайн-подложки для работы не нужны;
в этой версии сетевые тайлы не подключаются. Импортируются локальные векторные
слои через GeoPandas (движок GDAL/pyogrio): проверены GeoPackage, GeoJSON, Shapefile и FlatGeobuf;
другие форматы зависят от установленных драйверов GDAL. Для многослойного файла
выберите слой. CRS автоматически читается из файла. Если CRS отсутствует,
выберите её из локального каталога PROJ с поиском по коду и названию;
также поддерживается ввод EPSG/WKT. Некорректная геометрия отклоняется без исправления;
пустые геометрии подсчитываются, Z сохраняется в исходном слое и не отображается.
Один импорт ограничен 100 000 объектов, без усечения. Исходные файлы не изменяются.

На вкладке «Атрибуты» выберите импортированный слой: таблица показывает все его
поля, FID и тип геометрии, включая записи без геометрии. Таблица доступна до
построения карты и сохраняется вместе со слоем в проекте.

В нижней таблице **«Слои»** перетаскивайте строки или используйте кнопки
**«Вверх» / «Вниз»**: первая строка рисуется поверх остальных слоёв.
На вкладке **«Настройки слоя»** выберите слой, поле и условие фильтра.
Исходные объекты сохраняются; флажок позволяет оставить скрытые категории
в легенде. Здесь же задаются поле подписи и размер текста: пересекающиеся
подписи размещаются с отступом либо пропускаются. Для числового поля выберите
режим **«Числовая шкала»**, палитру, линейный или логарифмический масштаб,
пределы и цвет пропусков. Нулевые и отрицательные значения логарифмической
шкалы отображаются цветом пропусков.

При выборе объекта карточка рядом с таблицей атрибутов показывает его поля.
Для связанного слоя скважин она также показывает число замеров в текущей
выборке, диапазон глубин и наличие числовых показателей. Связь требует
однозначного точного ключа скважины.

Команда **«Присоединить области к пробам»** добавляет выбранные атрибуты
полигонов и колонку статуса в таблицу замеров. Учитываются текущая выборка
проб и фильтр полигонального слоя. Попадания на границы, в перекрытия,
вне областей и отсутствие координат отмечаются отдельно; неоднозначным
попаданиям атрибуты не назначаются. Это снимок пространственной привязки
с происхождением в метаданных колонок; вся операция отменяется одной командой Undo.

Над картой можно **сохранить именованный вид** и восстановить его: общую CRS,
охват, порядок, видимость, фильтры и оформление импортированных слоёв.
Виды используют уже импортированные слои, без копирования их геометрии.
В **«Оформлении»** доступны заголовок и положение легенды, масштабная линейка
и стрелка истинного севера. Линейка рассчитывается по геодезическому расстоянию,
а направление севера учитывает проекцию; они обновляются при навигации.
Экспорт PNG/SVG/PDF/TIFF использует текущий охват и заданные размеры в мм и DPI.

Для CRS координат и карты доступны режим «Автоматически из данных» и каталог
CRS с названиями. CRS координат берётся из выбранного точечного слоя либо
метаданных `crs` координатных колонок. Для колонок Longitude/Latitude
(также lon/lat и Долгота/Широта) используется WGS 84. Для прочих колонок без
метаданных выберите CRS явно. Автоматическая CRS карты совпадает с CRS
точечного слоя, первого импортированного слоя либо координат проб.
Определённые названия обеих CRS отображаются на вкладке «Координаты».

На вкладке «Координаты» выберите X/Y и их CRS либо режим точного сопоставления
ключа пробы/ствола с полем точечного слоя скважин. Совпадение требует равенства
типа и значения: число `1` и строка `"1"` различаются. Повторный ключ в слое
не выбирается автоматически. Несколько проб одного ствола могут использовать
одну точку. Порядок координат всегда X/Y: долгота/широта либо easting/northing,
даже если EPSG перечисляет широту первой. GeoPandas преобразует геометрии
пакетно через строгую операцию pyproj, а сопоставление с площадками выполняет через spatial join;
преобразование выполняется
без скачивания сеток PROJ и без разрешения приблизительной ballpark-операции;
ошибки преобразования и координаты вне географического диапазона подсчитываются.

Цвет и размер символов задаются по числовым или категориальным свойствам.
Для геохимических семейств выберите колонку семейства и категориальный цвет;
приложение отображает предоставленные категории и не определяет семьи по карте.
Цвета, размеры и подписи категорий редактируются в таблице «Категории» и
сохраняются при фильтрации. Таблица, легенда и лимит 100 категорий на канал
учитывают только пробы, отображаемые на текущей карте. Доступны символ,
обводка, прозрачность, шрифты,
подписи и пределы осей, сетка, размеры изображения и DPI. Оформление, видимость
и порядок добавленных слоёв сохраняются в проекте вместе с копией геометрии,
атрибутами и происхождением. Слои отрисовываются в порядке списка, пробы — поверх.

Область карты: текущая таблица, все пробы либо выделение. Фильтры карты дополняют
эту область по точечной глубине, точному значению стратиграфии и календарной дате
ISO-записи (границы включены; это не приведение часовых поясов к UTC).
Значения глубины сравниваются в единице выбранной колонки. Если выбран низ отбора,
учитывается положительная длина пересечения с диапазоном; при одинаковых порогах
«от» и «до» проверяется попадание точки в полуоткрытый интервал пробы `[верх, низ)`.
Обратные интервалы, ND и пропуски любой границы исключаются с диагностикой.
Щелчок выбирает все пробы
в данной точке, прямоугольник — точки внутри области. Выделение передаётся таблице
и через неё другим окнам. Пробы, скрытые фильтром таблицы, не могут быть выделены
в ней: для такой выборки сбросьте фильтр таблицы. Панорамирование/масштабирование
доступно на панели; «Запомнить видимые пределы» фиксирует вид для экспорта.

Для агрегации выберите полигональный слой площадок, поле имени площадки,
показатель и mean/median/min/max.
Проба учитывается только при единственном покрывающем полигоне, включая границы.
Перекрытия и общие границы нескольких площадок дают неоднозначность, без двойного
счёта; отверстия полигонов учитываются. **N** — число проб, **n** — число допустимых
числовых значений. ND, `<LOD`, текст и исключённые интерполяции подсчитываются отдельно.
Агрегация выполняется по пробам, а не по скважинам: повторы увеличивают вес места.
Семейство на площадке — мода с явным статусом ничьей и частотами в снимке.
В режиме агрегатов цвет показывает значение, размер — N, подпись — N/n и способ;
щелчок выбирает пробы площадки. Координата символа — точка внутри полигона,
а не новая измеренная координата.

Экспорт: PNG, SVG, PDF, TIFF, полный снимок JSON и GeoJSON в WGS84.
В режиме «Только пространственные слои» GeoJSON содержит видимые векторные объекты
с учётом фильтров слоёв. В режимах с пробами GeoJSON содержит пробы и площадки.
JSON содержит настройки, CRS-операцию, версии библиотек, UUID выборки,
значения проб, слои и диагностику; данные проб вне выборки не включаются,
но импортированные фоновые слои сохраняются целиком. Растровые изображения
не являются GeoTIFF. Экспорт всегда перестраивает карту из готового снимка.
Изменение параметров или входных данных блокирует экспорт до обновления.
Файл карты заменяется атомарно; неудачная запись сохраняет предыдущую версию.

### Отдельный инструмент пространственной интерполяции

«Пространственная интерполяция…» фиксирует CRS, привязку координат, фильтры карты
и слои при открытии. При каждой проверке или расчёте выбранная область и значения
проб считываются из проекта заново. Окно показывает объём подготовленной выборки
до и после фильтров карты и число проб с координатами. На карте выберите локально
подходящую проецированную CRS в метрах. В окне интерполяции задайте показатель,
степень IDW, максимум и минимум соседей, радиус поиска и размер сетки. Укажите,
почему пробы сопоставимы по методу, стратиграфии и глубине. Метрические единицы
сами по себе не гарантируют отсутствие искажений
проекции. Требуются 4–1000 уникальных неколлинеарных мест; сетка 10–200 узлов
по каждой оси. Используются исходные точки проб, а не символы агрегатов площадок.
Начните с кнопки **«Проверить выборку»**, чтобы увидеть исключения, повторы и
доступность соседей. Меню **«Разделы…»** открывает любую вкладку в узком окне.

Повторные координаты по умолчанию отклоняются. Mean/median по месту разрешается
только явным выбором; при LOO исключается целое место со всеми его повторными
пробами. Интерполированные колонки не используются. Для расчёта на вкладке
«Поверхности IDW» используются заданные параметры. Сохраняются остатки по местам,
RMSE, MAE, смещение, число соседей, расстояние до ближайшего места и число проверок
вне обучающей оболочки.
Сетка ограничена выпуклой оболочкой и поддержкой радиуса/минимума соседей;
геологические барьеры эта маска не моделирует.

Вторая поверхность — **эмпирическая локальная оценка ошибки**: корень из IDW
квадратов LOO-остатков. Это диагностический показатель неопределённости,
**не кригинговая дисперсия, не калиброванная стандартная ошибка и не доверительный
интервал**. LOO не заменяет пространственно независимую проверку; на границах
обучающей оболочки проверка может быть экстраполяционной. Экспорт результата:
JSON со входным снимком/LOO/диагностикой/сеткой, CSV сетки, PNG и SVG двух поверхностей.

На вкладке **«Блочная проверка IDW»** проверьте прогноз на целых удержанных
пространственных блоках. Буфер дополнительно исключает из обучения соседние
локации. **«Сравнение настроек IDW»** сопоставляет заданные варианты, а
**«Устойчивость к разбиению»** показывает, как результаты меняются при другом
размере или сдвиге блоков. Во вложенной проверке параметры подбираются на
внутренних блоках, а качество оценивается на внешних.

На вкладке **«Сравнение методов»** можно построить вариограмму и сопоставить
IDW, линейный TIN, обыкновенный кригинг, сглаживаемый RBF, ближайшего соседа и
интерполяцию Клафа — Точера. Смотрите одновременно долю проверочных локаций
с прогнозом и ошибки на общих локациях, где прогноз есть у каждого
сравниваемого метода. Для визуального сравнения используйте общую цветовую
шкалу. Вид **«IDW и TIN · карта разности»** показывает TIN − IDW на общих узлах
и отдельно отмечает, где прогноз есть только у одного метода.

На вкладке **«Поверхности IDW»** или **«Сравнение методов»** после расчёта
выберите нужную поверхность. **«Добавить слои на карту»** добавляет
растровые слои в проект, а **«Экспорт GeoTIFF…»** сохраняет геопривязанную
сетку в CRS расчёта. Для обычной поверхности сохраняются прогноз, число
соседей и расстояние до ближайшей точки в метрах. Для карты разности
сохраняются разность и маска покрытия. Узлы вне расчётной области и
недоступные значения в соответствующих каналах записываются как NoData.
GeoTIFF содержит сетку данных, а TIFF из окна карты — изображение её оформления.

Синтетический пример: импортируйте `examples/map-samples.csv`, добавьте
`examples/map-wells.geojson` и `examples/map-sites.geojson`. Свяжите `Well` с полем
`Well` точечного слоя либо используйте Longitude/Latitude (EPSG:4326), задайте
CRS карты EPSG:32632. Для IDW отфильтруйте MD=1000, чтобы исключить повтор другой
глубины, и явно укажите синтетический контекст. Площадки перекрываются около E:
эта проба намеренно не должна учитываться на двух площадках.

Список слоёв и геометрия читаются в фоне с индикатором выполнения. Для карт
с 2000 и более пробами, векторными объектами или узлами растровых слоёв подготовка
и отрисовка выполняются в фоне. Масштабирование таких карт также рисуется в фоне.
Во время построения доступен индикатор выполнения. Изменившиеся настройки
вызывают повторное построение; устаревший кадр отбрасывается.
IDW/LOO выполняются в фоне на неизменном снимке.
Большие слои хранятся целиком в памяти; серверной подгрузки,
геодезического редактирования и общего GIS-редактора в этой версии нет.

## Отчёты HTML / PDF

Откройте **Файл → Отчёт…**. Выберите текущую таблицу, все пробы или выделенные
строки, колонки, группировку, сохранённые графики и политику обработки чисел.
Добавьте автора, заголовок и собственные выводы, затем нажмите «Собрать / обновить
отчёт». После изменения настроек необходимо собрать новый снимок.

В отчёт включаются происхождение данных, статистическая методика и версии библиотек,
описательная статистика, качество данных, корреляции, выбросы, выбранные графики,
геометрическая интерпретация и приложение с таблицей. При выборе более 30 колонок
корреляции отключаются. Лимит строк приложения настраивается от 0 до 10 000 и
не ограничивает выборку расчёта. Данные `<LOD` и `ND` не подменяются числами.

В HTML, PDF и DOCX таблица корреляций по умолчанию показывает пары с рассчитанным
коэффициентом и числом совместных наблюдений. Для остальных пар отчёт показывает
число пропусков по каждой причине. Включите **Показывать все пары корреляций**,
чтобы получить полную таблицу со статусами. В JSON всегда сохраняются все
проверенные пары, число совместных наблюдений и коды статусов.

Все графики перестраиваются **для выборки отчёта**, даже если их исходные настройки
использовали другую область. Оформление и индивидуальные политики числовых значений
и интерполяций сохраняются и указываются в подписях. Интерпретация пересчитывается
геометрическим ядром по последней сохранённой схеме с текущей привязкой, без
использования старого результата. Источник, версия и авторский научный статус схемы
фиксируются; ошибки несовместимой привязки нужно исправить либо отключить раздел.

HTML содержит встроенные изображения и работает без сети. PDF использует шрифты
с кириллицей, повтор заголовков, разбиение широких таблиц на панели и нумерацию
страниц. Предпросмотр Qt приблизительный: пагинация PDF выполняется отдельно.
Экспорт JSON сохраняет полный снимок **всех колонок выбранных проб**, исходных ячеек,
определений расчётов, статистики, схемы и настроек графиков вместе с изображениями.
Проб вне выборки в таблице снимка нет; категории оформления могут относиться ко
всему проекту. SHA-256 этого JSON указан в HTML/PDF для сопоставления файлов.
JSON экспортируется отдельно по явному выбору. Изменения проекта после сборки
не меняют готовый снимок. Каждый файл записывается атомарно.

## Измерения, повторные анализы и сохранение проекта

В таблице выберите ячейку и откройте **Правка → Измерения выбранной ячейки…**
или пункт контекстного меню **Измерения, источник и история…**. Карточка показывает
все результаты этого показателя для пробы, рабочий результат, метод, лабораторию,
версию, метаданные, источник и историю правок. Рабочий UUID и метод также видны
в подсказке ячейки. Производные колонки сохраняют свои определения и не становятся измерениями.

**Добавить результат анализа…** сохраняет отдельное измерение. Укажите метод,
значение и при наличии лабораторию, прибор, программу нагрева, подготовку,
фракцию, основание, LOD/LOQ и неопределённость. Новый результат не выбирается
автоматически. **Использовать выбранное измерение** обновляет таблицу и зависимые
расчёты; переключение и добавление поддерживают undo/redo. Ноль, отсутствие
результата, ND, `<`/`>` и приблизительное значение различаются. Число в записи
`<0.01` хранится как порог квалификатора и не объявляется LOD без метаданных.
Текстовые идентификаторы с ведущими нулями сохраняются буквально.
Снимки отчёта и статистики включают UUID рабочих измерений, повторы и сведения
об анализах только для выбранных проб/показателей.

Из Python API после открытия/синхронизации проекта можно добавить результат
через `project.science.add_result(sample_id, property_id, raw, analysis_fields=...)`,
затем явно выбрать его через `project.select_measurement(sample_id, property_id, result.id)`.
Выбор обновляет табличное представление и расчёты без Qt. Перед добавлением
результатов к созданному через API проекту вызовите `project.sync_measurements()`.

Проект версии 2 — SQLite с внешними ключами и проверкой целостности. UUID строк,
колонок и проекта сохраняются, в том числе при миграции JSON v1. Старые строки
не объединяются по именам; неизвестные методы не угадываются. Открытие v1 не
изменяет файл. При первом сохранении рядом создаётся точная копия
`имя.apyro.v1-<hash>.bak`, затем проект атомарно заменяется SQLite-файлом.
Старые версии приложения не читают v2; резервную копию можно скопировать под
расширением `.apyro` для открытия старым приложением.

Одновременные сохранения защищены системной блокировкой `.lock`. При изменении
проекта другим процессом устаревшая копия не перезаписывает файл: откройте новую
версию или используйте **Сохранить как…**. Файл `.lock` остаётся рядом, но сама
блокировка автоматически освобождается при завершении процесса.

Несохранённые изменения каждые 60 секунд записываются в отдельную копию.
Для именованного проекта она лежит рядом: `имя.apyro.autosave-<session>.apyro`.
Для нового проекта — в каталоге `AutoPyro-recovery` системной временной папки.
При открытии именованного проекта предлагается более новая копия; вручную её
можно открыть через **Файл → Восстановить автосохранение…**. Копия не заменяет
оригинал до явного сохранения. После сохранения или явного отказа от изменений
копия текущего сеанса удаляется. Системная очистка временной папки может удалить
автокопии новых проектов, поэтому рабочий проект следует сохранять явно.

Если основной файл повреждён, команда **Файл → Открыть проект…** проверяет
соседние автокопии и показывает путь и время изменения подходящей копии.
Если UUID оригинала прочитать не удалось, диалог сообщает, что совпали имя
и записанный путь. После подтверждения копия открывается как отдельный проект.
При сохранении предлагается новое имя с суффиксом `-recovered`. Повреждённый
файл и выбранная автокопия остаются на диске.

## Добавление данных в существующий проект

Откройте **Файл → Добавить измерения в текущий проект…**. Первый шаг — обычный мастер
чтения файла; второй — сравнение с текущим проектом. Ранее открытые данные,
UUID проекта, путь сохранения, графики и представления сохраняются.

1. Назначьте исходным колонкам существующие показатели, новые показатели или
   пропуск. По именам предлагаются только однозначные соответствия с одинаковым
   типом, единицей и основанием. Различающиеся единицы/основания не переименовываются
   автоматически: выберите отдельный показатель или заранее выполните явный перевод.
2. Отметьте колонки составного ключа пробы, например «скважина + номер пробы».
   Сопоставление точное, с сохранением ведущих нулей. Без ключей разные источники
   создают отдельные пробы, даже если имена совпадают.
3. Привяжите метод, лабораторию, прибор, программу нагрева, подготовку, фракцию
   и дату к колонкам файла; общий метод/лабораторию можно задать вручную.
4. Нажмите **Сравнить с проектом**. Вкладка **Пробы и решения** показывает совпадения,
   кандидатов и действия страницами по 100 строк. Все расхождения и ошибки собраны
   на отдельной вкладке. Неоднозначные совпадения и повторяющиеся ключи среди новых
   проб требуют явного решения: выбрать существующую пробу, создать отдельную или
   пропустить строку. Для следующего анализа одной новой пробы выберите
   **Добавить повтор к новой пробе** и укажите предыдущую строку, создающую её.
   Новые пробы с одинаковым ключом автоматически не объединяются.
5. Выберите политику рабочих результатов и примените импорт. По умолчанию текущие
   измерения остаются рабочими, новые результаты доступны в карточке ячейки.
   Другие варианты: заполнить только отсутствующие результаты либо выбрать новые
   рабочими. ND и `<LOD` не считаются обычными пропусками для заполнения.

Повторная загрузка распознаётся по SHA-256, листу, строке источника, назначению
показателя и исходной записи. Она не отменяет локальные правки. Если раньше
импортировалась только часть колонок того же файла, добавляются только новые
показатели. Без хеша содержимого совпадение источников не предполагается.
При изменении файла во время чтения или после предпросмотра импорт блокируется
до повторного чтения. Превышающие одну страницу данные не отсекаются.

Применение — одна операция undo/redo; отмена до применения не меняет проект.
Сравнение и подготовка выполняются в фоне на копии, а перед применением проверяется,
что проект не изменился после предпросмотра. Протокол сохраняется внутри `.apyro`,
доступен через **Файл → Протоколы импорта…** и остаётся в истории после отмены.
Новый показатель, отсутствующий в исходном анализе старой пробы, оставляет пустую
ячейку без выдуманного измерения «результат отсутствует».

## Обновление снимка базы данных

Для проекта, созданного из SQLite либо поддерживаемого PostgreSQL-снимка, выберите
**Файл → Обновить снимок БД…**. Окно сравнивает три состояния: последний принятый
снимок источника, текущие локальные результаты и новый согласованный снимок БД.

Для SQLite при первом обновлении отметьте уникальный ключ из исходных колонок.
Можно выбрать несколько полей. Порядок строк не используется, пропуски и повторения
ключа блокируют обновление. После применения ключ фиксируется. PostgreSQL использует
`source_record_id`; для непиролитических профилей сохраняются исходные фильтры,
аналитическая группа, вариант и номер повтора. Имена проб не являются ключом.

После **Прочитать и сравнить**:

- Если изменился только источник, предлагается новый результат БД; прежнее измерение
  сохраняется отдельно. Выбор можно изменить до применения.
- Если изменены только локальные данные, по умолчанию они сохраняются. При необходимости
  можно явно восстановить значение источника отдельным измерением.
- Если изменились обе стороны и результаты различаются, необходимо выбрать решение.
  При сохранении локального значения новый результат БД остаётся нерабочим повтором
  с собственным происхождением. Тот же конфликт не запрашивается заново до изменения источника.
- Новые записи можно добавить или пропустить. Исчезнувшие из БД пробы требуется явно
  сохранить локально: обновление не удаляет их. Состояние отсутствия фиксируется в снимке.
- Неразобранный новый числовой результат не заменяет локальное измерение. Его можно
  сохранить для аудита нерабочим; новую некорректную строку можно только пропустить.

Изменение набора полей требует отдельного подтверждения. Исчезнувшие поля не очищают
локальные данные; новые поля пока не создают показатели автоматически. Исчезновение
ключа или изменение единицы/определения показателя в нормализованном каталоге PostgreSQL
блокирует обновление до явного повторного импорта. Для SQLite и raw-снимка PostgreSQL
сохраняются объявленные при исходном импорте типы и единицы; значения отдельной колонки
с названием единицы не интерпретируются автоматически.

Сравнение и подготовка выполняются в фоне. До применения проект не меняется;
изменение проекта после предпросмотра блокирует применение устаревшего результата.
Вся операция поддерживает undo/redo, включая состояние базового снимка. UUID существующих
проб/показателей, исходные значения, повторы и оформления сохраняются. Проверка без
изменения рабочих данных не делает интерполяции устаревшими.

**Файл → Протоколы обновления БД…** показывает решения и сравнивавшиеся значения.
Последнее время проверки видно в строке состояния. HTML/PDF/JSON-отчёт и снимок
статистики сохраняют состояние выбранных проб, включая отсутствующие в источнике.
Это состояние на момент чтения, а не постоянная синхронизация или наблюдение за БД.

SQLite читается через `mode=ro`, `query_only` и одну транзакцию; локальный проект или
автокопию нельзя сохранить поверх исходного SQLite-файла. PostgreSQL читается в
read-only repeatable-read транзакции. Приложение дополнительно отклоняет административные
роли, права записи/владения схемой и объектами, в том числе через членство в других ролях.
Используется существующая учётная запись `readonly`: настройка описана в
[database/ACCESS.md](database/ACCESS.md). Приложение не перенастраивает роли автоматически.

Пароль не входит в проект, снимок или протокол. Для адреса, совпадающего с локальной
конфигурацией, он может подставляться из `.env`/окружения. Для другого сервера поле
пароля остаётся пустым; полный адрес подключения показан перед чтением.
Чтение не усекается молча: превышение лимита адаптера останавливает обновление.
Перенос проекта на другой компьютер не требует БД для просмотра, но для повторной
проверки источника нужен доступ по сохранённому адресу и актуальные реквизиты.

## Контроль качества

Откройте **Обработка → Контроль качества…**. Панель показывает ошибки и предупреждения
по формату записи, единицам и физическим ограничениям пиролитических показателей,
недостающему методу/лаборатории, различающимся повторам и противоречивым контекстам
рабочих S1/S2/S3. Можно фильтровать по уровню, правилу, решению, показателю,
пробе, скважине, глубине, UUID и источнику. Доступен фильтр по действующим
исключениям. Кнопка перехода открывает ячейку показателя. Если проба или колонка
скрыта, QC предложит временно её показать. Кнопка «Вернуть вид таблицы» восстанавливает
фильтр и видимость колонок. Сохранение проекта использует исходный вид.
В карточке замечания указаны файл, лист и строка либо координаты записи БД.
Кнопка «Источник…» показывает полный путь и остальные сведения происхождения.

Автоматическое распознавание использует название показателя или заголовок,
сформированный импортом, например `Pyrol6 / S3`. Для отношения `S2/S3`
сохраняется проверка формата, а правила отдельного измерения S3 не применяются.
Явно сохранённая роль показателя имеет приоритет.

Кнопка **«Профиль порогов пиролиза…»** открывает редактируемую таблицу порогов
TOC, S1, S2, Tmax, HI и OI. Включите «Применять пороги в этом проекте», чтобы
проверять измерения и вычисляемые HI/OI. Выход за типичный порог даёт предупреждение,
а за абсолютный — критическое предупреждение. Если диапазон `<LOD` пересекает
порог, проверка сообщает о неоднозначности и перечисляет затронутые границы.
Числовые пределы сверху и снизу учитываются с их строгими или включёнными границами.
Распознавание `<LOD` с числовым LOD действует при любом состоянии профиля.
В основном окне QC видны состояние профиля и количество проверенных и пропущенных
записей. Кнопка «Охват проверок…» показывает распознанные роли, причины пропуска
по показателям и охват сохранённых диагностик HI/OI в выбранной области.
В редакторе можно указать источник порогов, версию и описание применимости
методики. В поле «Применять к пробам» можно выбрать весь проект или сохранить
текущий состав именованного набора. Чтобы обновить состав, выберите набор
заново. Область просмотра QC и фильтры замечаний задаются отдельно.
Настройки сохраняются в проекте и поддерживают отмену.

Предупреждение можно принять с обязательным комментарием или вернуть на рассмотрение.
Для группового решения выделите строки с Ctrl или Shift. Ctrl+A в таблице QC
выбирает текущую выдачу. В диалоге видно, сколько выбранных замечаний можно
принять или вернуть. Принятие требует общего комментария. Отмена возвращает
все решения группы одной операцией.
Принятие не исправляет значение и не исключает его автоматически. Отдельно можно
исключить конкретное измерение из статистики, пиролитических расчётов, графиков/карт,
геометрической интерпретации или интерполяции, указав причину. В других видах анализа оно остаётся
доступным. Исключение не удаляет исходные значения и действует при использовании
этого измерения. Нерабочий повтор не влияет на текущую таблицу. Кнопка
«Действующие исключения…» открывает причины и позволяет снять исключение
после исчезновения замечания.

Решения сохраняются с версией правила, входов и описанием пороговой методики.
При изменении этих данных требуется новое рассмотрение. Исключения относятся к конкретной версии измерения. Решения и
снятие исключений поддерживают undo/redo. Статистика показывает число исключённых QC
значений; вычисляемые показатели получают явную диагностику вместо скрытой подстановки.
Снимки статистики и отчёта сохраняют применённые политики. HTML/PDF/JSON-отчёт включает
раздел QC с действующими исключениями. Лимит приложения ограничивает показ строк.
В таблице замечаний первыми идут ошибки, затем критические и обычные предупреждения.
Опция «Только замечания QC к рассмотрению» исключает принятые замечания из
таблицы до применения лимита строк.
JSON содержит полный список действующих исключений и исходные записи политик.

Это механические проверки данных, а не классификация зрелости, загрязнения или
геологического происхождения. Для повторов с одинаковым основанием QC сравнивает
значения в совместимых единицах. Если для всех повторов заданы сопоставимые
интервалы неопределённости, предупреждение появляется при отсутствии общей части.
При недостающих или несопоставимых декларациях применяется точное сравнение.
Отдельная проверка учитывает числовые пределы, `<LOD` и `ND` с заявленным LOD.
`ND` без числового предела остаётся вне сравнения по интервалам.
Проверка описательная, без оценки статистической значимости.
Подробнее — в `SCIENTIFIC_METHODS.md`.

## Ограничения текущей версии

Научная модель измерений, добавление анализов по точному ключу и базовая панель QC
доступны. Сопоставление по координатам, перекрытию глубин и похожим именам ещё не
реализовано. При совпадении ключей у новых строк укажите явно, какие из них
создают отдельные пробы, добавляют повтор к новой пробе или пропускаются.
ND/LOD можно явно импортировать в числовую колонку; по умолчанию смешанные колонки
пока предлагаются текстовыми. Квалифицированные результаты не участвуют в обычной
числовой интерполяции. Стандартную неопределённость можно распространить в формулах
пиролиза по отдельной настройке. Передача в геометрическое ядро задаётся отдельно.
Для непиролитических профилей отдельной области исключений QC пока нет.

Данные хранятся в памяти; отрисовка использует `QAbstractTableModel`, но постраничного
чтения с сервера пока нет. Предпросмотр отображает 100 строк, импортирует все выбранные
строки. Открытие проекта, сборка отчётов, подготовка и экспорт графиков используют
фоновые задачи. На больших проектах сборка снимка и установка первого кадра всё
ещё могут давать заметные паузы. См. [замеры](IMPLEMENTATION_PLAN.md#2-производительность-хранения-снимков-и-интерфейса--p0).
Закреплённая колонка остаётся видимой при горизонтальной прокрутке.

Автоматического пересчёта интерполяций пока нет. Обновление БД поддерживает текущий
основной источник проекта; универсальное обновление нескольких независимых БД,
переназначение адреса источника и автоматическая миграция его полей пока не реализованы.
График интерполяции служит только предпросмотром; отдельный модуль графиков
предоставляет научное оформление и экспорт.
Исходные файлы в проект не встраиваются; сохраняются их путь, хеш и импортированные ячейки.

HTML, кириллица и пагинация PDF, атомарная запись и блокировка устаревшего предпросмотра.

точные имена стволов, несовместимые системы глубин, перевод m/ft, квалификаторы,
пересчёт и защита производных колонок, undo/redo, версии схем, перенос шаблонов
графиков между проектами и неизменность диапазона глубин при отрисовке фона.
Для интервальных проб проверяются включение, касание границ, разрывы и перекрытия,
покрытие объединением без двойного счёта, единицы длин, обе границы и их квалификаторы,
отрезки на графиках, выбор по пересечению, шаблоны и восстановление проекта.
Для карт проверяются четыре реальных векторных формата, неизменность источников,
CRS и порядок координат, точные ключи, фильтры, отверстия/перекрытия площадок,
счётчики N/n, категории, экспорт и связанное выделение. Для IDW проверяются
эталонный прогноз, исключение коллокаций целиком в LOO, маска оболочки/радиуса,
остатки, квалификаторы и запуск только явной командой.

## Геохимия вне пиролиза

Меню **Обработка → Геохимия** содержит семь самостоятельных разделов с 13 профилями:

- **Изотопы нефти** — Sofer CV.
- **Геохимия газа** — молекулярные отношения и изотопный порядок C1–C3.
- **Органическая петрография** — Ro витринита и макрогруппы керогена.
- **Фракционный состав SARA** — состав и баланс фракций.
- **Элементный состав** — H/C–O/C из массового состава и готовых отношений.
- **Хроматография и биомаркеры** — Pr/Ph–Pr/nC17–Ph/nC18, CPI C24–C34 и OEP C27, стераны/гопаны, MPI-1–DBT/Phen.
- **Экстракция и TOC** — отношение экстракта к органическому углероду.

Для CPI и OEP привяжите все 11 пиков nC24–nC34 одного анализа и одной фракции.
Выберите площади `[a]` или массовые концентрации `[ca]` с единой основой измерения.
При нулевом знаменателе соответствующий индекс остаётся пустым. Формулы и интервалы
соответствуют [таблице OA6 USGS](https://pubs.usgs.gov/of/1998/ofr-98-0034/OA.pdf).
Чтобы посмотреть распределение, выделите одну строку результатов и нажмите
**Профиль н-алканов**. Высота столбца показывает долю пика в суммарном сигнале
C24–C34. При нулевой сумме или неполном наборе пиков профиль недоступен.

После расчёта SARA откройте **Треугольную диаграмму SARA**, чтобы сравнить
доли насыщенных, ароматических и суммы смол с асфальтенами. График приводит
доли к 100% для проб с полным составом и балансом в заданном допуске.
Число показанных проб указано под диаграммой. Нажатие точки открывает строку
с исходной суммой SARA и результатами расчёта.
Для сравнения отдельных фракций выделите до восьми строк и нажмите
**Сравнить профили SARA**. Профили показывают исходные массовые доли всех
четырёх фракций на общей шкале от 0 до 100%.

После расчёта **Изотопы газа · порядок C1–C3** выберите до восьми строк и
откройте **Диаграмму Chung**. График показывает δ¹³C на шкале VPDB по оси Y
и обратное число атомов углерода по оси X. Каждая линия соединяет три
измерения одной пробы. [Определение диаграммы Chung](https://doi.org/10.1016/0009-2541(88)90108-8).

Каждый раздел открывается отдельной вкладкой со своими профилями, параметрами
и привязками. Условия применимости и допуски показываются только для выбранной
методики. Импорт исходных измерений выполняется отдельно, до открытия анализа.
Сохранённые проекты,
результаты и протоколы прежнего общего модуля совместимы с новым разделением.
Расчётные профили отделены
от методов, позволяющих назначать интерпретационный тип. Применимость,
подготовку материала и совместимость измерений подтверждает аналитик.

Работа с текущей PostgreSQL БД:

1. Откройте **Файл → Импорт геохимии из БД…** или одноимённую команду на
   стартовом экране. Проверьте соединение и заполненность доступных показателей.
   Чтение выполняется в `REPEATABLE READ, READ ONLY`.
2. Выберите набор показателей, аналитическую группу, способ измерения, загрузку,
   скважину и номер повтора. Нажмите **1. Загрузить предпросмотр**, проверьте снимок,
   затем **2. Открыть в основной таблице**. Проверка несохранённых изменений действует как обычно.
   Превышение лимита отклоняет запрос без усечения. Пароль в проект не попадает.
3. Откройте нужный раздел в **Обработка → Геохимия**. Пройдите вкладки
   **1. Метод → 2. Привязки → 3. Условия**: выберите метод и выборку,
   проверьте колонки и единицы, задайте контекст и подтвердите применимость.
   Подсказка возле кнопки **Рассчитать** объясняет, чего не хватает для расчёта.
   Для изотопов подтвердите VPDB,
   для Sofer — сопоставимые C15+ фракции нефти. Автоматическая подсказка
   опирается на исходную группу и название поля. Кнопка **Подобрать незаполненные привязки**
   сохраняет ручной выбор; произвольные колонки связываются вручную.
4. Нажмите **Рассчитать**. Числовые результаты выводятся отдельными столбцами,
   действия с готовым результатом включаются после расчёта. По необходимости
   добавьте результаты в таблицу (есть undo/redo), стройте график в общем
   редакторе оформления, выбирайте пробы по UUID или экспортируйте протокол.
   Для Sofer автоматически создаётся схема Shapely с границей CV=0.47.
5. Сохраните проект `.apyro`. Общий отчёт HTML/PDF/JSON включает сохранённые
   методики с новым пересчётом для выборки отчёта. JSON протокола самодостаточен:
   `autopyro.nonpyro.replay_report(protocol)` воспроизводит расчёт без БД.

Одна строка снимка соответствует `source_record_id`; совпадающие имена проб
не объединяются. Сохраняются ID пробы, исходной записи, загрузки, анализа,
номер повтора и хеш исходного файла. При импорте можно включить
**Загрузить несколько наборов показателей** и **Сохранить все повторы анализов**.
Выбранный номер повтора определяет рабочие значения таблицы; остальные
измерения сохраняются отдельно. Если выбранного повтора нет, значение остаётся пустым.
Новый снимок заменяет локальную таблицу с обычной проверкой несохранённых изменений.

**Обработка → Геохимия → Паспорта и сравнение проб…** открывает общий экран:

- Анализы автоматически относятся к одной логической пробе только при совпадении
  ID пробы в одной БД и состояния материала. Для файлов и ручных данных выберите
  несколько записей и нажмите **Объединить выбранные записи…**. Это связь между
  строками: исходные строки, UUID и измерения сохраняются. Есть undo/redo.
  Экстракт и остаток связываются с исходной пробой отдельно, без объединения материалов.
- **Паспорт пробы** показывает идентичность, скважину, интервалы, материал,
  исходные записи и сохранённые результаты. **Анализы и повторы** сохраняют исходные
  значения, единицы, номера анализов и повторов, происхождение и QC. При нескольких
  рабочих значениях выберите одно измерение для паспорта. Оно не меняет рабочую
  проекцию основной таблицы; после изменения измерения выбор нужно подтвердить заново.
  **Доступность методик** показывает наличие входных данных, а применимость и условия
  по-прежнему подтверждаются в соответствующем аналитическом модуле.
- Для сравнения сохраните выбранные пробы как именованную группу либо выберите
  отдельные пробы на вкладке свойств **Сравнение**. Группы A и B должны быть
  непересекающимися. Для каждого исходного числового показателя рассчитываются N,
  среднее, медиана, выборочное SD и разность средних B − A; график показывает
  отдельные пробы и среднее в единицах выбранного показателя.
  Каждая проба даёт не более одной точки. ND, пределы, пропуски, неоднозначные значения,
  несовместимые единицы/основания и исключения QC показываются как исключённые,
  без подмены нулями. Сравнение разных материалов требует явного подтверждения.

Связи, выбор измерений, группы и последнее сравнение сохраняются в `.apyro`.
После сравнения по двум или более показателям можно открыть **Анализ главных
компонент (PCA)**. Для расчёта нужны как минимум три полные пробы и два
независимых направления вариации. Показатели стандартизируются по среднему
и выборочному стандартному отклонению. Постоянные показатели исключаются.
График показывает координаты PC1 и PC2 с цветом по группам. Таблица показывает
коэффициенты показателей. Чтобы сохранить расчёт PCA, экспортируйте сравнение в JSON.

**Иерархическая кластеризация** строит дендрограмму методом Уорда по
стандартизированным показателям. Задайте число кластеров, чтобы увидеть
состав каждого кластера в таблице. В расчёт входят от 3 до 2000 полных проб.
Для больших выборок дендрограмма сворачивает ветви, а таблица и JSON содержат
все допущенные пробы. Номера кластеров обозначают результат вычисления.

**Кластеризация K-средних** использует те же стандартизированные показатели.
Можно задать от 2 до 20 кластеров, меньше числа полных проб. График показывает
центры кластеров в единицах стандартного отклонения. JSON сохраняет состав,
центры, начальное число генератора случайных чисел и сумму квадратов расстояний
проб до центров их кластеров.

**Кластеризация DBSCAN** использует радиус в стандартизированных единицах
и минимальное число проб в окрестности, включая саму пробу. Таблица разделяет
ядро, границу и шум. Пропуски и другие причины исключения из расчёта сохраняются
отдельно от шума. Параметры и принадлежность проб входят в экспорт JSON.

Если выбранные показатели представляют части одного состава в одинаковых
единицах и на общей основе, после сравнения включите **Части одного состава
(CLR)**. PCA и кластеризация будут использовать логарифмы долей относительно
их геометрического среднего. Пробы с нулевыми, отрицательными или недопущенными
значениями исключаются целиком с указанием причин в JSON. После CLR расстояния
рассчитываются без дополнительной стандартизации отдельных частей.

Каждый успешный запуск PCA или кластеризации сохраняется в проекте.
В **Архиве запусков моделей** можно открыть сохранённый результат, проверить
совпадение его входов с текущим проектом и воспроизвести расчёт по сохранённому
снимку. Отдельный экспорт JSON включает результат, входы и версии библиотек.
Команда **Импорт запуска JSON** проверяет воспроизводимость расчёта перед
добавлением в архив другого проекта. Запуск открывается по собственному снимку,
поэтому для просмотра исходные таблицы проекта не нужны. Повторный импорт того же
запуска не создаёт копию.
Паспорт выбранного запуска в архиве показывает метод, версию расчёта, входные
показатели, настройки подготовки, параметры метода и ограничения применимости.

Для попарного сопоставления выберите по одной пробе в A и B и полный набор
пиков nC24–nC34 одной фракции и основы измерения. После сравнения откройте
**Сопоставить профили н-алканов**. Перекрытие рассчитывается как сумма меньших
из двух нормированных долей для каждого пика. Для разных состояний материала
используйте явное подтверждение в параметрах сравнения. Экспертное заключение
сохраняется отдельно от численного результата и привязывается к текущим входам.
Оба результата доступны в экспорте сравнения в JSON.
В том же сравнении можно отметить дополнительные числовые показатели,
например Pr/Ph или стереоотношения. Они появятся рядом с графиком на вкладке
**Дополнительные показатели**. Разность B − A рассчитывается для каждой пары
допущенных значений в единицах показателя. Таблица входит в JSON и привязывается
к тем же входам, что и экспертное заключение.
В заключении можно отдельно указать, отмечены ли признаки биодеградации в A и B
или данных для оценки недостаточно. Запишите обоснование в тексте заключения.
Результаты расчёта и экспертные отметки хранятся раздельно в JSON.
**Архив экспертных заключений** позволяет прочитать и экспортировать ранее
сохранённые оценки после изменения проекта. Архив показывает, совпадают ли
входы с текущими данными. Новые записи включают снимок использованных измерений.

**Линейный прогноз A → B** проверяет прогноз числового показателя на другой
группе скважин. В сравнении выберите целевой показатель и предикторы, укажите
обучающую группу A и проверочную группу B. У каждой пробы должна быть одна
однозначная скважина. Группы не могут содержать одну и ту же скважину.
Стандартизация предикторов и коэффициенты линейной модели оцениваются только
по полным пробам A. Для B нужны хотя бы две пробы с измеренной целью.
Вкладка проверки показывает ошибки и отмечает предикторы вне диапазона A.
Запуск сохраняется в архиве моделей и воспроизводится из снимка входов.
Флажок **Перекрёстная проверка по скважинам внутри A** по очереди исключает
из обучения каждую из 2–50 скважин A. Масштабирование и модель оцениваются
заново в каждом блоке. Вкладка **Ошибки по скважинам A** показывает ошибки
отдельных скважин. Проверка на B остаётся самостоятельной.
Для сравнения используется базовый прогноз: среднее цели по обучающим пробам.
В каждом блоке проверки по скважинам это среднее рассчитывается заново.
Ошибки модели и базового прогноза рассчитываются по одним проверочным пробам.
На вкладке **Ошибки по скважинам B** показаны RMSE и MAE модели и базового
прогноза по каждой проверочной скважине. Итог с равным весом скважин сначала
усредняет MSE и MAE по скважинам, затем извлекает корень из среднего MSE.
Чтобы получить прогноз для других проб, выделите их в списке проб и выберите
линейную модель в архиве. Команда **Применить модель к выбранным пробам**
использует сохранённые коэффициенты. Наличие измеренной цели не требуется.
Таблица показывает причины исключения и выход за диапазон обучения. Прогнозы
экспортируются отдельно в JSON и не записываются как измеренные значения.

Паспорт экспортируется в JSON, сравнение — в JSON или CSV. JSON сравнения содержит
входные значения, происхождение и причины исключений. Изменение исходных данных
блокирует экспорт старого сравнения до пересчёта.

При аудите 25.10.2026 проверены все 12 профилей на локальной БД. Для Sofer
получены 701 сопоставимая пара из 815 записей группы Isotopes;
воспроизведены 701 исходное CV (максимальная абсолютная разность 3.6e-15).
Для исходной популяции VR доступны 196 средних из 2746 записей;
оставшиеся строки не подменяются modal/user популяциями.

Физические свойства, PVT, цветовые индексы и прочие группы доступны в каталоге
заполненности, но не получают выдуманных автоматических калибровок.
`ND`, `<`, `>`, интерполяции, неизвестные единицы, смешанные основы,
отсутствующие компоненты SARA и неподтверждённые условия не заменяются
произвольными числами. Научные ограничения и источники — в
[SCIENTIFIC_METHODS.md](SCIENTIFIC_METHODS.md).

Подгонка кривых доступна через **Обработка → Подгонка кривых…**: OLS/WLS и
ODR/TLS, стандартные и пользовательские модели, метрики, доверительные и
предсказательные полосы. Поддерживаются робастные функции Huber/Soft L1,
границы параметров и сравнение моделей через K-fold кросс-валидацию.
Для робастных и ограниченных подгонок доступны bootstrap-полосы с воспроизводимым
Seed, прогрессом, отменой и диагностикой неудачных повторов.
Есть групповая и временная CV, Q–Q и диагностика остатков с переходом к пробе,
защищённые колонки прогноза/полос, фиксация и связи коэффициентов, поиск из нескольких
начальных приближений, сохранённые кривые и самостоятельный HTML-отчёт.
Формулы, ограничения и Python API описаны в
[docs/CURVE_FITTING.md](docs/CURVE_FITTING.md).
