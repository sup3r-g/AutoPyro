# Подгонка кривых

Открытие: **Обработка → Подгонка кривых…**. Выберите область анализа, числовые
колонки X/Y, модель и метод, затем нажмите «Рассчитать». Расчёт выполняется в фоне
по отдельному снимку нужных колонок. Изменение данных, области или параметров
сбрасывает результат; пересчёт запускается явно. Исходные измерения не меняются.

## Модели и методы

| Модель | Формула | Параметры |
| --- | --- | --- |
| Линейная | `a*x + b` | a, b |
| Полиномиальная, степень 1–10 | `c0 + c1*x + …` | c0, c1, … |
| Экспоненциальная | `a*exp(b*x) + c` | a, b, c |
| Степенная | `a*x**b`, X > 0 | a, b |
| Логарифмическая | `a*log(x) + b`, X > 0 | a, b |
| Константа | `c` | c |

**OLS** минимизирует сумму квадратов вертикальных остатков. При выборе колонки
σY получается WLS: минимизируется `Σ((f(x)-y)/σY)²`.

**ODR** одновременно оценивает параметры и исправленные координаты X:
`Σ((f(x_corrected)-y)/σY)² + Σ((x_corrected-x)/σX)²`.
Без колонок погрешностей используются единицы; это TLS в единицах исходных осей.
Изменение масштаба одной оси без соответствующего изменения σ меняет задачу TLS.
σ — стандартное отклонение, не дисперсия; значения должны быть положительными.

Все методы используют SciPy/NumPy. Линейные по параметрам модели OLS решаются
через масштабированный `lstsq`. Нелинейные модели используют `least_squares`;
для ODR строится разреженный блочный якобиан, с памятью O(N × P), где P — число
параметров. Устаревший `scipy.odr` не используется. Как и другие локальные методы,
нелинейная оптимизация зависит от начальной точки и не гарантирует глобальный минимум.

## Пользовательские модели

Введите формулу, имена параметров и начальные значения, например:

```text
Формула: a*exp(-b*x) + c
Параметры: a, b, c
Начальные значения: 10, 0.1, 1
```

Доступны `x`, `pi`, `e`, арифметические операции `+ - * / **` и функции
`exp`, `log`, `log10`, `sqrt`, `sin`, `cos`, `tan`, `abs`, `tanh`.
Каждый объявленный параметр должен использоваться. Формула разбирается через AST
и вычисляется векторно без `eval`/`exec`. Произвольные вызовы Python запрещены.
Для сохранения нескольких именованных формул используйте кнопку сохранения и
список «Мои модели». Библиотека хранится внутри проекта. Десятичный разделитель
в формулах и начальных значениях — точка.

## Данные, метрики и неопределённость

Пропуски, нечисловые значения, NaN/Inf, ND и цензурированные значения `<`/`>`
исключаются попарно по всем выбранным колонкам. Учитываются актуальные исключения
QC для статистики. Интерполированные колонки не предлагаются. Отрицательные
и нулевые σ вызывают ошибку. Недопустимые для модели X не удаляются молча.
Для оценки дисперсии требуется N > P. Неидентифицируемые модели отклоняются.

Все метрики относятся к **вертикальным остаткам исходных точек**, в исходной
шкале Y, без весов: N, MAE, MSE, RMSE, MedAE, MaxAE, Bias (`mean(y-fitted)`),
SSE, R² и R²_adj. Целевая функция оптимизатора выводится отдельно.

`R² = 1 − SSE/SST`; при постоянном Y результат не определён.
`R²_adj = 1 − (1 − R²) × (N−1)/(N−P)`. Последняя формула использует соглашение
о модели с константой; для нелинейных моделей и моделей без свободной константы
это описательный показатель, а не самостоятельный критерий выбора модели.
MAPE намеренно не вычисляется: при нулевых Y она не определена.

Ковариация OLS получается из якобиана через SVD. Для ODR используется дополнение
Шура по поправкам X: строки якобиана параметров делятся на
`sqrt(σY² + (df/dx × σX)²)` в исправленных координатах. Это локальная аппроксимация
Гаусса–Ньютона. Обычно ковариация масштабируется на `objective/(N−P)`.
Флажок абсолютных погрешностей отключает масштабирование; он требует σY,
а для ODR — также σX. Ошибки коэффициентов равны корням диагонали ковариации.
Эти оценки доступны для квадратичной функции потерь без активных границ.

Полосы — **точечные**, с квантилем Стьюдента и N−P степенями свободы:

- Confidence: `f(x) ± t * sqrt(J(x) Cov J(x)ᵀ)` — неопределённость среднего.
- Prediction: `f(x) ± t * sqrt(J(x) Cov J(x)ᵀ + sY²)` — новое наблюдение,
  где по умолчанию `sY² = SSE/(N−P)` по вертикальным остаткам.

Для линейного OLS с независимыми нормальными ошибками постоянной дисперсии это
стандартные формулы. Для нелинейной модели, WLS и ODR это приближение.
Prediction условна по **точному будущему X**; погрешность будущего X в неё не
включена. Для неодинаковых будущих ошибок Y Python API позволяет явно передать
`prediction_sigma`. GUI использует общую дисперсию вертикальных остатков.
Полосы не являются одновременными доверительными областями для всей кривой.

На графике показываются кривая, обе полосы и вертикальные остатки. Панель
Matplotlib позволяет сохранить изображение. JSON содержит настройки, исходные
пары и UUID строк, исправленные X, коэффициенты, ковариацию, метрики и полосы.
Неопределённые метрики записываются как `null`. Запись атомарная.

## Робастная регрессия

В поле «Функция потерь» доступны обычная квадратичная функция, **Huber** и
**Soft L1**. Последние уменьшают влияние больших остатков, сохраняя все точки.
«Робастный масштаб» (`f_scale`) задаёт порог перехода: он применяется к остаткам,
делённым на σ. Без заданной σ масштаб выражается в единицах соответствующей оси.
Выбирайте масштаб исходя из ожидаемой ошибки измерения, а не размера выбросов.
При ODR функция потерь применяется отдельно к поправкам X/σX и остаткам Y/σY;
это робастная регрессия с ошибками обеих координат, не вращательно-инвариантная
робастная TLS. Начальные значения и локальные минимумы по-прежнему имеют значение.

Метрики остаются обычными невзвешенными вертикальными ошибками по всем точкам.
`objective` для робастного расчёта — `2 * cost` SciPy: сумма преобразованных
потерь, а не SSE. Сравнивать objective разных функций потерь как качество модели
нельзя; для сравнения используйте одинаковую схему CV и отложенные ошибки.

## Ограничения параметров

Нижние и верхние границы задаются через запятую в порядке параметров формулы.
Например, для `a*x+b`: нижние `0, -inf`, верхние `2, inf`.
Пустое поле означает отсутствие границ; одно число применяется ко всем параметрам.
В Python API это `bounds=([0, -np.inf], [2, np.inf])`.
Нижняя граница должна быть строго меньше верхней. Фиксация параметра одинаковыми
границами не поддерживается: исключите фиксированный параметр из формулы.
Явные начальные значения вне границ отклоняются; автоматические помещаются внутрь.
При смене модели/степени GUI очищает позиционные начальные значения и границы.
Библиотека пользовательских моделей сохраняет также границы.

Ограничения применяются к коэффициентам OLS и ODR; область X для положительных
стандартных моделей также сохраняется в ODR. При достижении границы имя параметра
появляется в отчёте и `active_bounds` экспорта.

Для робастного расчёта и при активных границах **аналитические** стандартные ошибки
и полосы не вычисляются: обычная ковариация OLS не описывает их неопределённость.
В режиме «Авто» полосы рассчитываются через bootstrap, описанный ниже.
В Python `standard_errors` остаются `None`, `FitResult.bands()` по-прежнему
предназначен для аналитических полос; для bootstrap используется отдельная функция.
Для ограниченного решения внутри границ остаётся прежняя локальная аппроксимация;
она не учитывает усечение распределения близкой границей.

## Bootstrap-полосы

«Метод полос» предлагает три режима:

- **Авто**: аналитические полосы, если ковариация доступна; иначе bootstrap.
- **Bootstrap (percentile)**: bootstrap независимо от доступности ковариации.
- **Bootstrap с одновременной полосой** калибрует доверительную полосу по всей
  расчётной сетке из 400 точек.
- **Только аналитические**: прежнее поведение, без bootstrap-пересчётов.

По умолчанию используется 500 повторов и Seed 0. Настройки сохраняются в проекте.
Расчёт идёт в фоне с прогрессом и отменой между подгонками. Изменение данных или
параметров отменяет устаревший bootstrap. Частичные результаты отменённого расчёта
не публикуются. Переключение Confidence/Prediction и уровня доверия использует
сохранённые распределения, без повторных подгонок.

По умолчанию в каждом повторе **совместно пересэмплируются строки X/Y/σX/σY с возвращением**.
Сохраняются модель, функция потерь, робастный масштаб, абсолютные погрешности,
границы и лимит вычислений. Подгонка стартует от исходной оценки; близкие к границе
старты немного сдвигаются внутрь, чтобы оптимизатор мог выйти с нулевой границы,
если оптимум пересэмплированных данных оказался внутри. При пересэмплировании
строк каждый повтор содержит исходное число строк.

Confidence — точечные квантили распределения предсказанных кривых на фиксированной
сетке. Для робастной регрессии это неопределённость **кривой устойчивого положения**,
которая не обязана совпадать с условным средним Y при асимметричном шуме.
Prediction — квантили распределения этих же кривых с добавленным независимо
пересэмплированным шумом Y из исходных вертикальных остатков. Остатки центрируются
по среднему для квадратичной функции потерь, по медиане для робастной.
В алгоритме версии 2 один шумовой остаток выбирается на повтор и используется
по всей сетке. Поэтому одинаковые X получают одинаковые границы, независимо от
порядка, плотности сетки и разбиения выходных строк на блоки. Предсказательная
полоса описывает распределение отдельного наблюдения при заданном X.
Выбросы в хвостах Prediction **не отбрасываются**. Интервалы могут быть асимметричны
относительно исходной кривой. Их границы не принуждаются к симметрии или взаимной
вложенности из-за конечной точности Monte Carlo.

При «Будущая σY» = 0 используется смесь сырых остатков: предполагается одинаковое
распределение ошибок Y для всех X. Для неодинаковых погрешностей задайте будущую σY:
исходные остатки делятся на обучающие σY, центрируются и затем умножаются на
будущую σY. Если обучающая σY не задана, для стандартизации используется выборочное
SD остатков; при нулевом разбросе такое масштабирование невозможно.
GUI задаёт одну будущую σY; API также принимает массив по сетке. Независимые
генераторы случайных чисел для пересэмплирования и шума сохраняют Confidence
распределение неизменным при изменении настроек Prediction.

Неудачные подгонки учитываются и **не заменяются дополнительными попытками**.
Требуется не меньше `max(20, ceil(0.9 * B))` успешных повторов; API позволяет задать
долю в диапазоне 0.5–1. Если порог недостижим, bootstrap завершается с ошибкой,
готовая исходная подгонка остаётся доступной. Исключение неудачных повторов само
может смещать результат — это отмечается в предупреждениях. Выводятся число
попыток/успехов/ошибок и до трёх примеров ошибок. При малом числе повторов в хвостах
для выбранного уровня доверия выводится рекомендация увеличить B.

По умолчанию рассчитываются **приближённые точечные percentile-интервалы**.
На активных границах они могут вырождаться и не обеспечивать
номинальное покрытие; bootstrap не устраняет ограничения выбранного оценивателя.
По умолчанию пересэмплирование предполагает независимые строки. Для повторов
одной пробы выберите колонку идентификаторов в поле «Группы bootstrap» и метод
«Bootstrap (percentile)». В режиме «Авто» колонка используется, если расчёт дошёл
до bootstrap. Для каждой использованной точки нужна непустая группа. В каждом
повторе из G наблюдаемых групп выбираются G групп с возвращением, целиком с их
точками и погрешностями. Размер выборки может меняться между повторами. Группы
предполагаются независимыми. При малом числе групп интервалы могут быть неточными.
В Python передайте `bootstrap_bands(result, x_grid, groups=labels)`, где метки
идут в порядке `result.x`.
Экспорт записывает `cluster_percentile`, число групп и выбранную колонку.

Для одной упорядоченной серии с различными, примерно равноотстоящими X
оставьте «Независимые строки» в поле групп, выберите «Bootstrap (percentile)»
и задайте «Длину блока bootstrap» от 2 до N−1. Соседство определяется по
возрастанию X. Каждый повтор выбирает с возвращением перекрывающиеся блоки
заданной длины и обрезает последний блок до N строк. Длина задаётся в точках.
При выборе колонки групп поле длины отключается. В API используйте
`bootstrap_bands(result, x_grid, block_length=8)`. Экспорт сохраняет метод
`moving_block_percentile` и длину блока. Предсказательная полоса по-прежнему
использует эмпирический остаток для одного будущего наблюдения.

Вкладка «Автокорреляция остатков» показывает до 40 лагов для текущей подгонки.
Остатки упорядочиваются по X. Для каждого лага сумма произведений центрированных
пар делится на сумму квадратов всех центрированных остатков. Устойчивая связь
на соседних лагах помогает оценить, на каком масштабе зависимость стоит учитывать
при выборе длины блока. График носит диагностический характер. Лаг измеряется в
точках, поэтому для интерпретации в единицах X нужен примерно равный шаг.

Prediction относится к одному будущему наблюдению и использует общую смесь
остатков. Она условна по точному будущему X. Для ODR
вертикальные остатки не разделяются на истинный шум Y и вклад ошибки X.
Малые выборки, обучающие остатки и неверная форма модели также могут давать
слишком узкие или смещённые полосы. Полосы не являются гарантией покрытия всей кривой.

Одновременный режим (`simultaneous=True` в Python) для каждого повтора берёт
максимальное абсолютное отклонение от исходной кривой по всей сетке. Квантиль
этих максимумов задаёт постоянную полуширину доверительной полосы в единицах Y.
Покрытие приближённое и относится к точкам калибровочной сетки. В выходных
колонках та же полуширина применяется внутри диапазона сетки. За его пределами
границы доверительной полосы остаются пустыми. Предсказательная полоса остаётся
точечной. Экспорт сохраняет метод `grid_max_deviation` и сетку калибровки.

Для обычного bootstrap память O(N + B × (P+M)), где M — размер сетки,
P — число параметров. Для группового вместо N учитывается также размер
текущего повтора, который зависит от размеров выбранных групп.
Одновременно хранится только одна пересэмплированная выборка; матрицы N × B нет.
Экспорт JSON включает метод, Seed, число повторов, диагностику, bootstrap-коэффициенты,
сетку и обе полосы. Ковариация и аналитические стандартные ошибки не подменяются
bootstrap-оценками. Валидация CV не запускает bootstrap для каждого блока.

## Сравнение моделей через кросс-валидацию

На вкладке параметров «Кросс-валидация» добавьте текущую модель в список,
настройте следующую и добавьте её. Каждая запись хранит отдельную формулу,
начальные значения и границы. Метод, функция потерь, масштаб и колонки погрешностей
общие для сравнения и берутся с вкладки «Параметры». Выберите K (2–20), Seed и
перемешивание, затем нажмите «Сравнить модели». Расчёт выполняется в фоне.
Список и настройки сохраняются в проекте; результат экспортируется отдельным JSON.

Все модели проверяются на одной общей выборке полных пар. При обычном K-fold
используются одинаковые K блоков.
Каждая модель обучается заново на K−1 блоках, предсказывает только оставшийся блок
и никогда не получает его Y при оценке коэффициентов или автоматических начальных
значений. Погрешности также выбираются только для обучающих строк.
Число обучающих точек в каждом блоке должно превышать число параметров всех моделей.

Доступны независимые строки, группы, «прошлое → будущее» и «По одной точке (LOO)».
LOO предназначен для независимых точек и линейных по параметрам моделей при
обычном или взвешенном МНК без границ. Число блоков равно числу точек. Для
каждой модели достаточно одной подгонки и расчёта рычагов. Прогнозы совпадают
с исключением по одной точке при полноранговых обучающих выборках. Несовместимые
модели и модели с неопределёнными прогнозами исключаются из рейтинга. В этом
режиме дополнительно выводится PRESS. JSON хранит номера блоков и прогнозы в
порядке исходных строк, а `fold_metrics` остаётся пустым, чтобы не дублировать
отдельную запись метрик для каждой строки. В API задайте `strategy="loo"`.

Для групп выберите колонку скважины/площади/серии: группа целиком попадает в один
проверочный блок. Группы распределяются с учётом числа строк, без разделения группы;
при одном Seed результат воспроизводим. Пустые группы отклоняются.
Для времени выберите числовую временную координату или колонку дат. Одинаковые
моменты времени не разделяются между обучением и проверкой. Первый из K+1 блоков
используется только для начального обучения, затем обучающая область расширяется.
«Разрыв» исключает указанное число различных моментов между обучением и проверкой.
Перемешивание в этом режиме выключено. Начальные обучающие строки имеют fold_id=-1
и прогноз `null` в JSON; они **не входят** в OOF-метрики. `N_evaluated` показывает
фактическое число проверенных строк. Колонка времени/группы берётся из того же снимка,
что X/Y. Число групп должно быть не меньше K, временных моментов — не меньше K+1.

Рейтинг строится по **общему RMSE всех out-of-fold (OOF) прогнозов** в исходном
порядке строк, а не среднему RMSE блоков. Также показываются OOF MAE, MedAE, R²
и выборочное стандартное отклонение RMSE блоков (оно не является доверительным
интервалом). CV измеряет вертикальный прогноз Y по исходному X, включая ODR.
Ошибки обучения/прогноза выводятся с номером блока. Частично успешная модель
не получает общих метрик и не включается в рейтинг; остальные модели продолжают
проверяться. Экспорт содержит номера блоков, UUID строк, OOF прогнозы, метрики и
ошибки, а также точные конфигурации моделей для повторения расчёта.

Обычный K-fold предполагает независимые наблюдения. Перемешивание нельзя использовать
для оценки будущего по временному ряду или переноса между зависимыми группами
(например, пробами одной скважины). Отключение перемешивания даёт последовательные
блоки, но обучение всё ещё использует строки с обеих сторон и не становится
проверкой прогноза будущего. Выбор лучшей модели и оценка её окончательного качества
по одному CV могут быть оптимистичны; для последней нужен отдельный тестовый набор.

Для независимого теста добавьте текстовую колонку и укажите `Train` или
`Обучение` для обучающих строк и `Test` или `Тест` для тестовых. Пустая роль
исключает строку. Выберите колонку в поле «Колонка ролей выборки» на вкладке
«Кросс-валидация». При зависимых наблюдениях назначайте целые группы одной
выборке. Для проверки прогноза будущего отведите будущие наблюдения в тест.
Кросс-валидация выбирает победителя только на обучающих строках. Затем победитель
один раз обучается на всех обучающих данных. Тестовые σ для оценки не нужны.
RMSE, MAE и R² теста показаны отдельно. При ошибке тестирования рейтинг CV
сохраняется. В JSON раздел `holdout` содержит UUID, X/Y, прогнозы, коэффициенты
победителя и метрики. В Python передайте обучающие X/Y обычными аргументами и
задайте `holdout=(test_x, test_y)`.

Поля «Тестовая модель A» и «Тестовая модель B» включают отдельный попарный
тест. Обе модели подгоняются на той же обучающей выборке. Вкладка «Попарный
тест» показывает прогнозы и абсолютные ошибки по UUID, а также разность
`|ошибка B| − |ошибка A|`. Положительная разность означает меньшую ошибку A.
Столбец разности можно сортировать. Двойной щелчок открывает пробу в таблице.
Сводка включает MAE обеих моделей, среднюю разность и число проб, где точнее
каждая модель. Все эти величины считаются по общим пригодным прогнозам.
Если прогноз выходит за область определения модели, соответствующая ячейка
остаётся пустой. Рейтинг CV сохраняется. JSON содержит попарные данные в
`holdout.pair`, а HTML содержит сводку. В API передайте
`holdout_pair=(имя_A, имя_B)` вместе с `holdout`.

При попарном тесте уровень доверия, число повторов, Seed, группы и длина
блока берутся с вкладки «Параметры» при запуске сравнения. При выбранной
колонке групп пересэмплируются целые группы. При заданной длине блока
используются соседние общие пробы по X. Без групп и блоков пересэмплируются
отдельные общие пробы. В каждом повторе вычисляется среднее парных разностей
абсолютных ошибок. Percentile-интервал описывает неопределённость тестовой
оценки при фиксированных моделях. Если он включает ноль, направление различия
отмечается как неопределённое. Режим и границы сохраняются в JSON и HTML.
При недостатке проб или групп интервал недоступен, а таблица ошибок сохраняется.
В Python передайте `pair_bootstrap={}` для настроек по умолчанию или задайте
параметры `confidence`, `resamples`, `seed`, `groups` либо `block_length`.

Поле «Практический порог ΔMAE» задаёт допустимое отклонение в единицах Y.
Задайте его до просмотра тестовых результатов. При положительном пороге δ
вкладка отдельно показывает положение интервала относительно диапазона
`[−δ, +δ]`. Если весь интервал лежит внутри диапазона, разница укладывается
в допуск. Если он целиком выше `+δ` или ниже `−δ`, преимущество A или B
соответственно превышает порог. При остальных положениях вывод относительно
порога неопределён. Нулевое значение отключает этот вывод. Настройка сохраняется
в проекте, порог и результат — в JSON и HTML. В API используйте
`pair_bootstrap={"margin": δ}`.

«Вложенная CV» оценивает процедуру выбора модели на независимых строках.
Задайте число внешних блоков K и число внутренних блоков. Для каждого внешнего
блока внутренний CV выбирает модель по RMSE только на оставшихся строках.
Победитель обучается на всей внешней обучающей части и прогнозирует свой
внешний блок. Выбор модели может различаться между блоками. Поле ролей
выборки должно быть установлено в «Без тестовой выборки».
В каждом внешнем блоке выполняется до `K_внутр × число моделей + 1` подгонок.

Таблица показывает победителя, внутренний RMSE, внешние RMSE и MAE по блокам.
Общая оценка объединяет все внешние прогнозы. При сбое блока общая оценка
недоступна, пригодные внешние прогнозы остаются в диагностике и JSON.
В JSON также сохраняются коэффициенты победителей и Seed внутренних разбиений.
В HTML сохраняется сводка по блокам. В API задайте
`strategy="nested", folds=5, inner_folds=4`.

«Вложенная CV по группам» использует выбранную колонку группы на обоих уровнях.
Каждая группа целиком относится к обучению или проверке своего блока.
Внутренняя CV видит только группы внешней обучающей выборки. Таблица и отчёт
показывают число групп в обучении и проверке. Если групп для внутреннего
разбиения недостаточно, соответствующий внешний блок помечается ошибкой.
В API используйте `strategy="nested_group", groups=labels`.

«Вложенная временная CV» использует порядок «прошлое → будущее» на обоих
уровнях. Выберите колонку времени и разрыв в числе различных моментов.
Одинаковые моменты не делятся между блоками. Разрыв применяется отдельно
в каждом внешнем и внутреннем разбиении. Для первых внешних блоков нужна
достаточная история для внутреннего обучения и проверки. Начальные строки
без внешнего прогноза имеют `fold_id=-1` и `null` в JSON и не входят в сводку.
Таблица показывает число моментов в обучении и проверке и число строк в
разрыве. В API используйте `strategy="nested_time", times=values, gap=2`.

После сравнения выделите успешную модель в таблице и нажмите «Подогнать
выбранную модель» на вкладке настроек CV. Без выделения используется первая
модель рейтинга. После вложенной CV действие заново запускает её внутреннюю
стратегию на всей исходной выборке, выбирает победителя и подгоняет его.
Число блоков, разрыв и колонка группы или времени берутся из сравнения.

Итоговый расчёт использует ровно те обучающие UUID, которые вошли в сравнение.
Строки независимого теста могут получить прогноз при создании выходных колонок.
В параметры итоговой кривой переносится определение выбранной модели. Источник
выбора и обучающие UUID сохраняются при экспорте, сохранении результата и
создании колонок. Итоговая подгонка заменяет текущий результат сравнения.
Обычное действие «Рассчитать» использует активную область анализа.

В архиве результатов действие «Пересчитать по сохранённым строкам» запускает
подгонку с сохранёнными настройками, уровнем доверия и обучающими UUID.
Используются текущие значения по этим UUID в сохранённом порядке. Если строки
удалены, исключены из анализа или больше не помечены как обучающие в исходной
колонке ролей, пересчёт останавливается. Устаревший архив остаётся доступным
для просмотра. Новый результат указывает, какой архив использован.
Активная область анализа по-прежнему задаёт строки для выходных колонок.

После пересчёта вкладка «Сравнение с архивом» показывает изменившиеся X, Y,
σX и σY по UUID обучающих строк, старые и новые коэффициенты и разницу
прогнозов `текущий − архивный`. Двойной щелчок по изменению открывает исходную
пробу. Разница прогнозов вычисляется в точках архивной сетки, попадающих в
текущий обучающий диапазон X. Сводка показывает X с максимальной абсолютной
разницей. JSON итоговой подгонки включает раздел `archive_comparison`.

## Диагностика и применение результата

Вкладка «Диагностика» строится только при открытии, без нового расчёта модели.
Для обычной подгонки показывает остатки против прогноза и нормальный Q–Q график;
после CV — фактические значения против OOF-прогноза и отложенные остатки. Выбор
строки модели в сравнении переключает диагностируемый OOF-результат.
Вкладка «Влияние точек» доступна для моделей, линейных по параметрам, при
обычном или взвешенном МНК без границ. Рычаг показывает, насколько прогноз
в точке зависит от её собственного Y. Расстояние Кука оценивает суммарное
изменение подгонки при удалении этой точки. При WLS обе величины рассчитываются
с учётом σY. Строки отсортированы по убыванию расстояния Кука. Двойной щелчок
выбирает исходную пробу. При нулевом остаточном разбросе или вырождении модели
после удаления точки расстояние Кука не определено. В Python используйте
`result.influence()` для получения обоих массивов в порядке исходных точек.

Там же показаны прогноз и ошибка leave-one-out (LOO) для каждой точки. Ошибка
равна обычному остатку, делённому на `1 − h`, где `h` — рычаг точки. Формула
даёт результат подгонки без этой точки без повторной оптимизации. Сводка
содержит PRESS (сумму квадратов ошибок), RMSE, MAE и прогнозный R². Как и в
сравнении моделей, метрики считаются без весов по исходным значениям Y, даже
если для подгонки выбран WLS. Если удаление точки приводит к вырождению
модели, прогноз для неё пуст и сводка показывает число доступных прогнозов.
В Python `result.leave_one_out()` возвращает прогнозы в исходном порядке.

Таблица остатков отсортирована по абсолютной ошибке. Метка «Проверить» означает
отклонение более 3.5 робастных SD от медианы (`1.4826*MAD`, при MAD=0 — обычное SD).
Это подсказка, а не автоматическое исключение или проверка статистической значимости.
Щелчок по точке или двойной щелчок по строке выбирает пробу в исходной таблице по
UUID; скрытая фильтром строка не заставляет модуль менять фильтры.

Вкладка параметров «Результаты модели» позволяет создать защищённые числовые
колонки прогноза, остатка и четырёх границ полос. Применяется готовая модель к
текущей области анализа: прогноз возможен также для строк с X и отсутствующим Y;
остаток в них пустой. Если полосы недоступны, создаются только прогноз и остаток.
Новая подгонка не запускается. Для bootstrap пересчитывается только значение
сохранённых коэффициентов на новых X и распределение Prediction, порциями по
512 строк. Экстраполяция возможна и автоматически не валидируется.
Все колонки добавляются одной отменяемой операцией, сохраняют единицу Y, настройки,
коэффициенты, обучающие пары/UUID и отпечаток источников в `curve_fit_runs`.
Результаты не становятся исходными измерениями. Изменение использованных данных,
единиц или состава исходных строк меняет отпечаток источника. Связанные результаты
получают отметку об устаревании в заголовке колонки. Правка примечания сохраняет
актуальность, пока примечание не входит в настройки подгонки, например как группировка.
Удаление исходной колонки также делает результат устаревшим.

## Коэффициенты, связи и начальные приближения

«Параметры bootstrap» показывает медиану, асимметричный percentile-интервал,
Bootstrap SD, гистограмму выбранного коэффициента и долю попаданий к границе
(`isclose`, rtol=1e-5, atol=1e-8). Это отдельные bootstrap-оценки; аналитическая
ковариация не подменяется ими. Интервалы и гистограммы обновляются по кешированным
повторам. Для связанного коэффициента распределение выводится из свободных
коэффициентов; фиксированный имеет нулевой разброс. У фиксированных/связанных
коэффициентов доля у границы не рассчитывается.

Поле «Фиксация и связи параметров» принимает выражения через `;`, например
`b=0` для прямой через начало координат или `c0=0; c2=2*c1` для полинома.
Зависимости раскрываются безопасной заменой AST, без `eval`. Циклы, неизвестные
имена и зависимость коэффициента от X запрещены. Начальные значения и границы
задаются **только для свободных параметров**, в порядке, показанном в интерфейсе.
Число степеней свободы также учитывает только свободные параметры.
Должен остаться хотя бы один свободный коэффициент. Связи действуют внутри одной
модели. Для общих коэффициентов между сериями предусмотрен отдельный режим.

## Совместная подгонка серий

На вкладке «Параметры» выберите X, Y, модель и при необходимости σY. Откройте
«Совместная подгонка», выберите колонку с названиями серий и отметьте общие
коэффициенты. Остальные будут оценены отдельно для каждой серии. Например,
для модели `a*x + b` отметьте `a`, чтобы оценить один наклон и своё смещение
для каждой скважины. Нужны хотя бы две серии, один общий и один отдельный
коэффициент. Режим поддерживает стандартные и пользовательские модели при
OLS/WLS с квадратичной функцией потерь, Huber или Soft L1. Робастный масштаб
применяется к вертикальным остаткам, делённым на σY, если она задана.
Для пользовательской формулы укажите
начальные значения, как при обычной подгонке. При выборе ODR/TLS или связей
коэффициентов кнопка запуска совместной подгонки отключается с пояснением.
Несколько начальных приближений и флажок абсолютных погрешностей относятся
к обычной подгонке.

Нижние и верхние границы с вкладки «Параметры» действуют на общие коэффициенты
и задают границы по умолчанию для отдельных. Нажмите «Изменить границы по сериям»,
выберите серию и отметьте «Переопределить» для нужного коэффициента. Пустая
ячейка в переопределённой паре снимает соответствующую границу. Снятие флажка
возвращает оба значения по умолчанию. Ранее сохранённые границы открываются
в таблице, а формат хранения в проекте сохраняется. Подгонка с ограничениями
и нелинейная подгонка используют
разреженный якобиан. Для нелинейной модели найденное решение зависит от
начальных значений.

Таблица результата показывает отдельные коэффициенты и ошибки по сериям.
Кнопка «Сравнить варианты совместной подгонки» проверяет текущий набор общих
коэффициентов и варианты с одним общим коэффициентом. Коэффициент с заданными
границами по сериям остаётся отдельным в сравниваемых вариантах. Разбиение
выполняется внутри каждой серии с фиксированным seed. Все варианты используют
одни блоки, а рейтинг строится по RMSE всех отложенных прогнозов. Число точек
в каждой серии должно быть не меньше числа блоков. Такой CV оценивает прогноз
для известных серий при независимых строках. Подгонка для новой серии требует
отдельного сценария с оценкой её коэффициентов.
Выбор строки переключает серию на графике. «Обзор серий» накладывает кривые
на общие оси и выделяет выбранную серию. «Остатки по серии» показывает
вертикальные остатки относительно прогноза Y и таблицу наблюдений. Щелчок
по точке или Enter на выбранной строке таблицы выделяет соответствующую
строку исходных данных. Оба графика создаются при первом
открытии и используют готовые коэффициенты и прогнозы.
На вкладке «Исключённые строки» видны все причины пропуска строк из выбранной
области: пропуски, ND, цензурированные или нечисловые значения, исключения QC,
пустые метки серий, неположительные σY и неположительные X для моделей,
которым требуется X > 0. Такие строки пропускаются до подгонки.
Двойной щелчок, Enter или кнопка «Показать выбранную пробу» открывает строку в
исходной таблице по UUID. Если строку скрывает фильтр, интерфейс сообщает об этом.
На графике можно выбрать серию. JSON сохраняет общие и отдельные коэффициенты,
UUID строк, принадлежность к сериям, прогнозы и фактические границы. Стрелки
`↓` и `↑` отмечают активную нижнюю и верхнюю границу соответственно.
На вкладке «Совместная подгонка» кнопка «Создать колонки прогноза и остатков»
добавляет в таблицу проекта две числовые колонки в единицах Y. Они содержат
результаты всех серий, включая те, которые сейчас скрыты на графике.
Строки, пропущенные при подгонке, остаются пустыми. Колонки хранят настройки
расчёта и доступны в обычных графиках. Значения представляют снимок расчёта.
Добавление обеих колонок отменяется одним действием.

Кнопка «Сохранить совместную подгонку для отчёта» добавляет снимок в проект.
В настройках отчёта можно выбрать любой сохранённый снимок. По умолчанию
выбирается последний. Раздел «Совместная подгонка» появляется в отчёте,
если он включён и выборка отчёта содержит все строки, использованные при подгонке.
Если строк не хватает, проверка перед выпуском указывает их число.
HTML, PDF и DOCX показывают формулу, метод, общие и отдельные коэффициенты,
метрики и диагностику bootstrap. JSON содержит тот же снимок в структурированном
виде. В отчёте есть отдельный график каждой серии с наблюдениями, кривой и
доступными доверительной и предсказательной полосами. Уровень доверия фиксируется
при сохранении снимка. Для каждого графика сохраняется до 2000 наблюдений.
При большом числе серий лимит на график уменьшается до общей цели в 20 000
наблюдений, с лимитом не ниже шести на серию.
Для больших серий точки упорядочиваются по X. Из каждого блока сохраняются
крайние X, Y и остатки, чтобы заметные отклонения оставались на графике.
Метрики рассчитаны по всем точкам,
а число показанных наблюдений указано в подписи. PNG строятся при сборке отчёта
без повторной подгонки и bootstrap. Для отражения изменений в данных заново
выполните подгонку и сохраните её для отчёта. Снимок и колонки совместной
подгонки проверяются по исходной выборке, включая пропущенные при расчёте
строки, колонки X, Y, σY, метки серий и действующие исключения QC.
Перестановка строк не влияет на актуальность. После изменения источников
значения сохраняются с предупреждением в таблице и отчёте. Для старых
результатов без отпечатка источника актуальность не подтверждается.

Архив и CV относятся к обычной подгонке. В Python используйте `fit_joint_curve(x, y, series, model,
shared=("a",), sy=sy)` из `autopyro.curves.joint_fitting`. Ядро устраняет
локальные коэффициенты по сериям перед общей подгонкой, поэтому память
растёт с числом строк и коэффициентов модели, без матрицы `N × число серий`.

Для совместных полос выберите bootstrap на вкладке «Параметры». В режиме «Авто»
bootstrap запускается при робастной функции потерь или активных границах.
В остальных случаях совместная подгонка в режиме «Авто» оставляет результат
без полос. Аналитических полос для совместной подгонки пока нет. Сводка,
JSON и отчёт показывают фактически применённый способ расчёта полос.
Каждый повтор пересэмплирует строки с возвращением **внутри каждой серии**,
сохраняет размеры серий и заново подгоняет все коэффициенты совместно. Для
предсказательной полосы шум берётся из центрированных остатков выбранной серии.
Это точечная полоса для одного будущего наблюдения. Одновременная доверительная
полоса калибруется по сетке выбранной серии. Пересэмплирование предполагает
независимые строки внутри серии. Группы и блоки применяются к обычной подгонке.

Смена уровня доверия или серии использует уже рассчитанные повторы. Полосы
для нового сочетания рассчитываются в фоне. Последние 32 сочетания хранятся
в кеше до изменения подгонки. JSON
сохраняет коэффициенты и шумовые реализации всех повторов, а также полосы
выбранной серии. При отмене или недостатке успешных повторов исходная подгонка
остаётся доступной. На кеш повторов выделяется до 256 МиБ. В Python используйте
`bootstrap_joint_fit(result, resamples=500)` и затем `bootstrap.bands(result, series, grid)`.

«Начальных приближений» (1–100, по умолчанию 1) и отдельный Seed задают multi-start.
Сначала используется введённое или автоматическое приближение. Затем для параметров
с двумя конечными границами используются равномерные старты внутри диапазона;
для остальных — нормальные возмущения текущего лучшего решения с масштабом
`1+abs(parameter)`, с приведением к допустимым границам. Выбирается наименьшая
целевая функция среди сошедшихся решений. Ошибки отдельных стартов сохраняются
в диагностике. Глобальный минимум не гарантируется.
После совместной нелинейной подгонки проверяется локальная идентифицируемость
свободных коэффициентов по нормированным производным модели. Если отдельные
коэффициенты одной серии или общие коэффициенты нельзя разделить по данным,
расчёт завершается предупреждением. Коэффициенты на активных границах остаются
отмеченными в результате и исключаются из проверки свободных направлений.
Повторы bootstrap с вырожденной подгонкой считаются неуспешными.

Для прямого неограниченного OLS выполняется один точный линейный solve независимо
от числа стартов. CV вычисляет старты отдельно по каждому обучающему набору.
Bootstrap сохраняет выбранное число стартов — стоимость при этом растёт примерно
как число повторов × число стартов.

## Сохранённые результаты и отчёт

«Сохранить результат…» сохраняет внутри проекта неизменяемый снимок чисел, исходных
пар, UUID, сетки, полос, настроек, коэффициентов и диагностики. Можно выбрать несколько
снимков и наложить кривые с полосами на один график без подгонки. Для наложения должны
совпадать показатели X/Y. Устаревшие снимки сохраняются и явно помечаются.
«Восстановить параметры результата» возвращает конфигурацию и область анализа;
пересчёт запускается явно. Удаление снимка не удаляет колонки и их протоколы.

«Экспорт отчёта HTML…» создаёт один самостоятельный HTML-файл: выбранные модели,
коэффициенты, метрики, графики, диагностика, bootstrap-интервалы, ограничения,
старты, сведения об источниках и их отпечатки. Рисунки встроены как SVG без
внешних ресурсов. Если есть текущий результат CV, в отчёт включаются его рейтинг,
ошибки, конфигурация разбиения и график OOF-прогноза. Экспорт выполняется в фоне
и не запускает оптимизацию. Русские/английские подписи и иконки используют общие
каталоги и тему приложения.

## Python API

```python
from autopyro.curve_fitting import fit_curve, standard_model, custom_model

result = fit_curve(x, y, standard_model("polynomial", degree=2))
mean, ci_low, ci_high, pi_low, pi_high = result.bands(x_grid, confidence=.95)

model = custom_model("a*exp(-b*x)+c", ("a", "b", "c"))
result = fit_curve(x, y, model, method="odr", initial=[10, .1, 1], sx=sx, sy=sy)

robust = fit_curve(x, y, loss="huber", f_scale=.5,
                   bounds=([0, -float("inf")], [10, float("inf")]))

from autopyro.model_comparison import FitCandidate, compare_models

comparison = compare_models(x, y, [
    FitCandidate("line", standard_model()),
    FitCandidate("quadratic", standard_model("polynomial", degree=2)),
], folds=5, seed=42)
best = comparison.ranking[0]  # если хотя бы одна модель прошла все блоки
print(best.name, best.metrics["RMSE"])

from autopyro.curve_bootstrap import bootstrap_bands

bootstrap = bootstrap_bands(robust, x_grid, resamples=500, seed=42)
mean, ci_low, ci_high, pi_low, pi_high = bootstrap.bands(confidence=.95)
# Новый уровень доверия — без повторной подгонки:
bands_99 = bootstrap.bands(confidence=.99)
print(bootstrap.diagnostics(confidence=.99))
```

Базовые определения SciPy:
[least_squares](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html),
[paired percentile bootstrap](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html),
[ковариация и absolute_sigma](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.curve_fit.html).

## Аудит численной устойчивости и интерфейса (2026-11-05)

Линейный solve центрирует признаки и отклик, нормирует столбцы и использует одну
SVD для коэффициентов и ковариации. Независимая от параметров часть пользовательской
линейной модели вычитается из отклика. Для полос хранится фактор ковариации:
дисперсия вычисляется как квадрат нормы, что уменьшает потерю точности при больших
смещениях X. Производные нелинейных моделей адаптируют шаг к масштабу и границам;
ODR оптимизирует поправки X в единицах σX и использует разреженный якобиан.
Это улучшает устойчивость, но не устраняет неидентифицируемость параметров и
плохую обусловленность произвольной модели.

Bootstrap кеширует коэффициенты и шумовые реализации. Создание колонок использует
тот же расчёт, что график, без повторной подгонки или многократного сканирования
обучающих остатков. При явно выбранном bootstrap его ошибка не заменяется
аналитическими полосами. Протокол содержит фактический метод, уровень доверия,
погрешности и данные для воспроизведения. Отпечаток источников версии 2 учитывает
UUID и значения независимо от перестановок строк/колонок; старые снимки версии 1
проверяются по прежним правилам.

Просмотр архива сохраняет исходные уровни доверия и отключает действия над скрытым
текущим расчётом. «Показать текущий расчёт» возвращает его без оптимизации.
Изменения настроек CV отменяют устаревшее сравнение между блоками, очищают OOF
и не отменяют независимый расчёт полос. Иконки и новые сообщения используют общую
тему и скомпилированные русские/английские каталоги.

Воспроизводимый замер: `python -m tools.benchmark_curve_audit --gui-rows 100000`.
Результат сохранён в `benchmarks/curve-audit-2026-11-05-final.json`.
На текущей машине для 100 000 точек медианы составили: OLS 0.020 с, ODR 0.259 с,
Huber 0.049 с, групповая CV двух моделей (5 блоков) 0.215 с.
Bootstrap на 10 000 точек с 200 повторами занял 1.187 с.
Первое построение GUI на 100 000 точек ускорилось с 0.82 до 0.48 с после устранения
поиска оптимальной позиции легенды и обводки маркеров. Все точки сохранены.
GUI измерялся без импорта проекта, в offscreen Qt; это ориентиры конкретного
окружения, а не гарантированная задержка на других данных или компьютерах.
