# Независимая приёмка встроенных схем интерпретации

Пакет предназначен для эксперта по нефтегазовой геохимии. Технические эталоны проверяют воспроизводимость поведения AutoPyro. Научная применимость, качество источников и независимые измеренные пробы оцениваются экспертом отдельно. Статус `validated` в каталоге обозначает заявленный статус схемы.

## Порядок проверки

1. Начните с `04-sources.md` и `01-blind-inputs.json`. Для каждой редакции сверьте источник, рисунок или таблицу, оси, единицы, шкалы и допустимые диапазоны. Реестр различает исходный SVG, публикацию и рисунок. Если оригинал пока не установлен, зафиксируйте недостающую ссылку или страницу.
2. Запишите ожидаемые статусы, области, типы, стороны порогов или диапазоны HIo до просмотра `02-technical-evidence.json`. Для опубликованных диаграмм используйте оригинальное изображение и документируйте погрешность оцифровки. Координаты и интервалы в задании выражены в физических единицах осей.
3. Откройте техническую выгрузку и сопоставьте независимые ожидания с фактическими результатами по ID пробы. В `scheme` хранится полная редакция, включая геометрию, заявленные ожидания, ограничения и имеющиеся данные о происхождении. `actual` содержит вывод ядра, `failures` — расхождения с техническими эталонами. `unit_checks` содержит результаты проверки привязки обеих осей.
4. При наличии измеренных проб проверьте переносимость на данных с известными методом и единицами, независимым заключением и документированной неопределённостью. Для сравнения с AutoPyro укажите источник, способ привязки колонок и идентификаторы проб. При недостатке данных отметьте, какая часть проверки осталась открытой.
5. Внесите решение в `03-decisions.md`, укажите имя эксперта, дату, использованные источники и ограничения применения. Привязывайте решение к указанному SHA-256 редакции. При расхождении укажите ID пробы, независимое ожидание, фактический результат, критерий сравнения и ссылку на страницу источника.

## На что смотреть

| Критерий | Что сверить |
| --- | --- |
| Геометрия | Положение кривых и порогов, соседство областей, пересечения, пробелы и поведение на границе. |
| Применимость | Разницу между выходом за оси, выходом за область классификации и отказом из-за расстояния до кривых. |
| Единицы | Тип показателя, знаменатель и массу породы или TOC. Отдельно проверьте различие GP и S0+S1+S2. |
| Неопределённость | Интервалы внутри одной области, пересечение нескольких областей и выход части интервала из применимого домена. |
| HIo | Начальное значение на траектории, выбор родительских кривых, диапазон при неоднозначности и обоснование предела применимости. |
| TOCo Jarvie | Соответствие справочных линий источнику и отсутствие автоматически рассчитанного TOCo в текущей схеме. |

Варианты решения — **принято в указанной области применимости**, **требует доработки**, **недостаточно данных**. При расхождении с источником или при отсутствии достаточных данных укажите затронутый критерий и редакцию.

## Воспроизведение

Из корня репозитория выполните команду в окружении AutoPyro.

```powershell
python -m tools.export_interpretation_expert_review --output tmp/interpretation-expert-review
```

Для повторного расчёта по сохранённым схемам и входам выполните команду проверки.

```powershell
python -m tools.export_interpretation_expert_review --verify tmp/interpretation-expert-review/02-technical-evidence.json
```

Проверка использует схемы из файла. Она сверяет их контрольные суммы, состав проб, полные результаты расчёта, эталоны и единицы. При расхождении команда возвращает код 1 и указывает схему, пробу и изменившееся поле. Для старого снимка передайте путь к его файлу в `history`. Сравнение результатов строгое, поэтому смена версии расчётного окружения может потребовать разбора численных расхождений.

Выгрузки формата 2 содержат опись схем, редакций, контрольных сумм и количества эталонов. Проверка сверяет состав с описью и выявляет пустые наборы и повторяющиеся редакции. Файлы формата 1 также поддерживаются. Для них полноту набора схем нужно дополнительно сверить с листом экспертных решений.

Выгрузка фиксирует версии Python, Shapely и GEOS. Контрольная сумма вычисляется штатной функцией `scheme_hash` по JSON-представлению схемы. Повторный запуск обновляет технические файлы и сохраняет заполненный лист решений. Редакции с новыми контрольными суммами добавляются в конец листа со статусом «Ожидает». Старые заключения сохраняют привязку к прежним контрольным суммам.

При изменении заданий, технической выгрузки или реестра источников прежние файлы сохраняются вместе в папку `history`. Название вложенной папки содержит SHA-256 набора имён и контрольных сумм файлов снимка. Старые папки, названные по SHA-256 технической выгрузки, также сохраняются. Для проверки старого заключения найдите в архивной выгрузке запись схемы с контрольной суммой из листа решений. Архив включает только снимки, сохранённые после появления этой функции.
