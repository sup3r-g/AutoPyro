# Интерфейс AutoPyro

Пакет `autopyro.ui` содержит слой представления на PySide6. Точка запуска
`python -m autopyro` и команда `autopyro` вызывают `ui.application.main`.

## Рабочее пространство и KDE Breeze

В листе **Интерполяция** после предпросмотра и создания колонки сохраняется
версионированный снимок выбранных X, Y и групп, единиц, рабочих измерений
и их происхождения. Полный набор опор хранится один раз на группу, включая
опоры PCHIP за пределами ближайшей пары. Исходные измерения не заполняются.

Чтобы проверить прошлый расчёт, выберите созданную колонку в списке листа
интерполяции и нажмите **Проверить сохранённый расчёт**. Проверка заново
вычисляет предложения из снимка и сравнивает их с сохранёнными результатами;
текущая таблица, выделение, история и признак устаревания колонки не меняются.
Проверка работает после правки данных и повторного открытия проекта.
Старые колонки без снимка не появляются в этом списке: для них нужно
создать новый расчёт по исходным данным. Версии NumPy/SciPy записываются
в снимок; сравнение результатов допускает погрешность 1e-12.
Подготовка снимка и проверка от 10 000 строк выполняются в фоновой задаче
с индикатором прогресса. При изменении данных или фильтра во время
подготовки предпросмотр отбрасывается и требует повторного расчёта.

Для разработчика: `autopyro.interpolation.prepare` возвращает предложения
и JSON-совместимый протокол; `replay(protocol)` воспроизводит его без
живого проекта. `propose` сохраняет прежний контракт без подготовки снимка.
Ядро не зависит от Qt. Протокол находится в
`column.metadata["interpolation_protocol"]`; контрольная сумма проверяет
целостность содержимого. Регрессионные сценарии:
`tests/test_interpolation_protocol.py` и `tests/test_table_acceptance.py`.

Новые расчёты из интерфейса дополнительно разделяются по выбранной колонке
ствола и привязанному в стратиграфии стволу, а также по методу, лаборатории,
прибору, программе нагрева, подготовке, фракции, единицам и базе рабочего Y.
Пустые сведения об анализе образуют отдельный контекст, не совпадающий
с известным; число проб без указанного метода выводится в сводке. Само
совпадение пустых полей не доказывает научную сопоставимость проб: для таких
данных необходима ручная проверка контекста и дополнительная группировка.

Если сохранена схема стратиграфии, доступные уровни **Не пересекать границы**
включены по умолчанию. Можно оставить нужные уровни. Пробы разделяются по
ID конкретного интервала, даже при одинаковых названиях подразделений.
Пробы вне покрытия, в перекрывающихся интервалах или без ствола исключаются;
причины доступны на вкладке **Ограничения**. Используются существующие
правила глубины и единиц стратиграфии; MD/TVD и начало отсчёта не подменяются.
Объявленный в привязке интервальный режим блокирует расчёт: середины
интервалов не используются. При отсутствии привязки интервальный характер
данных не угадывается по названиям колонок.

Ограничения, исходная схема/привязка, дополнительные глубинные входы и
диагностика записываются в протокол v2 и воспроизводятся после изменения
живой схемы. Чтение и воспроизведение прежних протоколов v1 сохраняются.
Без `constraints` программный API продолжает прежний алгоритм v1; явные
ограничения доступны и в `propose(..., constraints=...)`.

При 100 тыс. и более рабочих измерений во входах снимка prepare может
использовать кодирование v3. Оно убирает только повторяющиеся null у восьми
объявленных необязательных полей и сохраняет их значения в
`measurement_defaults`. Применяется лишь при реальной экономии JSON-байтов.
Алгоритм остаётся `/1` или `/2`; расчёт, ограничения, опорные точки и
ненулевые значения не меняются. UUID, время создания, ревизия, квалификатор,
единицы и база остаются явными. Replay v3 восстанавливает объявленные null,
проверяет схему и обязательные поля; идентификаторы/даты не создаются заново.
Старые v1/v2 читаются прежним способом, пустые/малые снимки обычно остаются
в этих кодированиях. При редактировании данного контракта нужна новая версия.

Большие снимки новых расчётов автоматически архивируются существующим
JSON/zlib-кодеком проекта. В колонке и журнале сохраняется неизменяемая строка,
которая не распаковывается при обычном открытии или переключении вкладок.
Кнопка проверки распаковывает снимок и проверяет обе контрольные суммы перед
воспроизведением; для архивной строки эта операция всегда выполняется в фоне.
При просмотре соответствующего действия в истории архив раскрывается
только для выбранной записи, также в фоновой задаче.

`prepare` по-прежнему возвращает обычный словарь; `replay` принимает словарь
или архивную строку без изменения научных алгоритмов. Кодирования v1/v2/v3
воспроизводятся через replay. Архиватор применяется
к JSON размером от 64 КиБ до 256 МиБ, если сжатая форма меньше исходной.
Маленькие, несжимаемые или превышающие лимит снимки остаются в прежнем виде.
При открытии старые словари не преобразуются и файл не перезаписывается.
Временная память построения полного снимка остаётся необходимой: это
оптимизация хранения и открытия, а не потоковое построение протокола.

Контрольная сумма и архив теперь кодируют крупные коллекции протокола
порциями по 1000 записей через стандартный JSONEncoder. При этом байты JSON
остаются прежними: научные версии, контрольные суммы и формат архива не
меняются. Целые текстовая/байтовая копии всего JSON для хеша или сжатия
не создаются. Ограничение относится к числу записей в порции; одна крупная
запись или её вложенный массив всё ещё могут потребовать много памяти.
Само дерево снимка, сортировка ключей и итоговая архивная строка остаются
в памяти. Превышение лимита архива прекращает кодирование оставшихся записей
и сохраняет прежний inline fallback.

Крупный предпросмотр пиролитических расчётов выполняется через существующую
фоновую задачу с прогрессом. Параметры считываются из Qt до запуска;
изменившиеся за время задачи данные/выборка делают результат неприменимым.
Небольшой предпросмотр по-прежнему выполняется непосредственно в листе.

Разработчику: при добавлении/удалении производной колонки AddColumnCommand
пропускает синхронизацию исходных Measurement, но выполняет все пересчёты
зависимостей и уведомления модели. Флаг `Project.refresh(sync_measurements=False)`
допустим только для изменений производных колонок. Для правки исходных данных
и добавления обычной колонки остаётся стандартная синхронизация.

AddColumnCommand передаёт UUID добавленной/удалённой колонки через
`changed_columns`. Пиролитическое ядро пересчитывает её и транзитивные
зависимости, сохраняя обход полного графа для диагностики циклов. Независимые
формулы сохраняют прежние результаты. Это допустимо при уже подготовленном
проекте и изолированном добавлении/удалении производной колонки. Для правок
исходных данных, QC, обычного refresh или присутствующих nonpyro/stratigraphy
колонок остаётся полный пересчёт. Уведомления Qt и пометки устаревших отчётов
сохраняются независимо от выбора пересчитываемых формул.

При вставке/удалении производной колонки команда использует
`TableModel.refresh_derived_structure`. Если ядро подтверждает, что затронута
только эта колонка, штатных Qt columnsInserted/Removed достаточно для её
ячеек. Модель сообщает proxy через `derivedStructureChanged` набор UUID;
proxy перепроверяет фильтр/сортировку только при зависимости их правил от
этого набора. Изменения существующих зависимых ячеек и полный fallback
получают обычный dataChanged. Сигнал changed и data_revision обновляются
во всех случаях, сохраняя инвалидирование предпросмотров и обновление окон.
`Project.refresh`/`calculations.recompute` возвращают набор затронутых UUID
при избирательном расчёте либо None для полного прохода. Только операция
вставки/удаления вправе использовать набор для структурного уведомления;
обычный refresh существующих ячеек всегда отправляет dataChanged.

Первая стадия создаёт Measurement из исходной таблицы; вторая повторяет
подготовку уже заполненного реестра. Построение входов и проверка связей,
UUID строк, значений и исходного текста не входят во время стадий.
`--profile` сохраняет отдельный cProfile каждой стадии; интервалы Qt этот
инструмент не измеряет. Числовой парсер находится в `measurements.py`;
импорт `parse_number` из `core.py` сохраняется для совместимости.

При явной сортировке `FilterProxy.sort` на время синхронного вызова Qt
использует `TableModel.cache_sort_indexes`: один корневой QModelIndex
на исходную строку выбранной колонки. Это сокращает повторное создание
индексов при сравнениях. Контекст освобождает набор в `finally`, включая
ошибки; после сортировки индексы не кешируются. Набор не хранит значения,
не перемещает исходные строки и не используется в фоновых задачах.
Обычный `TableModel.index` проверяет границы непосредственно по плоской
таблице; строки под дочерним индексом отсутствуют. Для модели с иерархией
или постраничной загрузкой этот путь потребует отдельной реализации.

Тот же временный контекст применяется при обновлении зависимой сортировки
после derivedStructureChanged. Для нескольких числовых ключей порядок
подготавливается один раз с учётом направления каждого ключа, None и
исходной позиции при полном равенстве. Значения не переводятся во float:
большие целые сохраняют точность. Смешанные/квалифицированные значения,
текст и нестандартные типы используют прежний компаратор. Ранги живут
только в контексте операции; последующее изменение данных читает новые
значения. Дополнительная временная память зависит от числа строк и ключей.

Для нагрузки на правила, использующие созданную интерполяционную колонку:

```powershell
.venv\Scripts\python.exe tools/benchmark_workspace_interpolation.py --rows 30000 --dependent-rules --output tmp/dependent-rules.json
```

После полного сценария выполняются отдельные filter/sort undo/redo.
Ожидаемый список UUID вычисляется независимо, проверяются значения,
текущая ячейка, выделение и QPersistentModelIndex. Флаг несовместим с
`--table-only`; результаты записаны в dependent_rule_checks.

При структурном изменении зависимой колонки proxy дополнительно проверяет,
может ли фильтр расшириться. Отсутствующая колонка даёт None для всех проб;
общая обработка None сохранена для операторов, отрицаний и AND/OR.
При возможном добавлении строк текущие ранги и индексы подготавливаются
один раз. При сужении эта работа пропускается. Решение влияет только на
подготовку сортировки: сам фильтр Qt выполняется всегда.

Контрольный запуск того же сценария без этой подготовки:

```powershell
.venv\Scripts\python.exe tools/benchmark_workspace_interpolation.py --rows 30000 --dependent-rules --plain-filter-ordering --output tmp/dependent-filter-control.json
```

Флаг действует только в процессе бенчмарка; расчётные данные и обычный Qt
порядок не подменяются. Режим записывается в поле filter_ordering JSON.

`FilterProxy.ordered_row_ids` сохраняет один неизменяемый tuple UUID текущего
порядка. Снимок сбрасывается сигналами Qt об изменении данных, layout,
строк/колонок и reset; ключ также учитывает идентичность модели/проекта и
data_revision. Если ревизия меняется во время получения UUID, результат
не сохраняется в кеше. MainWindow.row_ids возвращает новую изменяемую
копию списка, поэтому вызывающий код не может испортить общий снимок.

Формат source_token сохранён: идентичность модели, analysis_revision и
tuple UUID в текущем порядке. Прямые proxy.sort/set_rules/invalidate также
сбрасывают снимок через сигналы Qt, даже без изменения analysis_revision.
Первое получение UUID после изменения по-прежнему проходит Qt; повторные
запросы обхода Qt не делают (копирование list/tuple остаётся линейным).
Изменения данных должны использовать протокол уведомлений модели и её
ревизии; кеш не является наблюдателем произвольных записей в Python-объекты.

Команды интерфейса меняют правила и порядок через `FilterProxy.set_sort_rules`.
При изменении колонки/направления достаточно одного sort; при новых правилах
для прежней колонки/направления нужен invalidate внутри временной подготовки
рангов и QModelIndex. Сброс выполняет sort(-1) без предварительной сортировки
по старым правилам. Повторное применение тех же настроек ничего не пересчитывает.
Восстановление сохранённого представления использует этот же путь.

Замер настоящих команд панели на синтетическом показанном окне (offscreen):

```powershell
.venv\Scripts\python.exe tools/benchmark_sort_controls.py --rows 30000 --output tmp/sort-controls.json
```

Инструмент проверяет полный порядок UUID после применения двух правил,
изменения направления при прежних параметрах Qt и сброса. Подготовка проекта
в измерения не включена. Пользовательские проекты не открываются.

Если протокол интерполяции превышает MAX_PROTOCOL_BYTES (256 МиБ), архиватор
сохраняет прежний inline JSON. `AddColumnCommand` готовит независимую копию
метаданных истории до push(); `_prepare_snapshot` выносит её в worker для
большого проекта и проверяет идентичность проекта/data_revision после работы.
Перед push диалог повторно проверяет source_token, включая прямую смену
фильтра/порядка. Ошибка подготовки не добавляет колонку или команду отмены.
При redo готовится новая копия до beginInsertColumns; события истории не
делят изменяемый протокол ни с колонкой, ни друг с другом. Уже подготовленные
метаданные добавляются в историю без повторного deepcopy в Project.event.
Архивы остаются неизменяемыми строками, их лимит не меняется. При сохранении
SQLite v4 большие вложенные протоколы выносятся в реестр хранилища;
после открытия каждый владелец снова имеет независимые изменяемые данные.
Это улучшает отзывчивость; полное копирование и его расход памяти остаются.

Большой сценарий, включая воспроизведение из сохранённого протокола:

```powershell
.venv\Scripts\python.exe tools/benchmark_workspace_interpolation.py --rows 100000 --replay --output tmp/workspace-full-100000.json
```

Размер протокола подсчитывается потоково вне замера предпросмотра. JSON
содержит размер/лимит и признак превышения. Инструмент сверяет все новые
значения, HI, порядок UUID, удаление значений при undo и независимость inline
событий при redo. `--replay` дополнительно сверяет полный список предложений.
Эта проверка не включает сохранение большого SQLite-файла или нативный экран.

Компоновка следует [рабочему пространству LabPlot](https://docs.labplot.org/en/interface/interface_introduction.html):
слева расположен обозреватель проекта с поиском таблиц, колонок, листов и
сохранённых представлений. В центре открываются вкладки таблицы, графика,
карты, статистики и интерпретации. Выбор колонки показывает её свойства;
параметры активного листа появляются в правой панели.
Существующие расчёты и формат проектов сохраняются.

Свойства проекта и таблицы — отдельные страницы правой панели. При выборе
проекта показываются его название, источник и размеры. При выборе таблицы
или её колонки открываются вкладки **Таблица**, **Фильтр**, **Сортировка**,
**Видимые колонки** и **Представления**, аналогично параметрам графиков.
Команды меню **Таблица** открывают страницы настройки в правой панели.
В этом же меню доступны команды для работы с наборами проб.

Условия фильтра редактируются карточками с выбором колонки, оператора,
значения и NOT; сочетание задаётся через AND/OR. **Применить фильтр**
проверяет черновик и обновляет таблицу. Ошибки показываются в самой панели,
прежний фильтр при ошибке сохраняется. У сортировки колонки отмечаются
флажками, порядок меняется перетаскиванием или стрелками, направление —
двойным щелчком. В **Представлениях** имя вводится прямо в поле,
сохранённое представление выбирается в списке. Видимость колонок
редактируется непосредственно на одноимённой вкладке.
Изменение фильтра или сортировки требует нажатия **Применить**;
переключение между проектом, таблицей и графиком сохраняет черновик.
Смена проекта загружает параметры нового проекта.

**Обработка → Стратиграфия / Интерполяция / Расчёты пиролиза /
Геохимия / Контроль качества** открывает
документы в центральных вкладках. Их формы, параметры, сброс и справка
расположены справа; в центре остаются таблицы результатов, интервалы и
сравнение интерполяции с измерениями. Переключение вкладок сохраняет
черновики. Создание колонок оставляет документ открытым и поддерживает
отмену прежними командами. Изменение исходных данных или текущей выборки
делает предпросмотр неактуальным: перед созданием колонок нужен пересчёт.
При смене проекта документы закрываются вместе с прежними черновиками.

В подменю **Геохимия** доступны отдельные документы: **Изотопы нефти**,
**Геохимия газа**, **Органическая петрография**, **Фракционный состав SARA**,
**Элементный состав**, **Хроматография и биомаркеры**, **Экстракция и TOC**.
У каждого документа собственный набор профилей и черновик параметров.
Импорт находится в **Файл → Импорт геохимии из БД…** и на стартовом экране;
он открывает исходные измерения в таблице перед выбором аналитического модуля.
Справа расположены последовательные вкладки **1. Метод**, **2. Привязки**,
**3. Условия**. Карточки названы по показателям и показывают обязательность,
исходную колонку и единицу её значений. Автоподбор заполняет только пустые
привязки. Результаты и описание методики находятся в центре; числовые значения
выводятся отдельными столбцами. Подсказка возле **Рассчитать** объясняет следующий
шаг. Команды добавления результатов в таблицу, графика, выбора проб и сохранения
протокола сгруппированы отдельно и доступны только для актуального расчёта.
Переход к графику
сохраняет вкладку геохимии. После смены данных или выборки перед созданием
колонок, графиком и экспортом требуется актуальный расчёт.
Экран **Геохимия → Паспорта и сравнение проб** связывает исходные строки одной
пробы без удаления записей, показывает анализы/повторы и доступность методик.
Ручные связи, отношения исходного материала с экстрактом/остатком, выбор измерений
и именованные группы поддерживают undo/redo. Настройка сравнения находится
на отдельной вкладке свойств; таблица и график используют одну выбранную точку
на пробу и показывают исключения. Паспорт экспортируется в JSON, сравнение —
в JSON/CSV, экспорт устаревшего сравнения блокируется.

В контроле качества справа расположены фильтры замечаний, комментарий,
решения и исключения из анализов; в центре — замечания и обоснование.
Решения и исключения по-прежнему поддерживают отмену. Команды перехода
к пробам активируют центральную вкладку таблицы.

В статистике область, показатели, поиск, группировка, корреляции, сброс,
справка и команды экспорта расположены справа. В центре остаются вкладки
сводки, заполненности, корреляций и потенциальных выбросов. В интерпретации
правая панель содержит **Параметры** с привязками осей и командами работы
со схемой и **Схема** с редактором JSON и применением редакции. Результаты
интерпретации остаются в центре. Переключение между листами сохраняет
параметры и черновик JSON; сброс параметров не очищает редактор схемы.

Компоновка этих документов задаётся `widgets/documents.py`; вычисления
по-прежнему выполняются существующими предметными модулями. Окна выбора
файлов при импорте и экспорте схем остаются стандартными диалогами Qt.

Панели можно перемещать, отделять и скрывать через меню **Вид**.
Там же доступно **Восстановить расположение панелей**. Меню **Окно**
переключает документы, **Ctrl+W** закрывает текущий лист.
Открытые вкладки можно переставлять перетаскиванием. Контекстное меню полосы
вкладок содержит команды **Закрыть все** и **Закрыть остальные**. Последняя
оставляет вкладку, по которой открыто меню. Массовое закрытие учитывает запрет
закрытия отдельного документа, включая выполняющиеся расчёты.
Вкладка **Таблица** также закрывается крестиком или **Ctrl+W**. Закрытие
убирает только лист из центра окна: данные, фильтр, выделение и история
отмены сохраняются. Выбор таблицы, колонки или представления в обозревателе
проекта снова открывает таблицу. При открытии нового проекта она появляется
автоматически.
Расположение сохраняется в пользовательских настройках отдельно от проекта.
После переноса управления колонками в свойства таблицы прежнее расположение
панелей заменяется стандартным при первом запуске; остальные настройки
сохраняются. Версия формата расположения задаётся `workspace.LAYOUT_VERSION`.

В **Настройки → Настройки приложения** выбирается светлая или тёмная
**KDE Breeze**; смена оформления применяется сразу. Используются официальные
цветовые схемы и SVG-значки KDE, включённые в пакет вместе с лицензиями.
При наличии системного стиля Qt `Breeze` используется он. В Windows без
этого плагина используется `Fusion` с палитрой и значками Breeze.
Цвета научных графиков определяются настройками самого графика.
Источники ресурсов и лицензии описаны в [theme/assets/README.md](theme/assets/README.md).

## Большие таблицы и проверка производительности

Чтение файла, определение типов и подготовка измерений при импорте выполняются
в рабочем потоке. Qt-модель создаётся в главном потоке после подготовки данных;
повторный полный проход подготовки при подключении таблицы не выполняется.
Прямое открытие большого проекта показывает индикатор подготовки с работающим
циклом событий Qt. Порог фоновой обработки — 100 тысяч ячеек.

При обычном редактировании синхронизируются измерения изменённых строк.
Выбор рабочего результата через `Project.select_measurement`, включая undo/redo
команды таблицы, также синхронизирует и пересчитывает только выбранную пробу,
если в проекте есть лишь построчные пиролитические формулы. Наличие производных
непиролитических или стратиграфических колонок сохраняет полный пересчёт.
Интерполяция помечается устаревшей без автоматического повторного запуска;
результаты интерпретации также получают прежний признак устаревания.
Для обычных и пиролитических колонок таблица уведомляет только изменённые
строки. При наличии интерполяции, стратиграфии или непиролитических производных
сохраняется полное уведомление, поскольку меняются и зависимые представления.
Изменение одной обычной строки не вызывает полной пересортировки.

Отдельный замер выбора рабочего результата на синтетической широкой таблице:

```powershell
.venv\Scripts\python.exe -m tools.benchmark_working_selection --rows 30000 --extra-columns 75 --output tmp/selection.json
```

Инструмент выполняет select/undo/redo для повтора S2 с пересчётом HI; проверяет
все строки по отпечатку и неизменность двух измерений и исходного SourceRecord.
Файлы проектов не читаются и не записываются. Подготовка, GC, проверки и
отложенная обработка Qt исключены из времени команд; синхронные сигналы включены.
Пиковый рабочий набор накопительный, включая подготовку. Это не замер полного
рабочего стола, p95 или нативной отзывчивости Windows.

Сквозной тест `test_wide_table_edit_repeat_undo_background_recovery_and_reopen`
проверяет 1300 строк × 80 исходных показателей в основном окне: выбор повтора,
правку, undo/redo, настоящую фоновую автокопию, восстановление, сохранение и
повторное открытие. Сравниваются все строки, колонки, измерения, UUID, источники
и журнал; ND/пороговые результаты сохраняются. Полный нагрузочный путь на
30 тыс. × 80 также пройден отдельным инструментом, описанным ниже. Нативная
Windows/физический дисплей требуют отдельной проверки.

Однородные числовые и текстовые колонки сортируются по заранее вычисленным рангам;
смешанные квалифицированные значения используют прежнее сравнение. Ранги не
переиспользуются после правки, равные значения и пропуски сохраняют свои правила.

Автосохранение большой таблицы копирует и записывает проект в фоне. Изменение
проекта во время подготовки отменяет эту попытку. Сначала создаётся отдельный
временный файл, который публикуется только для актуальной попытки; отменённая
запись не возвращает удалённую копию и не заменяет существующую. Повторное
автосохранение неизменённого проекта пропускается. Закрытые формы импорта
освобождаются, чтобы не удерживать ранее открытые книги и проекты в памяти.

При восстановлении чтение `Project.load` и подготовка таблицы выполняются
в существующей фоновой задаче с модальным индикатором. Текущий проект
заменяется только после успешного чтения и проверки метаданных восстановления;
повторная подготовка при подключении к Qt-модели пропускается. Исходные
target/digest для защиты от чужой записи сохраняются. Ошибка чтения оставляет
текущий проект и файлы на месте. Подключение готовой модели и отрисовка
по-прежнему выполняются в главном потоке и могут вызывать отдельные паузы.
Явное сохранение использует существующую фоновую задачу с модальным
индикатором. Сначала отменяется текущая автокопия; её завершения ожидает
отдельная задача с работающим циклом Qt. `BackgroundAutosave.cancel()`
возвращает Event завершения именно этой записи, не зависящий от времени
удаления QThread. Пока идёт явное сохранение, таймер не начинает новую
автокопию, а повторная команда Save возвращает False.

Синхронизация рабочих измерений остаётся в главном потоке: сохраняется
поддержка прямых записей через старый API и идентичность объектов измерений.
Затем `copy_project` создаёт независимый снимок в рабочем потоке; обычный
`Project.save` выполняет проверку, запись SQLite, fsync и атомарную замену
со штатной защитой path/digest. Стек undo и модель не заменяются. Полная
копия требует дополнительной памяти и времени; синхронизация и автоматический
GC всё ещё могут давать отдельные паузы. Фон не гарантирует заданный SLA.

Изменение проекта во время ожидания/копирования отменяет запись до обращения
к целевому файлу. Если снимок уже записывается, он остаётся независимым:
сохранённый файл согласован, актуальные изменения остаются dirty, Save
возвращает False и не разрешает закрыть/заменить проект как сохранённый.
При Save As текущему проекту передаются новые path/digest, чтобы следующая
запись сохранила защиту от чужих изменений. Если окно уже переключено на
другой проект, его путь и состояние не меняются. Ошибка записи сохраняет
предыдущий файл, автокопию, dirty и прежнюю привязку хранилища. Автокопия
удаляется только после успешного сохранения актуального состояния.

Полный воспроизводимый сценарий с отдельным замером стадий:

```powershell
.venv\Scripts\python.exe -m tools.benchmark_recovery_workflow --rows 30000 --extra-columns 75 --directory tmp/recovery-wide-new
```

Каталог должен быть новым. В нём создаются только синтетический проект,
локальный INI настроек и `result.json`; существующие проекты и пользовательские
настройки не используются. Прогон не удаляет свой каталог. Автосохранение
вызывается явно после выбора/правки S2, undo/redo и пересчёта HI. Проверяются
публикация автокопии, восстановление основным окном, явное сохранение и обычная
команда открытия с подставленным путём в диалоге выбора файла. Сверяются
отпечатки всех сохраняемых полей после восстановления и повторного открытия,
контрольные суммы неизменяемых файлов, UUID, исходный результат и сведения
о неопределённости повтора. Проверки и построение набора исключены из времени.

Для каждой стадии записываются длительность, наибольший интервал таймера Qt
и память Windows. Пик накопительный и включает перекрытие старого/нового
проекта, подготовку и автокопию. Виджеты показаны на выбранном Qt backend;
по умолчанию `offscreen` не измеряет физический рабочий стол Windows.
Отложенная обработка событий входит во время стадий; принудительный GC перед
стадией, отпечатки и хеши файлов — нет. Обычный автоматический GC во время
операции входит в замер. Один проход не устанавливает p95 или холодное чтение диска.
Промежуточные результаты записываются после каждой завершённой стадии;
только итоговое `verified: true` означает прохождение всех проверок.

Для отдельного сравнения явного сохранения добавить `--save-only`: выполняются
подключение таблицы, сохранение и повторное открытие со сверкой всех полей.
Стадии выбора/правки/автокопии/восстановления в этом режиме пропускаются;
режим явно записывается в отчёт. Использовать новый каталог для каждого запуска.

`--save-only --repeat-save` дополнительно выбирает повтор S2, правит его
до 9, проверяет HI=450 и повторно сохраняет в тот же созданный файл.
Проверяются неизменность исходного измерения, актуализация storage digest,
dirty=False после сохранения и все поля после финального открытия.
Первый файл отдельно не перечитывается: полная сверка относится к последней
версии. Диагностика записывает initial_save и repeat_save раздельно;
повторная запись включает проверку предыдущего digest. Каталог по-прежнему
должен быть новым, пользовательский существующий файл не используется.

`--save-diagnostics` наблюдает существующие операции Save через временные
обёртки только в процессе утилиты: синхронизацию, copy_project, проверку,
SQLite/кодирование/commit, fsync, замену и контрольную сумму. Вложенные интервалы
пересекаются; exclusive_seconds вычитает только дочерние вызовы того же потока.
Ожидание worker в главном потоке не является дополнительной работой CPU.
Слабый finalizer отмечает начало освобождения корневого снимка; интервал
до возврата worker — граница освобождения, не точный профиль всех деструкторов
и не доказательство возврата памяти операционной системе. Если освобождение
не наблюдалось, поле остаётся пустым. Обёртки восстанавливаются при ошибке;
алгоритм записи, fsync, блокировки и политика GC не подменяются.

SQL-диагностика дополнительно использует подкласс SQLite Connection через
штатный factory: executemany по таблицам и commit. Явно переданный factory
сохраняется. Генераторы строк не материализуются. Кодирование RecordEncoder
суммируется по потоку/родительскому SQL-пакету без span на каждую запись.
executemany включает кодирование генератором; остаток после вычитания JSON
всё ещё включает генератор, обвязку, SQL и индексы, а не только дисковый I/O.
Время commit включает внутреннюю работу SQLite, в том числе её синхронизацию.

Проверка `PRAGMA foreign_key_check` измеряется отдельно: execute и fetchall.
Нативный курсор сохраняет строки нарушений и исключения. Раздел `timeline`
содержит восемь самых длинных интервалов таймера Qt (10 мс), пересекающиеся
с ними этапы и интервалы автоматического GC поколения 2. Это временное
совпадение, а не доказательство причины задержки; вложенные этапы пересекаются.
Таймер охватывает контекст Save, обработка очереди Qt после него входит только
в общий замер стадии. Отсчёт ведётся от первого этапа, поэтому начало первого
интервала таймера может быть чуть отрицательным. GC не отключается и не
перенастраивается; callback и обёртки снимаются также при исключении.

Внутри `copy_project` замеряются `copy_measurements` (подготовка копий
измерений) и `copy_table_mappings` (копирование плоских словарей). Время
`exclusive_seconds` родительского этапа включает оставшийся `deepcopy`
и обвязку. Внутри `copy_measurements` отдельно измеряются отбор записей
`select_copy_measurements` и регистрация пустых копий
`allocate_measurement_copies`. Оставшееся время включает заполнение полей.
Пересечение интервала Qt с одним из этапов локализует задержку
по времени, но само по себе не устанавливает её причину.

Построение поисковых индексов измеряется как `secondary_index_build`.
`--early-secondary-indexes` воспроизводит прежний порядок: индексы создаются
до вставки строк. Контроль меняет порядок только в процессе утилиты; в отчёте
пишется `secondary_indexes_after_rows`. `--defer-progress-start` — отдельный
эксперимент отложенного запуска Worker через Qt; в приложение не включён:
сравнение на 3 тыс. × 80 не подтвердило уменьшения первого интервала Qt.

`--write-cache-mib N` меняет бюджет записи только в процессе утилиты;
0 оставляет штатный кеш SQLite. Отрицательное значение отклоняется.
Рабочий бюджет временной базы записи увеличен с 64 до 256 МиБ после сравнения
сохранения 10 тыс. × 80: около 20% меньше времени ценой примерно 192 МБ
дополнительной пиковой памяти. Кеш чтения, формат и долговечность не меняются.
Это бюджет, не предварительное выделение фиксированного объёма; при закрытии
соединения кеш освобождается. Паузы GUI этим изменением не устранены.

`snapshots.copy_project` и `copy_table_state` предварительно копируют плоские
словари `Row.values`, `Row.original`, `SourceRecord.original` и рабочих UUID.
Быстрый путь применяется только к обычному dict с ключами и значениями типов
str/int/float/bool/None. Новый словарь принадлежит снимку; порядок и значения
сохраняются. Общая memo-таблица сохраняет исходные связи между слоями, но не
объединяет разные изменяемые объекты. Подклассы, вложенные списки/словари и
остальные расширения используют прежний deepcopy. Оригиналы удерживаются
в memo до окончания копирования, как в стандартном deepcopy.

В утилите есть отдельный `--experimental-empty-lists`: кандидат прямого
копирования пустой истории измерений. Он действует только в процессе замера.
В продукт не включён: сравнение полного снимка не подтвердило ускорение.
Для контроля запускать ту же команду без этого флага. Рабочее копирование
историй использует обычный deepcopy.

`--experimental-scalar-fields` — отдельный кандидат пакетного копирования
скалярных полей записи с deepcopy истории. Для расширений и иного порядка
полей сохраняет прежний путь. Не включён в продукт: полный снимок на 800 тыс.
измерений не ускорился. `--experimental-single-pass` проверяет однопроходную
регистрацию и заполнение измерений; тоже не включён в продукт, поскольку
полный снимок стал медленнее. Экспериментальные флаги нельзя объединять.

`--diagnostics` добавляет наблюдение за GC только на время самой функции
копирования, без принудительных сборок перед измерением. Пороги GC и его
включение не меняются; собственный callback удаляется даже при ошибке.
В раздельном режиме дополнительно записываются размеры memo: контейнер,
ключи, поверхностные размеры значений и словари атрибутов Measurement.
Это не глубокий размер графа и не резидентная память процесса.

`--allocations` отдельно включает tracemalloc: текущие/пиковые Python-выделения
и основные строки с оставшимися выделениями. Это чистый остаток, а не общий
трафик всех выделений; это не полный учёт нативной памяти библиотек. Снимок статистики
строится после таймера и замера памяти процесса. Время с tracemalloc нельзя
сравнивать с обычным запуском как скорость программы.
При нескольких стадиях накопительный пик процесса может также включать
построение статистики предыдущих стадий; его нельзя считать пиком одной копии.
Первичные отчёты диагностики ошибочно включали предстадийный GC; для выводов использовать
исправленный `tmp/snapshot-gc-aligned-10000x80.json`.

Для отдельного профиля копирования без сохранения файлов:

```powershell
.venv\Scripts\python.exe -m tools.benchmark_snapshot_parts --rows 3000 --profile --output tmp/snapshot-profile.json
.venv\Scripts\python.exe -m tools.benchmark_snapshot_parts --rows 10000 --whole --plain-mappings --output tmp/snapshot-control.json
.venv\Scripts\python.exe -m tools.benchmark_snapshot_parts --rows 10000 --whole --output tmp/snapshot-fast.json
```

Без `--whole` отдельно измеряются создание memo измерений и остальная копия
(включая подготовку плоских словарей). Между стадиями вызывается явный GC.
С `--whole` измеряется обычный copy_project целиком без промежуточного GC.
`--plain-mappings` отключает только новый путь в процессе инструмента.
Профилированные времена включают накладные расходы cProfile; для сравнения
задержек нужны отдельные запуски без профиля. Проверяются равенство данных и
независимость снимка. Пользовательские файлы не читаются и не записываются.

Замечания QC представлены `QAbstractTableModel`: доступны все замечания,
но строки и переводы создаются для отображаемых ячеек. Фильтрация и решения
не пересоздают миллионы `QTableWidgetItem`. Правила QC повторно выполняются
при изменении данных; решения и их отмена обновляют состояние без повторного
запуска неизменённых проверок. Большой расчёт QC также выполняется в фоне.

Воспроизводимый прогон реального импорта, сортировки, фильтра, правки,
отмены и QC с замером максимальной задержки таймера интерфейса:

```powershell
.\.venv\Scripts\python.exe -m benchmarks.large_table examples/npd.xlsx --qc
```

По умолчанию используется `offscreen`, результат записывается в
`tmp/large-table-benchmark.json`. Для окон Windows задайте
`$env:QT_QPA_PLATFORM = 'windows'`. Параметр `--report PATH` меняет путь отчёта.
Прогон использует временные настройки, не изменяет исходную книгу и проверяет
возврат исходного значения после undo. Длительность зависит от оборудования;
регрессионные тесты проверяют число обращений, виртуализацию и отзывчивость,
а не фиксированное время выполнения.

## Сброс параметров и контекстная помощь

В окнах с параметрами есть кнопка **По умолчанию**. Она возвращает параметры
текущей операции к исходным значениям, а не очищает проект. Предпросмотр, если
он зависит от изменённых параметров, становится неактуальным и требует пересчёта.
Диалоги чтения файлов используют сохранённые значения импорта из настроек приложения;
диалог источника БД — сохранённые параметры подключения.

В окнах графиков и карт:

- **Сбросить оформление** возвращает стандартные цвета, маркеры, оси, легенду,
  размеры и DPI. Привязки X/Y, вид графика, область выборки, CRS, фильтры карты
  и загруженные данные сохраняются. У карты сбрасывается также оформление слоёв;
  сами слои и их геометрия остаются.
- **Сбросить параметры вкладки** сбрасывает только текущую форму. На вкладке
  выбора данных это может снять привязки колонок; значения проекта сохраняются.
- В редакторе геометрии **Сбросить вид** вписывает схему в окно и возвращает
  показ проб, сохраняя геометрию, редакцию, черновик и историю правок.
- **Свойства → Таблица → Сбросить параметры представления** снимает фильтрацию, сортировку
  и скрытие колонок. Именованные представления и значения ячеек сохраняются.

**Что это?** включает стандартный режим Qt What's This: затем нажмите на
параметр. Также доступно **Shift+F1**; в главном окне — меню **Помощь**.
Справка объясняет смысл параметра, единицы, ограничения и автоматические значения.
То же подробное описание появляется при наведении на параметр или его подпись.
Рядом с каждым редактируемым параметром находится отдельная кнопка сброса
со значком KDE Breeze. Она восстанавливает только это поле, сохраняя соседние
настройки, и запускает существующие обработчики обновления и проверки.
В таблицах параметров, категорий оформления и слоёв сброс отдельной ячейки
доступен через контекстное меню. Таблицы исходных данных и результатов исключены.
Пароли в справке не показываются. Для окон просмотра измерений и библиотеки
шаблонов доступна помощь; кнопка очистки данных под видом сброса не добавляется.

Общие формы задают значения по умолчанию при создании полей. Новый параметр
получает базовую справку автоматически; специальное пояснение добавляется
в `parameter_description()` или через `setWhatsThis()`. Для обычного диалога
вызовите `add_parameter_tools()` после построения формы. Сброс затрагивает
редактируемые параметры; таблицы результатов исключены. Таблицы настройки,
например сопоставление колонок, включаются явно через `tables=`. При восстановлении
сигналы временно блокируются, затем вызывается один обработчик обновления.
`widgets.parameter_reset.parameter_field()` возвращает контейнер поля с кнопкой;
используйте его при управлении видимостью строки `QFormLayout`. Контролы в
`Form.fields` остаются прежними, а значения берутся из `Form.defaults`.

## Настройки приложения

Меню **Настройки → Настройки приложения…** открывает отдельное окно с вкладками:

- **Общие:** язык, включение автосохранения и его интервал (1–120 минут).
- **Импорт по умолчанию:** разделитель CSV/TSV, кодировка и десятичный знак.
- **Подключение к БД:** сервер, порт, база и пользователь PostgreSQL, путь и
  таблица SQLite. Пароль действует только в текущем сеансе и не записывается
  в `QSettings` или проект. При изменении адреса или пользователя поле пароля очищается.

«Сохранить» применяет настройки, «Отмена» оставляет прежние значения.
«По умолчанию» сбрасывает только черновик окна до нажатия «Сохранить».
Настройки хранятся отдельно от проектов в пользовательском `QSettings` AutoPyro.
Автосохранение перенастраивается сразу. Параметры импорта и БД подставляются
в новые диалоги; импортный шаблон может переопределять значения. Источники
открытых проектов остаются прежними. До задания настроек БД используются
существующие значения окружения / `.env`. Пароль окружения не переносится
на другой сервер, порт, базу или пользователя.

Язык применяется при следующем запуске; приложение сообщает о необходимости
перезапуска. По умолчанию выбран русский язык.

## Каталоги Qt и добавление языков

Переводы загружаются стандартным `QTranslator` из `.qm`. Каталог приложения
использует контекст `AutoPyro`, метаданные языка — `AutoPyroLanguage/native_name`.
В поставку входят отдельные русские `autopyro_ru.ts/.qm` и английские
`autopyro_en.ts/.qm` каталоги. Русский каталог содержит исходные русские тексты
и загружается тем же механизмом, что и остальные языки; отсутствие перевода
по-прежнему приводит к выводу исходного текста.
Python-словарей переводов и фиксированного списка языков нет. Доступные языки
определяются по валидным файлам `autopyro_<locale>.qm` в:

- `autopyro/ui/i18n/translations/` внутри установленного пакета;
- `AutoPyro/translations/` в пользовательском каталоге данных Qt
  (`QStandardPaths.GenericDataLocation`, в Windows обычно `%LOCALAPPDATA%`).

Пользовательский каталог имеет приоритет. Некорректные `.qm` пропускаются;
при отсутствии выбранного языка используется русский исходный текст.
Имя языка берётся из метаданных каталога либо из `QLocale`. Региональные
коды (`pt_BR`, `zh_Hant_TW`) поддерживаются, направление интерфейса
выбирается по локали, включая языки с письмом справа налево.

Для добавления, например, немецкого языка:

```powershell
.\.venv\Scripts\python.exe -m autopyro.ui.i18n.catalogs --new de --name Deutsch
.\.venv\Scripts\pyside6-linguist.exe autopyro/ui/i18n/translations/autopyro_de.ts
.\.venv\Scripts\python.exe -m autopyro.ui.i18n.catalogs --update --compile
```

Заполните переводы в Qt Linguist до компиляции. Новый `.qm` автоматически
появится в списке настроек. Изменять Python-код для нового языка не требуется.
Для пользовательского каталога утилита также принимает `--directory PATH`.
Исходные `.ts` и скомпилированные `.qm` включены в пакет приложения.

Утилита добавляет новые литералы `tr()` в `.ts`, сохраняя прежние переводы
и сообщения предметных модулей. Перед `lrelease` проверяются подстановки;
незавершённые переводы не включаются в `.qm`. Шаблоны распознавания сообщений
хранят только исходные тексты в `source_patterns.py`, без языковых переводов.
Новые обычные сообщения русского каталога заполняются исходным текстом
автоматически; ранее отредактированные переводы сохраняются. Формы множественного
числа требуют отдельного заполнения в Qt Linguist.

Перевод охватывает меню, диалоги, подписи, сообщения, команды отмены и повторения.
Стандартные элементы Qt используют соответствующий локали `qtbase_<locale>.qm`,
если он доступен в поставке Qt. Пользовательские
названия, значения ячеек, единицы и идентификаторы остаются в исходном виде.
Содержимое сформированных научных отчётов и исходные протоколы хранятся в формате
предметных модулей; выбор языка интерфейса не переписывает эти документы.

Для новых текстов используйте `tr("Исходный текст")` из `ui.i18n` и обновляйте
каталоги приведённой выше командой. Динамические значения подставляйте после
перевода: `tr("Источник: {0}", path)`. Значения для логики передавайте отдельно
от подписей через `QComboBox.userData` / `currentData`. Для ошибки предметного
модуля используйте `message(exception)` на границе интерфейса; исходная ошибка
и пользовательские значения сохраняются. При неизвестном тексте выводится
оригинал. Для форм множественного числа поддерживается стандартное Qt numerus:
`tr("%n проба", n=count)`. Тест каталога проверяет наличие переводов и совпадение
подстановок.

## Каталоги визуализации и разделы параметров

`autopyro.plot_catalog` получает именованные цвета из
`matplotlib.colors.get_named_colors_mapping()`, маркеры из
`MarkerStyle.markers`, цветовые шкалы из текущего `matplotlib.colormaps`.
`widgets.style_labels` задаёт русские и английские подписи маркеров, цветов,
цветовых шкал и положений легенды через каталоги Qt. Для редких цветов
используется описание оттенка по фактическому RGB вместе с точным кодом цвета.
Списки показывают образцы цветов и градиенты; исходные идентификаторы доступны
в подсказках и сохраняются через `currentData()`. Делегаты таблиц меняют только
представление значений. Новые регистрации библиотек остаются доступными;
для неизвестной цветовой шкалы отображается её собственное имя.
Списки включают регистрации расширений; цвет можно также ввести вручную
в формате Matplotlib, маркер — задать выражением MathText.

У Matplotlib нет общего реестра типов графиков. Каталог `KINDS` обнаруживает
публичные методы построения `Axes` и `Axes3D` по API установленной версии.
Шесть прежних представлений AutoPyro сохраняют свои имена для совместимости
с проектами. `library_plot` адаптирует табличные данные к сигнатурам методов:
дополнительные колонки выбираются на вкладке «Библиотека», матрицы собираются
из отмеченных треков без заполнения пропусков. Для регулярных поверхностей
требуется полная сетка X–Y без повторов. Параметры метода, например `NFFT`
и `noverlap`, можно передать объектом JSON. Они не выполняются как Python-код.

Установленные Seaborn (методы с аргументом `ax`) и UltraPlot подключаются
автоматически. Необязательные зависимости: `pip install -e ".[visualization]"`.
Без них приложение использует Matplotlib. UltraPlot требует собственный Figure;
при переключении библиотек обновляются canvas и панель навигации.

Основание логарифма хранится в `AxisSpec.log_base` отдельно для X, Y, Z
и каждого трека. Допустимо положительное конечное число, отличное от 1;
прежние проекты используют 10. Предпросмотр и экспорт применяют одну конфигурацию.

Общие формы и настройки модулей разделены `QGroupBox`. `widgets.groups`
переносит существующие элементы в именованные разделы, сохраняя сигналы,
сброс параметров и справку. Расчётные операции модулей не меняются.

## Граница с логикой приложения

Интерфейс импортирует предметные операции из тематических пакетов, например
`autopyro.model`, `autopyro.analysis` и `autopyro.schemes`. Импорт и экспорт файлов
собраны в `autopyro.data_io`, а доступ к БД и хранение проектов — в `autopyro.database`.
Предметная логика и хранилище отделены от интерфейса.

Диалоги собирают параметры, вызывают существующие операции и показывают
результат. Общие компоненты импортируются из `widgets`, а не из специализированных
окон. Фоновые операции используют `tasks`; изменения таблицы проходят через
Qt-команды `table.commands`, сохраняя существующее поведение undo/redo.

## Совместимость импортов

Новый код интерфейса использует модули внутри `autopyro.ui` напрямую.
Прежние пути к модулям интерфейса, БД и предметной логики зарегистрированы
в едином модуле `autopyro/_compat.py`.
Отдельных файлов-обёрток в корне пакета больше нет. Перенаправления загружаются
по требованию: импорт предметной логики не загружает Qt и окна. Поэтому старые
и новые импорты получают одни и те же классы и объекты модулей, в том числе
при подмене зависимостей в тестах. `autopyro.dialogs` переэкспортирует классы,
разделённые между `tasks`, `data_io` и `dialogs`.

Проверка: из корня проекта выполнить в PowerShell:

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
.\.venv\Scripts\python.exe -m pytest -q
```

Для проверки запуска и восстановления панелей в нативном Qt Windows:

```powershell
$env:AUTOPYRO_NATIVE_SMOKE = '1'
.\.venv\Scripts\python.exe -m pytest tests/test_application_startup.py -q
```

Эти проверки открывают и закрывают тестовые окна со временными настройками;
в обычном прогоне они пропускаются. Они покрывают аварии Qt при показе окна,
которые не воспроизводятся платформой `offscreen`.

### График внутри интерпретации

`InterpretationDialog` встраивает `PlotDialog(interpretation_owner=...)` над таблицей
результатов. Оба блока видны одновременно; вертикальный `QSplitter` позволяет
менять их высоту, сохраняя минимальный размер каждого блока. Страницы общих настроек графика находятся в панели
свойств документа интерпретации. Вид фиксирован как `scatter`; X/Y, область данных
и чтение текстовых чисел задаются параметрами интерпретации. Слой схемы доступен
только для актуального отчёта, включая экспорт. При редактировании схемы или
изменении входов старый график очищается до повторного расчёта.

Маркеры, оси, подписи, категории, оформление и настройки экспорта синхронизируются
между двумя документами через `plot_shared_settings`. Привязки данных, вид и
научные слои остаются локальными: `plot_current` и `interpretation_plot_current`.
При смене осей схемы подписи и шкалы принимаются из определения схемы. Закрытие
документа освобождает ресурсы предпросмотра; повторное открытие восстанавливает
тот же редактор и настройки. Пиролитические схемы выбираются в интерпретации.

Холст графика заполняет доступную ширину и высоту области просмотра. При изменении
размера окна или панелей предпросмотр перерисовывается в фоне после короткой паузы,
сохраняя масштаб осей и выделение проб. Размеры в миллиметрах относятся к экспорту
и сохранённому оформлению; подгонка предпросмотра их не изменяет.

Карты, пространственная интерполяция IDW, стратиграфическая колонка и редактор
геометрии используют общий `widgets.figure_canvas.FittedFigureCanvas`. Холст
занимает всю область, выделенную компоновкой Qt, в том числе после повторного
построения колонки с экспортными размерами/DPI. Изменение окна сохраняет оси и
выделение без повторного расчёта данных. Географический масштаб карты остаётся
одинаковым по X и Y; заданные размеры экспорта карты и колонки не меняются.

На панели каждой визуализации `widgets.figure_canvas.CanvasView` добавляет режимы
«Подогнать под окно» (по умолчанию) и «Реальный размер». Во втором режиме холст
получает размеры рисунка при экранном DPI, а область просмотра включает прокрутку.
Для редактора схем и IDW без настроек размеров используется исходный размер
рисунка. Переключение меняет только просмотр и сохраняет пределы осей, выделение
и параметры экспорта. В графиках используется существующая фоновая отрисовка;
замена холста при смене библиотеки сохраняет выбранный режим.

Режимы сохраняются в `project.view['visualization_view_modes']` отдельными ключами:
`plot`, `interpretation_plot`, `map`, `stratigraphy_column`, `spatial_interpolation`,
`geometry_editor`, `curve_fitting`. Значения `fit` и `actual` не зависят от языка интерфейса.
Восстановление не изменяет проект; отсутствующая или неизвестная запись означает
подгонку. Переключение помечает проект как изменённый через `MainWindow.view_changed`,
обновляя состояние сохранения и автосохранения без инвалидирования расчётов.

Все Matplotlib-холсты используют `widgets.navigation.NavigationToolbar`: исходный
вид, назад/вперёд по истории, перемещение и масштабирование рамкой. Панель содержит
общие значки приложения, переведённые подписи/подсказки, координаты курсора и режим
`CanvasView`. Стандартные Save, Subplots и Customize не показываются: экспорт и
оформление выполняются средствами приложения. Перепривязка истории к осям фоновых
кадров и завершение перетаскивания сохранены в общей реализации.
Отмена оформления, пакетный экспорт и удаление слоёв графика доступны в меню «…»
панели действий графика. В редакторе схем отмена/повтор находятся рядом с объектами,
а «Вписать всё» — рядом с пределами осей. Подгонка кривых использует ту же панель
и `CanvasView`; отдельная кнопка экспорта изображения находится в параметрах модуля.

Область анализа задаётся общим `AnalysisScope` (`ui/analysis_scope.py`). Переключатель
на панели «Обработка» и списки в документах синхронизированы: текущая таблица,
все пробы, выделенные строки и все записи `project.view['named']`. Новые и изменённые
представления обновляются в открытых документах. Выбранный код хранится в
`project.view['analysis_scope']`; старый проект начинает с текущей таблицы.
Представление вычисляется отдельным кешируемым `FilterProxy`, с собственными
фильтрами и сортировкой. Фильтр исходной таблицы при этом сохраняется. Пустая
область не заменяется всеми пробами; отсутствующая колонка фильтра вызывает ошибку.
Удаление активного представления возвращает общий выбор к текущей таблице.

Общий выбор используют графики, карты, статистика, интерпретация, геохимия вне
пиролиза, расчёты, интерполяция, привязка стратиграфии, отчёты и список QC. Целевая
категория исключений QC остаётся отдельным параметром. IDW при запуске получает
новый снимок строк выбранной области с настройками исходной карты; устаревший
результат после смены области отбрасывается. Предпросмотр проб в редакторе схем
обновляется по той же области, с прежним ограничением 2000 проб. Смена области,
выделения или активного представления инвалидирует зависимые предпросмотры;
`source_token` включает ревизию общей области для защиты создания колонок.

Кнопка «⋯» рядом с общим выбором области и контекстное меню списков области дают
команды создания, переименования и удаления представлений. Создание сохраняет
текущие фильтры, сортировку и оформление исходной таблицы, затем выбирает новое
представление для анализа. Названия обрезаются по краям; пустые и совпадающие
названия отклоняются без перезаписи. Переименование сохраняет выбранную область
и обновляет ссылки в сохранённых настройках, графиках и истории оформления
открытых графиков. Удаление требует подтверждения; для удалённого представления
ссылки настроек возвращаются к текущей таблице. Архивные результаты не меняются.
Операции сразу обновляют списки во всех модулях и свойствах таблицы и сохраняются
обычным сохранением проекта.

Команда «Редактировать представление» открывает `table.view_properties.SavedViewProperties`
в правой панели, сохраняя текущую визуализацию в центре. Редактор использует общие
виджеты условий и сортировки таблицы, но читает и обновляет выбранную запись
`project.view['named']`. Кнопки сохранения фильтра и сортировки применяют изменения
к представлению, сохраняя остальные его параметры. Исходные фильтры и порядок
строк таблицы не меняются. Обновление инвалидирует зависимые предпросмотры через
общий `AnalysisScope`; кнопка «Готово» возвращает свойства текущего документа.
Смена области переключает открытый редактор на другое выбранное представление;
переименование сохраняет незаписанный черновик условий, а удаление или выбор
встроенной области закрывает редактор. Переключение проекта очищает его цель.

Контекстное меню обозревателя строится в `ui/project_menu.py` по типу и стабильному
идентификатору объекта под курсором. ПКМ подсвечивает узел с заблокированным
`currentItemChanged`, не открывая лист и не применяя представление. Меню проекта
содержит операции файлов, импорта, истории и отчёта; таблицы — её свойства,
фильтры, сортировку, колонки, представления и экспорт. Колонки предлагают показ,
копирование, сортировку, условие фильтра и открытие анализа с выбранной колонкой.
Представления можно использовать для анализа, применить к таблице, редактировать,
переименовать или удалить. Сохранённые графики поддерживают открытие, переименование,
удаление пресета и фоновый экспорт выбранной конфигурации.

Листы дают доступ к существующим расчётам, экспорту, масштабу просмотра и закрытию
с проверкой готовности результата и занятости. Подменю «Открыть модуль» включает
все аналитические модули, отдельные разделы геохимии и отчёт. Из контекста
представления модуль получает именно его область. Слои карты показаны дочерними
узлами и предлагают свойства, атрибуты, показ и удаление по ID. Контекстный экспорт
готового листа активирует его без повторного запуска, чтобы сохранить результат.

Наведение на точку показывает исходные значения X/Y и выбранных каналов оформления,
единицы и актуальный результат интерпретации. Для сохранённого слоя без подходящего
отчёта результат вычисляется по координатам точки и схеме слоя. Наведение на область
показывает полное название независимо от видимости её подписи; на общей границе
показываются названия всех найденных областей. Поиск учитывает отверстия полигонов
и преобразования координат схемы. Точка имеет приоритет перед областью.

`plot_hover.HoverIndex` использует KD-дерево экранных координат и STRtree областей.
Индекс точек строится лениво, обновляется при смене пределов/размера осей и
сбрасывается вместе с кадром. События наведения объединяются таймером 60 мс;
каждое движение мыши не запускает обход всех проб или перерисовку графика.

Выделение графика интерпретации и таблицы результатов синхронизировано по UUID.
Обычный щелчок выбирает строку целиком; таблица поддерживает множественное
выделение. Выбор рамкой на графике выбирает соответствующие строки результатов.
Подсветка обновляет только слой выделения, без нового расчёта или подготовки
предпросмотра. При пересчёте сохраняется пересечение выбранных UUID с новой
таблицей результатов. Строки без числовой точки остаются доступными в таблице.
Это выделение не изменяет исходную таблицу проб и её выборку «Выделенные строки»;
в самостоятельном модуле «График» прежняя связь с исходной таблицей сохранена.

### Предварительный контроль качества и объяснение пробы

`interpretation_quality` проверяет пользовательские диапазоны TOC, S1, S2,
Tmax, HI и OI перед геометрической интерпретацией. SI трактуется как S1,
T-Max как Tmax. Границы включены в диапазоны. Значения вне типичного диапазона
дают предупреждение; значение оси вне абсолютного диапазона не передаётся
ядру и возвращает not_applicable. Исходная таблица не изменяется. Ошибка
неиспользуемого вспомогательного показателя не блокирует независимые оси.
Поддерживаемые единицы нормируются перед сравнением; без подходящей единицы
выдаётся предупреждение о невозможности проверки. Между повторяющимися
вспомогательными колонками одного свойства автоматического выбора нет.

Профиль пользователя (абсолютный минимум / типичный минимум / типичный максимум /
абсолютный максимум): TOC 0/0.1/84/100, S1 0/0.2/2/100, S2 0/0.5/100/1000,
Tmax 350/400/500/600, HI 0/10/900/1200, OI 0/2/5/500. В частности, типичный
максимум OI=5 сохранён из предоставленной таблицы; это пользовательский ориентир,
а не заявленная универсальная научная норма.

Правила и предупреждения сохраняются в JSON отчёта, предупреждения также в CSV
и колонке «Контроль качества». Существующие QC-исключения, интерполяции, пропуски
и квалифицированные записи не подменяются числом. Панель объяснения под таблицей
показывает результат текущей пробы, источник и редакцию схемы, причины
неоднозначности, расстояния и HIo. При множественном выборе поясняется текущая
строка; при пересчёте старое объяснение помечается неактуальным. Выбор пробы
читает готовый отчёт по индексу строки, не сканирует все пробы и не запускает ядро.

### Сравнение диагностических диаграмм

Флажок «Сравнить HI–Tmax, HI–OI и S2–TOC» включает три одновременно видимые
диаграммы. Выборка, чтение текстовых чисел, оформление и выделение по UUID общие;
шкалы и подписи осей задаются каждой научной схемой. Недостающие, неоднозначные
показатели или неподдерживаемые единицы отображаются сообщением в соответствующей
панели. Неявное смешение колонок из разных групп не допускается. Автоматически
показатели не рассчитываются: HI/OI следует заранее подготовить в модуле расчётов.

`interpretation_comparison` разрешает привязки, готовит отдельные отчёты и
компонует обычный scatter-рендерер на трёх осях. Числовые колонки подготавливаются
общим кэшем, предпросмотр выполняется существующим фоновым процессом. Совпадающий
основной отчёт повторно не рассчитывается. Выделение обновляет слой подсветки на
всех осях, а не пересчитывает три схемы. Подсказки учитывают схему оси под курсором.

Таблица получает отдельные колонки результатов трёх диаграмм; они же включаются
в CSV. JSON-снимок содержит отдельные отчёты, QC и редакции схем. Экспорт рисунка
сохраняет всю тройку. Панель объяснения показывает сопоставление результатов
выбранной пробы, не подменяя разные признаки единым геологическим заключением.
Выключение режима возвращает исходную диаграмму, сохраняя выделение.

### Неопределённость измерений

Используется неопределённость **выбранного рабочего измерения**, заданная в его
карточке. absolute/interval — ±u в единицах значения; standard/std/sigma — ±1u;
expanded — уже расширенное ±u; relative_percent — ±u процентов от модуля значения;
relative_fraction — относительная доля. Нулевой интервал не рисуется. Тип и
заданный уровень доверия сохраняются в отчёте; множители 1.96, k и дополнительные
доверительные уровни не вычисляются. При неуказанном/неподдерживаемом типе или
несовпадении единиц выводится предупреждение, а интервал не придумывается.
Неопределённость производных HI/OI автоматически из S2/TOC/S3 не выводится.

Для полигонов ядро получает x_bounds/y_bounds: пересечение нескольких областей
даёт статус «Неоднозначно» и список uncertainty_regions. Пробы с таким
геометрическим пересечением на рисунке помечаются оранжевым ромбом. При двух
неопределённых координатах показывается прямоугольник, при одной — отрезок.
На логарифмической оси диапазон с неположительной границей не рисуется. Выход
границ за область применимости схемы явно отражается статусом результата;
границы не обрезаются автоматически. Для ближайших кривых/HIo выполняется
адаптивная интервальная интерпретация, описанная ниже. Оболочки не объявляются эллипсами или
совместными доверительными областями: ковариация исходных ошибок неизвестна.

Флажок «Показывать интервалы неопределённости» в оформлении управляет рисунком,
не меняет расчёт или предупреждающие маркеры. Автомасштаб учитывает данные вместе
с показанными диапазонами. Коллекции примитивов и STRtree избегают N отдельных
художников и повторного обхода всех областей для каждой пробы. Выделение по UUID
по-прежнему относится к точкам, включая сравнение трёх диаграмм.

Границы, тип, уровень доверия и версии измерений сохраняются в JSON; CSV содержит
x_bounds/y_bounds и uncertainty_regions. Повторное воспроизведение использует
замороженные границы. Изменение метаданных неопределённости помечает сохранённый
результат неактуальным; штатные команды измерений меняют ревизию данных и снимок
фонового предпросмотра. Отдельный научный store в процесс отрисовки не передаётся.

Интервалы HI–Tmax/HI–OI теперь возвращают possible_types — возможные типы по
опорным кривым; HIo возвращает value_bounds и объяснение неоднозначности. Поиск
рассматривает всю область через липшицевы оценки расстояний и адаптивное уточнение.
При исчерпании бюджета сохраняется консервативная оболочка, что явно указано в
панели и подсказке. Экстраполяция запрещена. Подробности и параметры описаны в
SCIENTIFIC_METHODS.md, раздел «Интервальная интерпретация HI–Tmax, HI–OI и HIo».
Для HIo родительские кривые семейства и возможные типы по исходным траекториям
показываются раздельно. CSV/JSON сохраняют возможные типы и interval_details.
