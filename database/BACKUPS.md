# Резервное копирование и проверка восстановления

Из корня проекта, при запущенном сервисе PostgreSQL в Compose:

```powershell
.venv/Scripts/python.exe -m autopyro.database.tools.backup_database
```

Требуются административное подключение к базе и доступ к Docker. Подключение
использует `.env` и переменные PG*; пароль не передаётся в аргументах Docker
и не выводится. Поддерживается текущая база `geochemistry`. Перед копированием
команда проверяет, что TCP-подключение и Compose относятся к одному кластеру.
Можно выбрать другой каталог: `--output-root D:/Backups/AutoPyro`.

Каждый запуск создаёт новый каталог `database/backups/geochemistry_<UTC-время>_<id>`:

- `geochemistry.dump`: полный архив pg_dump custom, включая таблицы и данные,
  исходные JSON, справочники, версии интерпретаций, журнал миграций, представления,
  функции, триггеры, индексы, ограничения и права объектов.
- `SHA256SUMS.txt`: SHA256 всего архива.
- `verification.json`: статус проверки и манифесты исходной/восстановленной базы.
- `README.md`: краткое описание успешного результата.

Старые дампы не перезаписываются. Каталог неудачного запуска сохраняется с
`status=failed` для диагностики; он не является проверенной резервной копией.
Только `status=verified` с завершённой очисткой означает успешный результат.

## Как проверяется дамп

Административная read-only транзакция экспортирует снимок PostgreSQL.
`pg_dump --snapshot=...` и чтение отпечатков используют один снимок данных:
параллельное изменение строк не приводит к сравнению разных моментов времени.
Состояния последовательностей не подчиняются MVCC, поэтому для успешной проверки
они должны оставаться стабильными. Запускать без параллельных импортов, миграций
и административного редактирования интерпретаций.

Архив восстанавливается через pg_restore с `--exit-on-error --single-transaction`
в новую базу `geochem_restorecheck_<случайный id>`. Сравниваются:

- число строк и SHA256 отсортированного набора построчных SHA256 всех таблиц;
  порядок физических строк не важен, одинаковые строки учитываются с кратностью;
- состояния и параметры последовательностей;
- колонки, типы, значения по умолчанию, identity/generated и ограничения;
- определения представлений, индексов, функций и триггеров;
- владельцы, ACL объектов и схем, default privileges в схемах.

После проверки временная база удаляется. Очистка разрешена только для имени
с ожидаемым случайным префиксом и только если эта база была создана данным
запуском; имя исходной базы отдельно запрещено. Исходная база не изменяется.
Если очистка не удалась, отчёт получает `cleanup_failed` и имя оставшейся базы.

Файл архива записывается в бинарном режиме через subprocess без PowerShell
перенаправления: преобразование бинарного потока в текст исключено.
Проверка требует дополнительного места в PostgreSQL для восстановленной базы
и вычисления отпечатков. Серверные роли и их пароли, конфигурация сервера,
Compose, `.env` и файлы приложения в дамп отдельной базы не входят.

## Текущая проверенная копия

Актуальная копия хранится в `backups/geochemistry_2026-11-08_123755_1fb7ae34`.
Архив занимает 22 810 210 байт. Проверены 28 таблиц, 18 последовательностей,
20 представлений, 259 ограничений, 72 индекса, 9 функций и 6 триггеров.
Данные и определения совпали, временная база удалена. Копия включает миграцию
015 и пилотный черновик интерпретации 913 для ствола 7227/10-1.

## Ручное восстановление в новую базу

На текущем сервере роли admin и readonly уже существуют. На другом сервере
их необходимо создать до восстановления: роли и пароли не входят в архив.
Используйте совместимый PostgreSQL и клиент pg_restore; текущий Compose
использует PostgreSQL 18. Восстанавливайте только в новую пустую базу.

```powershell
docker compose cp database/backups/geochemistry_2026-11-08_123755_1fb7ae34/geochemistry.dump postgres:/tmp/geochemistry_manual_restore.dump
docker compose exec -T postgres createdb -U admin --template=template0 --owner=admin geochemistry_restored
docker compose exec -T postgres pg_restore -U admin --exit-on-error --single-transaction --dbname=geochemistry_restored /tmp/geochemistry_manual_restore.dump
```

Если `geochemistry_restored` уже существует, createdb должен завершиться ошибкой;
не продолжайте восстановление в непустую базу. Команды не заменяют рабочую
`geochemistry`, и приложение продолжает подключаться к ней.
Права объектов восстанавливаются из архива. Свойства новой базы, её имя и доступ
на уровне DATABASE нужно настроить отдельно; pg_restore без `--create` не
подменяет их настройками рабочей базы. Например, для новой базы ограничьте
TEMPORARY для PUBLIC и предоставьте readonly CONNECT, если это требуется.

Проверить целостность перед восстановлением:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath database/backups/geochemistry_2026-11-08_123755_1fb7ae34/geochemistry.dump
```

Сверьте результат с `SHA256SUMS.txt`. Проверка SHA256 файла не заменяет
испытание восстановления. Команда backup_database выполняет обе проверки.
