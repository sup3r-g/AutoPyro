# Привязка геохимических проб к выбранной интерпретации

Миграция 015 добавляет `geochem.v_lithostrat_depth_review`. Представление
доступно роли `readonly` и показывает интервалы зафиксированных версий с
неизвестным типом глубины или пустой точкой отсчёта. Для каждого интервала
указаны версия, ствол, границы, статус выбора и, при наличии связи с импортом,
имя файла, его SHA256, лист и строка Excel.

```sql
SELECT wellbore_name, interpretation_id, interval_number, unit_name,
       top_depth_m, bottom_depth_m, needs_depth_type, needs_depth_datum,
       source_name, source_sheet, source_row, is_selected
FROM geochem.v_lithostrat_depth_review
ORDER BY wellbore_name, interpretation_id, interval_number;
```

Первичная выгрузка [lithostrat-depth-review.json](lithostrat-depth-review.json)
содержит 2 514 интервалов по 181 стволу. Для всех интервалов известна строка
Excel, но требуются подтверждения типа глубины и точки отсчёта. Выгрузка фиксирует
состояние на момент проверки. Для актуального списка используйте запрос выше.

После проверки документа создайте дочерний черновик по инструкции
[LITHOSTRAT_VERSIONS.md](LITHOSTRAT_VERSIONS.md). В черновике заполните
`depth_type` и `depth_datum` для подтверждённых интервалов, указав документ,
редакцию и страницу в `note`. Номер интервала сохраняется при клонировании.
После проверки черновика зафиксируйте версию и выберите её для ствола по правилам
ниже. Для привязки проб значение `depth_datum` должно точно совпадать с их
подтверждённым datum. Исходные версии сохраняются в списке как отдельные версии.

Миграция `010_sample_lithostrat_matching.sql` требует миграций 007 и 009.
Прежние таблицы, представления и поведение приложения сохраняются.
Новая таблица `wellbore_interpretation_selection` хранит явный выбор одной рабочей
интерпретации для ствола, автора выбора, время и обязательное обоснование.
Выбрать можно только зафиксированную версию того же ствола. Автоматического выбора
самой новой версии или исходного снимка нет. Это текущая настройка, а не журнал
переключений; сами версии при переключении не меняются.

## Условия сопоставления

1. Есть общий `wellbore_id` и явно выбранная зафиксированная версия.
2. Связь исходной геохимической скважины со стволом проверена экспертом:
   `well_wellbore_link.reviewed=true`.
3. Глубины пробы конечны, неотрицательны и подошва не выше кровли.
4. Тип глубины интервала совпадает с типом пробы (сейчас MD).
5. Datum пробы непустой и точно совпадает с datum интервала.

Регистр, пробелы и синонимы datum автоматически не нормализуются. Совпадение
строк — необходимое условие, а физическая эквивалентность должна быть подтверждена
источниками до заполнения/проверки этих полей. Преобразований MD/TVD нет.
Изначальные версии Excel с неизвестными MD/TVD и datum не дают автоматических
попаданий. Не следует заполнять их предположительными значениями ради соединения.

Для точечной пробы интервал полуоткрытый `[top,bottom)`: точка на общей границе
попадает в следующий интервал. Для протяжённой пробы требуется положительная
длина пересечения; одно касание границы не считается попаданием.
`contained` означает полное вхождение пробы, `partial` — частичное пересечение.
`overlap_fraction` — доля длины пробы в интервале; у точечной пробы NULL.
Это геометрическая доля, а не статистический вес результата.

Несколько попаданий на одном ранге сохраняются: `matches_at_level>1`. Причина
может быть в пересечении границы протяжённой пробой или в альтернативных/
конфликтующих интервалах. Флаг не означает автоматически ошибку источника.
Ожидаемые попадания в разные ранги (GROUP и FORMATION) не считаются неоднозначностью.
Доли пересекающихся альтернатив могут суммарно превышать 1.

## Представления

| Представление | Содержание |
| --- | --- |
| `v_sample_lithostrat_context` | Все пробы, выбранная версия, автор/время/обоснование выбора и проверка геометрии глубин |
| `v_sample_lithostrat_match` | Каждое совместимое попадание пробы в интервал, ранг, доля и число попаданий на ранге |
| `v_sample_lithostrat_status` | Одна строка на пробу с причиной отсутствия попаданий или статусом matched/ambiguous |
| `v_geochemical_lithostratigraphy` | Все геохимические результаты с каждым подходящим интервалом выбранной версии |

Статусы отсутствия привязки: `no_wellbore`, `no_selected_version`,
`unreviewed_wellbore_link`, `invalid_or_missing_sample_depth`,
`unknown_sample_datum`, `no_compatible_depth_reference`, `outside_intervals`.
Показывается первая причина по порядку необходимых проверок.
Все новые таблицы/представления доступны `readonly` для SELECT.

Новое геохимическое представление содержит только сопоставленные результаты.
Один результат может повторяться на разных рангах или в альтернативных интервалах.
Для статистики сначала выбирайте ранг и правило обработки множественных попаданий;
не усредняйте всю таблицу без такого правила. Методы и повторы сохранены отдельно.

## Примеры

```sql
-- Причины отсутствия привязки по всем пробам:
SELECT match_status,count(*) FROM geochem.v_sample_lithostrat_status
GROUP BY match_status ORDER BY count(*) DESC;

-- Полные однозначные попадания TOC на ранге FORMATION:
SELECT sample_id,wellbore_name,top_md,base_md,depth_datum,
       interpretation_id,unit_name,group_name,repeat_number,
       analysis_run_id,source_field_id,value_numeric,unit_label
FROM geochem.v_geochemical_lithostratigraphy
WHERE unit_level='FORMATION' AND matches_at_level=1 AND match_kind='contained'
  AND source_label='TOC [%wt]'
ORDER BY wellbore_id,top_md,analysis_run_id;

-- Все потенциальные подразделения конкретной пробы:
SELECT * FROM geochem.v_sample_lithostrat_match
WHERE sample_id=1 ORDER BY unit_level,interval_top_md;
```

выборки, а старые зафиксированные версии остаются доступны по ID. Проверенные
сопоставления и выбор версии импортёры не сбрасывают.

## Применение

```powershell
.venv/Scripts/python.exe -m autopyro.database.tools.validate_sample_lithostrat_matching
.venv/Scripts/python.exe -m autopyro.database.tools.validate_sample_lithostrat_matching --apply
```

Первый запуск откатывает DDL. Второй фиксирует после проверок. В обоих случаях
синтетические интервалы, тестовый выбор и временные правки проб/связей откатываются.
Проверяются отпечатки существующих таблиц, повторяемость, границы, частичные
пересечения, ранги, множественные попадания, системы глубин, запрет выбора черновика
или версии чужого ствола, число строк соединения с измерениями и SELECT readonly.
Проверку запускать без параллельного изменения данных.
