# Версии литостратиграфических интерпретаций

Миграция `009_lithostrat_versions.sql` требует миграций 003 и 006.
Существующие таблицы Excel и прежние представления не меняются. Приложение
продолжает читать исходную разбивку; выбор новой интерпретации выполняется
явно по `interpretation_id` в новых представлениях.

## Устройство

- `lithostrat_interpretation`: ствол, уникальная в пределах ствола метка версии,
  родительская версия, автор, описание, даты создания и фиксации, статус.
- `lithostrat_interpretation_interval`: интервалы конкретной версии с глубинами,
  системой глубин, подразделением, пояснением и ссылкой на исходный интервал.
- `v_lithostrat_interpretation`: интервалы с описанием версии и общим стволом.
- `v_lithostrat_interpretation_overlap`: пересечения интервалов одного ранга
  внутри одной версии при одинаковых depth_type и datum (включая оба неизвестных).

Каждый импорт и исходный ствол получают одну самостоятельную исходную версию.
В текущем наборе это 181 версия и 2 514 интервалов. Исходные версии сразу
фиксируются; неизвестные MD/TVD и datum остаются NULL. Конфликтующие интервалы
сохраняются. Новое представление пересечений показывает потенциальный конфликт,
но не доказывает ошибку, особенно при неизвестной системе глубин.

Название и ранг подразделения сохранены в интервале как снимок. Последующее
переименование записи `lithostrat_unit` не меняет старую интерпретацию.
Идентификатор подразделения и исходного интервала сохраняют прослеживаемость;
исходный `raw_cells` остаётся в прежней таблице. Название общего ствола в
представлении берётся из актуального справочника, а не является историческим снимком.

Статусы:

- `draft`: редактируемый черновик.
- `published`: зафиксированная версия. Это фиксация состояния, а не одобрение
  геологической интерпретации и не назначение её основной для приложения.

После фиксации запрещены UPDATE/DELETE заголовка и INSERT/UPDATE/DELETE интервалов.
Для исправления создают дочерний черновик. Родитель должен быть зафиксирован
и относиться к тому же стволу. Идентичность, происхождение и родителя версии
нельзя менять после создания. Пустую версию зафиксировать нельзя.
Вложенные ранги и альтернативные пересекающиеся интервалы допускаются.
Триггеры блокируют строку заголовка при редактировании интервалов, чтобы
изменение интервала и фиксация версии не выполнялись одновременно.

## Работа с версиями (admin)

```sql
-- Найти исходные версии:
SELECT interpretation_id,wellbore_id,version_tag,status,source_import_batch_id
FROM geochem.lithostrat_interpretation
ORDER BY wellbore_id,interpretation_id;

-- Создать рабочую копию выбранной зафиксированной версии.
-- Подставить реальный interpretation_id вместо 1.
SELECT geochem.clone_lithostrat_interpretation(
    1,'revision-1','ФИО автора','Уточнение границ по каротажу, протокол ...');
-- Функция возвращает ID нового черновика. Копируются все интервалы,
-- их исходные ссылки, системы глубин и пояснения.
```

Пример для psql с получением идентификатора без ручного копирования:

```sql
BEGIN;
SELECT geochem.clone_lithostrat_interpretation(
    1,'revision-2','ФИО автора','Уточнение по документу ...') AS new_id \gset

-- Изменять только подтверждённые границы/системы глубин.
-- Пример изменения пояснения к одному интервалу:
UPDATE geochem.lithostrat_interpretation_interval
SET note='Проверено по каротажу, документ ...'
WHERE interpretation_id=:new_id AND interval_number=1;

-- Проверить состав и потенциальные пересечения:
SELECT * FROM geochem.v_lithostrat_interpretation
WHERE interpretation_id=:new_id ORDER BY top_depth_m,unit_level;
SELECT * FROM geochem.v_lithostrat_interpretation_overlap
WHERE interpretation_id=:new_id;

-- Зафиксировать только после проверки:
UPDATE geochem.lithostrat_interpretation
SET status='published',published_at=current_timestamp
WHERE interpretation_id=:new_id;
COMMIT;
```

После фиксации изменённой разбивки исходные интервалы Excel и версии-родители
сохраняются. Не нужно обновлять исходную таблицу для работы с новой версией.
Присвоение MD/TVD и datum выполняют по подтверждающему источнику с пояснением.
Автоматического соединения с геохимическими пробами по числам глубины нет.

## Импорт и установка

Импортёр Excel после обновления общего справочника вызывает
`snapshot_lithostrat_sources()`, если миграция установлена. Новые импортные пакеты
получают новые исходные версии. Повторный вызов не обновляет уже созданные снимки
и не сбрасывает пользовательские версии. Ручные дополнения к уже существующему
пакету автоматически в снимок не попадают: для новой редакции источника нужен
новый импортный пакет. Не изменяйте старые исходные пакеты на месте.

```powershell
.venv/Scripts/python.exe -m autopyro.database.tools.validate_lithostrat_versions
.venv/Scripts/python.exe -m autopyro.database.tools.validate_lithostrat_versions --apply
```

Первый запуск откатывает DDL и данные. Второй фиксирует миграцию с исходными
снимками после проверок. Временные версии для проверки откатываются в обоих случаях.
Проверяются сохранность существующих таблиц, повторный запуск, полнота исходных
интервалов и глубин, клонирование, независимость черновика, фиксация, блокировка
изменений и права readonly. Тесты могут оставлять пропуски в identity-последовательностях.
Применять при отсутствии параллельных изменений данных.

Роль `readonly` читает обе таблицы и оба представления; создать или изменить версию
через функции она не может. Ограничения неизменяемости предназначены для обычных
SQL-операций: администратор с полными правами по-прежнему может менять DDL и триггеры.
