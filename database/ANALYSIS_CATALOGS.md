# Справочники анализа

Экспорт кандидатов, экспертные решения и история изменений: [CATALOG_REVIEW.md](CATALOG_REVIEW.md).

Миграция `migrations/005_analysis_catalogs.sql` добавляет четыре таблицы:

- `indicator`: показатель, устойчивый уникальный `code`, название и описание.
- `measurement_unit`: единица, код, обозначение и описание.
- `analysis_method`: метод, код, название и описание.
- `source_field_semantics`: сопоставление исходного поля с показателем, единицей и методом. Несколько исходных полей могут ссылаться на один показатель и разные методы/единицы.

Исходные таблицы, результаты, `raw_cells` и `v_analysis_result` не меняются.
Приложение продолжает использовать прежние запросы. Новое представление
`v_analysis_result_semantic` дополняет результаты идентификаторами и названиями
справочников и признаками проверки. Все новые таблицы и представление доступны `readonly` для SELECT.

## Первичное заполнение

Каждому аналитическому полю соответствует отдельный предварительный показатель
с кодом `source-field:<id>`. Это включает текстовые поля метаданных: их научный
смысл ещё не классифицирован. Название группы становится предварительным методом
`source-group:<group>`, а точная непустая строка единицы — записью `source:<unit>`.
Пустая единица означает NULL, а не автоматически безразмерную величину.
Все записи и сопоставления имеют `reviewed=false`: группа источника не доказывает
методику анализа, а похожие названия не доказывают эквивалентность показателей.

После экспертной проверки можно создать канонический показатель и переназначить
ему несколько исходных полей. Методы и единицы уточняются аналогично.
Названия и значения в источнике при этом сохраняются. Новый справочник единиц
не выполняет преобразований: объединять числовые результаты можно только после
проверки единиц и методов. Метод задаётся на уровне исходного поля; различия
лабораторий и протоколов между отдельными запусками пока не моделируются.

```sql
BEGIN;
INSERT INTO geochem.indicator(code,name,reviewed)
VALUES ('organic_carbon_total','Общий органический углерод',true);
-- Подставить идентификаторы полей после проверки методики и единиц:
-- UPDATE geochem.source_field_semantics
-- SET indicator_id=(SELECT indicator_id FROM geochem.indicator
--                   WHERE code='organic_carbon_total'), reviewed=true
-- WHERE source_field_id IN (...);
COMMIT;

SELECT indicator_code, indicator_name, method_name, unit_symbol,
       value_float, value_int, value_text, mapping_reviewed
FROM geochem.v_analysis_result_semantic
LIMIT 100;
```

## Применение и проверка

Из корня проекта (учётная запись admin, локальный пароль читается из `.env`):

```powershell
.venv/Scripts/python.exe -m autopyro.database.tools.validate_analysis_catalogs
.venv/Scripts/python.exe -m autopyro.database.tools.validate_analysis_catalogs --apply
```

Первый запуск проверяет миграцию с откатом; второй фиксирует её после проверок.
Проверяются количество и агрегированный отпечаток строк прежних таблиц,
полнота сопоставлений, число результатов представления, повторное применение,
сохранение решений эксперта и чтение ролью readonly без права INSERT.
Старые таблицы не должны параллельно изменяться во время применения.

На пустой базе Compose выполняет миграцию после базовой схемы автоматически.
Существующий том требует явного применения. После расширения каталога вручную:

```sql
SELECT geochem.refresh_analysis_catalogs();
```

Импортёр Parquet вызывает эту функцию перед фиксацией импорта, если миграция
установлена. Повторное заполнение добавляет недостающие записи и сохраняет
существующие сопоставления. Произвольные UPDATE исходного каталога требуют
ручной проверки сопоставлений; автоматического переосмысления данных нет.
