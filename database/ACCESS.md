# Пользователи PostgreSQL

Настроены 25 октября 2026 года.

| Пользователь | Доступ |
|---|---|
| `admin` | Исходная роль `geochem`, переименованная с сохранением OID, владения и полномочий суперпользователя |
| `readonly` | Подключение к `geochemistry`, USAGE схемы `geochem`, SELECT всех её таблиц, представлений и последовательностей |

Подключение: `127.0.0.1:15432`, база `geochemistry`.
Пароль `admin` сохранён прежним; значение — `POSTGRES_PASSWORD` в корневом `.env`.
Случайный пароль чтения — `READONLY_PASSWORD` в том же файле.
`.env` исключён из Git. В SQL-миграции и отчётах пароли отсутствуют.

`readonly` не имеет членств в других ролях, SUPERUSER, CREATEDB, CREATEROLE,
REPLICATION или BYPASSRLS. Ему не выданы права записи или изменения схемы.
CREATE в `public` и TEMPORARY для PUBLIC в этой базе отозваны, чтобы не получить
эти права через общие привилегии. SELECT последовательностей не даёт права `nextval`/`setval`.
Новые таблицы, представления и последовательности, создаваемые ролью `admin` в
`geochem`, автоматически доступны для чтения через default privileges.
Для объектов, создаваемых другими владельцами или в других схемах, нужны отдельные выдачи прав.

По умолчанию транзакции `readonly` имеют `default_transaction_read_only=on`.
Запрет на запись обеспечивается также объектными правами: проверен и после
отключения этого пользовательского параметра в тестовом сеансе.

Compose и импортёры теперь используют `admin`. SELECT-адаптер приложения
`autopyro.geochem_database.local_parameters()` использует `readonly` и пароль из
`.env` либо `READONLY_PASSWORD`; явные `PGUSER`/`PGPASSWORD` имеют приоритет.
Схема по-прежнему называется `geochem` — изменилось только имя пользователя.

## Повторная настройка и проверка

```powershell
.\.venv\Scripts\python.exe -m autopyro.database.tools.configure_users
.\.venv\Scripts\python.exe -m autopyro.database.tools.validate_users
```

При настройке старой базы с пользователем `geochem` задайте `PGUSER=geochem` перед
первым запуском и удалите эту переменную после переименования. Для уже настроенного
окружения используется `POSTGRES_USER=admin` из `.env`.
После создания нового пустого тома Compose сначала инициализирует `admin` и основную
схему; `configure_users.py` нужно запустить отдельно, чтобы создать читателя.

Результат проверки: **35 PASS**. Успешно проверены оба парольных TCP-подключения,
владение `admin`, чтение 14 таблиц и 3 представлений, отсутствие права менять
11 последовательностей, отклонение INSERT/UPDATE/DELETE/TRUNCATE/ALTER/DROP/CREATE,
отказ `SET ROLE admin`, default privileges на новых объектах. Тестовые изменения
откатились. Количества проб и аналитических результатов не изменились.

## Дамп от 24 октября

Ранее созданный дамп сохраняет старые имена владельцев `geochem`. При восстановлении
именно этого архива в текущую конфигурацию создайте пустую базу с владельцем `admin`,
используйте `pg_restore --no-owner --no-privileges -U admin ...`, затем примените
`configure_users.py`, чтобы назначить читателю права. Сам старый архив не изменялся.
